# 플러그인 관리

## 플러그인의 출처

플러그인은 기본 패키지, 서명된 공식 카탈로그, 신뢰하도록 설정한 사용자 지정 저장소 또는 로컬 업로드에서 올 수 있습니다. 출처, 버전, SHA-256과 서명을 확인하세요.

## 표시 정보

관리 페이지의 각 카드에는 플러그인 ID, 버전, 출처, 상태, 의존성, 활성화 여부와 진단 정보가 표시됩니다.

## 가능한 작업

활성화, 비활성화, 시작, 중지, 재로드, 다시 시작, 제거와 삭제를 정책에 따라 수행할 수 있습니다. 카드에 표시된 적용 시점(즉시, 백엔드 재시작 또는 소프트웨어 재시작)을 따르세요.

## 로컬 플러그인 설치

`.jar` 또는 지원되는 `.zip`과 별도 `.sig` 파일을 함께 선택합니다. 서명이 없거나 아티팩트와 일치하지 않거나 신뢰할 수 없는 키로 서명된 파일은 fail-closed로 거부됩니다.

## 웹 플러그인 마켓

공식 또는 신뢰할 수 있는 저장소를 탐색하고 검색·필터링한 뒤 설치합니다. 크기, 해시, 서명과 출처 검증 후 설치되며 대부분 재시작 후 적용됩니다.

## 복구 경로

플러그인이 실패하면 진단 정보와 로그를 먼저 저장하세요. 필수 플러그인이 없거나 시작하지 못하면 앱은 복구/수리 모드로 진입할 수 있습니다.

## 데스크톱 GUI

애플리케이션이 소유한 선언형 UI 문서의 플러그인 페이지는 백엔드 상태를 읽기 전용으로 표시하며 Swing과 Compose가 같은 내용을 렌더링합니다. 설치, 제거, 활성화와 비활성화는 Web 플러그인 관리 페이지에서 수행합니다. `gui-swing`은 기본 설치 및 기본 provider이고 `gui-compose`는 필요할 때 설치합니다. 둘 다 `process-restart`이므로 설치, 업데이트, 활성화 변경, 제거 또는 provider 선택 변경 후 전체 애플리케이션을 다시 시작해야 합니다.
