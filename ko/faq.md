# 자주 묻는 질문

증상에 맞는 항목을 확인하세요. 계정·데이터베이스·경로 작업 전 실제 작업 디렉터리를 확인하고 백업을 보존합니다. 화면의 대기 시간만보다 로그와 작업 결과를 우선 확인하세요. 명령의 `APP.jar`는 실제 주 프로그램 이름으로 바꾸고 배포 디렉터리에서 실행합니다.

## 설치와 실행

**Java를 찾지 못함:** [Adoptium](https://adoptium.net/) 등에서 Java 17+를 설치하고 터미널을 다시 열거나 `JAVA_HOME`·`PATH`를 설정합니다. `java -version`으로 확인하세요.

**문자가 깨짐:** UTF-8 인수를 넣습니다.

```text
java -Dfile.encoding=UTF-8 -jar APP.jar
```

**6999 포트 사용 중:** 이미 실행한 PixivDownloader인지 먼저 확인하세요. 같은 데이터 디렉터리에서 중복 실행하지 않습니다. 다른 프로그램이면 용도를 확인한 뒤 중지하거나 `config/config.yaml`의 `server.port`를 바꾸고 재시작합니다.

**Windows 설치 실패:** 실행 중인 `PixivDownload.exe`를 닫고 과거 MSI 잔여 설치를 확인합니다. 설치판은 이전 설치 마이그레이션을 처리합니다. 관리자 권한으로 설치 프로그램을 실행하세요.

**제거:** Windows 설치판의 제거 기능이나 설정 → 앱을 사용합니다. Java 배포판은 [저장·백업](/ko/storage)에 따라 작품·설정·상태·데이터베이스를 보존한 뒤 프로그램 파일을 제거합니다. 작업 디렉터리 전체를 버려도 되는 프로그램 파일로 간주하지 마세요.

**관리자 재초기화:** 비밀번호만 잊었다면 아래 재설정을 사용합니다. 초기화 상태 자체를 바꿔야 한다면 중지·백업 후 `state/setup_config.json`을 옮기고 `--setup` 또는 GUI 안내를 실행합니다. 모든 설정을 지우거나 데이터베이스를 이전·재구성하는 명령이 아닙니다.

**서버·Docker가 종료 코드 78로 끝남:** 무화면 실행 전 초기화를 마쳐야 합니다.

```text
java -Dfile.encoding=UTF-8 -jar APP.jar --setup
java -Dfile.encoding=UTF-8 -jar APP.jar --no-gui
```

**비밀번호 분실:** 같은 인스턴스를 중지하고 다음을 실행합니다.

```text
java -Dfile.encoding=UTF-8 -jar APP.jar --reset-password
```

원래 비밀번호는 필요 없고 새 비밀번호를 확인합니다. 최소 8자, 권장 12자 이상입니다. 성공하면 기존 세션이 로그아웃됩니다. 기존 비밀번호를 알고 바꾸려면 `--change-password`를 사용합니다. [최초 설정](/ko/first-setup)을 참고하세요.

**인수를 인식하지 못함:** 오타 `--no-guii`, 등호 없는 `--username admin`, 위치 인수는 거부합니다. `--help`로 확인하세요. `--key=value`는 Spring 속성 재정의로 그대로 전달됩니다.

## 프록시와 네트워크

**설정했는데 다운로드 실패:** GUI 저장·CLI setup의 프록시는 즉시 다시 로드합니다. 직접 파일을 편집했다면 재시작하거나 GUI 저장으로 적용하세요. 실제 Pixiv 작품을 브라우저에서 확인하고 백엔드 로그의 실패 호스트·오류를 읽습니다. CDN 루트 주소 응답만으로 다운로드 성공을 판단하지 않습니다. 방화벽의 프록시 포트도 확인하세요. 전역·작업·플러그인·브라우저 경로 차이는 [네트워크 안내](/ko/network-access)를 참고하세요.

**프록시 뒤 사용자가 모두 제한됨:** 신뢰 프록시가 없으면 TCP 출처 주소를 사용하므로 하나의 프록시를 공유할 수 있습니다. 실제 출구 주소나 컨테이너 네트워크만 지정합니다.

```yaml
server.trusted-proxy-cidrs: 172.18.0.0/16
```

매 요청에 완전한 `Forwarded` 또는 `X-Forwarded-For`·`X-Forwarded-Proto`·`X-Forwarded-Host`를 보내야 합니다. 공개·클라이언트 네트워크를 신뢰하지 마세요. 누락·비신뢰 헤더는 400입니다. [설정](/ko/configuration?id=https와-리버스-프록시)을 참고하세요.

**LAN 접속 실패:** 6999 방화벽, 설정의 바인딩 제한을 확인하고 `http://서버IP:6999/`로 접속합니다.

## Cookie

**검색이 비어 있음:** Search에는 Cookie가 필요합니다. Netscape/Header 선택과 실제 값 형식, 저장 후 로그인 인식, 만료, 프록시를 확인하세요.

**형식 오류:** 완전한 `PHPSESSID`가 필요합니다. 일반 페이지 스크립트가 읽은 Cookie에는 없을 수 있습니다. [첫 다운로드](/ko/first-download)로 다시 가져와 저장하고 자격 증명을 로그나 Issue에 붙이지 마세요.

**저장 Cookie 삭제:** 다운로드 페이지에서 명시적으로 지웁니다. 예약은 자기 자격 증명 연결을 가지므로 각 작업에서도 해제해야 합니다. 로그아웃이 모든 저장 자격 증명을 삭제하지는 않습니다.

## 다운로드와 듣기

**Ugoira 재생 실패:** 선택 형식의 인코더를 갖춘 FFmpeg가 필요합니다. PATH와 `ffmpeg -version`을 확인하세요. Windows GUI 상태에서 다운로드할 수 있습니다.

**EPUB 표지 누락:** 프록시를 확인하고 표지 URL 호스트가 SSRF 허용 경계인 `.pximg.net`으로 끝나는지 확인한 뒤 다시 다운로드합니다.

**온라인 TTS 실패:** Edge 음성은 백엔드 프록시로 Microsoft에 연결합니다. `proxy.*`를 확인하세요. 오래된 버전으로 handshake 403이 나면 새 Edge 버전·시계 차이를 자동 보정하고 재시도합니다. 계속 실패하면 시스템 시각을 확인합니다. 브라우저 엔진으로 바꿀 수도 있지만 네트워크 여부는 선택 음성 서비스에 따라 다릅니다. 초대 게스트는 solo·multi 모두 `guest-invite.tts-request-limit-minute`을 적용받으며 429면 기다리거나 관리자에게 조정을 요청합니다. 관리자 자신은 이 제한을 받지 않습니다.

**일부 작품만 실패:** Cookie 만료, Pixiv 빈도 제한, 프록시 불안정, 삭제·비공개를 구분하세요. 유효 Cookie를 저장하고 필요하면 동시 수·빈도를 낮추며 접근할 수 없는 작품은 건너뜁니다.

**파일명 템플릿:** `{artwork_id}`처럼 지원 변수와 중괄호를 사용합니다. 잘못된 파일명 문자는 정리됩니다. 변경한 템플릿은 새 다운로드에만 적용하고 기존 파일명은 바꾸지 않습니다.

**Ugoira가 할당량을 많이 소비:** multi에서 `multi-mode.quota.limit-image`를 설정할 수 있습니다. 예를 들어 10이면 총 이미지 수가 10을 넘는 작품은 비례해 여러 할당량을 사용합니다.

## GUI

**계속 시작 중:** 10초가 넘으면 기다린 초를 표시하며 데이터베이스 갱신 중일 수 있습니다. `log/latest.log`에서 이전·포트 대기·플러그인 로드 상태와 오류를 확인하고 Java 17+인지 점검하세요. 시작이 느리다고 데이터베이스를 삭제하지 마세요.

**온라인 업데이트 실패:** 네트워크와 공유 프록시를 확인합니다. 필요하면 [Releases](https://github.com/Sywyar/PixivDownloader/releases)에서 직접 받아 설치할 수 있습니다.

**오류 창의 세부 정보:** 공통 오류 안내를 표시하며 상세 오류는 로그에 기록합니다. 창의 로그 열기로 확인하세요.

## 데이터베이스와 백업

**위치:** 기본 SQLite는 `data/pixiv_download.db`이며 WAL·SHM이 있을 수 있습니다. PostgreSQL이면 설정한 서버에 있습니다. 작업 전에 실제 공급자·경로를 확인하세요.

**손상 의심:** 중지하고 원본·동반 파일을 보존한 뒤 백업 복사본을 진단합니다. SQLite CLI의 `PRAGMA integrity_check;`는 검사만 하며 복구 명령이 아닙니다. 검증한 백업 복원을 우선하세요. 원본을 지운 뒤 작품 디렉터리로 갤러리를 복원할 수 있다고 가정하지 마세요. PostgreSQL에는 해당 서버의 복구 절차를 사용하며 SQLite 명령을 적용하지 않습니다.

**데이터베이스 분실·이전 후 재다운로드:** 건너뛴다고 보장할 수 없습니다. 작품 식별, 페이지 수, 경로, 태그, 컬렉션은 데이터베이스가 기준입니다. 이미지 파일만으로 완전한 작품을 추정하지 않습니다. 원본을 보존하고 맞는 데이터베이스 백업을 복원하세요. 경로 변경은 접두사 마이그레이션, 엔진 변경은 검사·이전 절차를 사용합니다. 보충 도구는 기존 기록을 채우며 임의 디렉터리 전체 복구 도구가 아닙니다.

**백업:** 중지한 뒤 `config/`, `state/`, `data/`, 플러그인, 실제 작품·컬렉션 경로를 보존합니다. 아이콘은 `data/collection_icons/`입니다. PostgreSQL 서버와 외부 가져오기 원본도 별도 백업해야 합니다. [저장 원칙](/ko/storage)을 참고하세요.

## 사용자 스크립트

패널이 없다면 Tampermonkey와 해당 스크립트 활성화, `@match`, 페이지 권한을 확인하고 새로 고칩니다. All-in-One과 독립본은 별도 스크립트·저장 공간이므로 같은 기능을 동시에 켜면 패널이 중복됩니다. 하나만 선택하세요.

백엔드 불가·미로그인이면 서비스 실행과 solo 로그인을 확인합니다. 다른 호스트에서는 실제 백엔드 주소와 `@connect`를 모두 확인해야 합니다. [사용자 스크립트](/ko/userscripts)를 참고하세요.

## 보안과 업데이트

Pixiv 계정 제한을 피한다고 보장할 수 없습니다. 본인의 Cookie를 사용하고 요청 빈도·동시 수를 조절하며 서비스 규칙을 따르세요.

multi의 로그인하지 않고 초대도 없는 사용자는 **방문자**이며 다운로드 상태는 신원별로 구분됩니다. 관리자는 관리 화면을 갖습니다. **초대 게스트**는 solo·multi에서 허용된 페이지·작품만 접근합니다. 컬렉션·이력·통계도 각 진입점의 권한을 따릅니다.

HTTPS는 실제 인증서·키 경로로 설정한 뒤 재시작하고 확인합니다.

```yaml
server.ssl.enabled: true
server.ssl.certificate: /path/to/cert.pem
server.ssl.certificate-private-key: /path/to/key.pem
```

PEM과 JKS가 함께 있으면 PEM이 우선합니다. 리버스 프록시는 [설정](/ko/configuration)을 참고하세요.

새 컴퓨터로 이동할 때는 중지·백업·복원을 하고 경로가 다르면 데이터베이스 접두사를 갱신합니다. 로그인, 갤러리, 소설 본문, 컬렉션, 새 다운로드를 확인한 뒤 이전 복사본을 처리하세요.

GUI는 시작 시 자동 또는 상태 페이지에서 업데이트를 확인합니다. Java는 새 배포판을 완전히 풀고 설명에 따라 앱·플러그인을 함께 교체하며 설정·상태·데이터는 유지합니다. JAR 하나만 바꾸지 마세요. Windows는 새 설치판으로 복구 또는 덮어설치합니다. 시작 시 같은 데이터베이스의 스키마 업그레이드가 가능하지만 SQLite↔PostgreSQL은 별도 검사·이전이 필요합니다. 전후 백업과 기존 작품 확인을 수행하세요.

해결되지 않으면 [Issues](https://github.com/Sywyar/PixivDownloader/issues)에 OS, 앱 버전, 재현 단계, 실제 결과, 필요하면 스크린샷을 첨부합니다. `log/latest.log`에서 Cookie·토큰·비밀번호·개인 주소를 제거하세요.
