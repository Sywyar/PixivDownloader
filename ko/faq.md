# 자주 묻는 질문(FAQ)

증상별로 진단 및 해결 절차를 찾으세요. 데이터베이스, 계정이나 폴더를 조작하기 전에 실제 작업 폴더를 확인하고 백업을 보존하세요. 아래 명령의 `APP.jar`는 배포 패키지의 실제 주 프로그램 JAR 이름으로 바꾸고 압축을 모두 푼 폴더에서 실행하세요.

## 설치 및 시작

### 'Java는 내부 또는 외부 명령이 아닙니다'라는 메시지

Java 17+가 설치되어 있지 않거나 환경 변수에 등록되지 않았습니다. [Adoptium](https://adoptium.net/)에서 Java 17+를 설치하고 터미널을 다시 열거나 `JAVA_HOME`과 `PATH`를 확인하세요.

### 시작 후 콘솔의 중국어가 깨짐

수동 실행 시 `-Dfile.encoding=UTF-8`을 추가하세요. 배포 패키지의 `run.bat` / `run.sh`에는 이미 포함되어 있습니다.

```bash
java -Dfile.encoding=UTF-8 -jar APP.jar
```

### 포트 6999가 이미 사용 중이라는 메시지

같은 데이터 폴더를 사용하는 PixivDownloader 인스턴스가 이미 실행 중인지 먼저 확인하세요. 같은 데이터 폴더로 여러 인스턴스를 실행하지 마세요. 다른 프로그램이 사용 중이라면 그 프로그램을 중지하거나 `config/config.yaml`의 `server.port`를 변경한 후 재시작하세요.

### Windows 설치 패키지 설치 실패

실행 중인 `PixivDownload.exe`를 먼저 닫고 관리자 권한으로 설치 프로그램을 다시 실행하세요.

### 제거하거나 관리자 계정을 다시 초기화하는 방법

- **제거**: Windows 설치 버전은 설치 프로그램이나 시스템의 '설정 → 앱'에서 제거합니다. Java 압축 버전은 먼저 [저장소 및 백업](/ko/storage)에 따라 작품 폴더, `config/`, `state/`와 `data/`를 백업한 후 프로그램 파일을 삭제하세요. 작품과 데이터베이스가 들어 있는 작업 폴더 전체를 바로 삭제하지 마세요.
- **비밀번호 분실 또는 재초기화**: 비밀번호만 잊었다면 서비스를 중지하고 `--reset-password`를 실행하세요. 초기화 상태를 실제로 다시 만들어야 한다면 서비스 중지 및 백업 후 `state/setup_config.json`을 다른 곳으로 옮기고 `--setup`이나 데스크톱 안내를 실행하세요. 업무 설정을 비우거나 데이터베이스를 다시 만들지는 않습니다. [초기 설정](/ko/first-setup)을 참고하세요.

### 서버 / Docker가 시작 직후 종료 코드 78로 종료됨

헤드리스 모드(`--no-gui`)에서 초기 설정이 완료되지 않으면 종료 코드 `78`로 중단됩니다. 대화형 초기화를 먼저 실행한 후 서비스를 시작하세요.

```text
java -Dfile.encoding=UTF-8 -jar APP.jar --setup
java -Dfile.encoding=UTF-8 -jar APP.jar --no-gui
```

### 관리자 비밀번호 분실

실행 중인 인스턴스를 중지한 후 로컬에서 재설정 명령을 실행하세요. 기존 비밀번호는 필요하지 않습니다. 비밀번호는 최소 8자, 권장 12자 이상이며 재설정하면 기존 세션이 모두 무효화됩니다. 기존 비밀번호를 알고 있다면 `--change-password`를 사용할 수 있습니다.

```text
java -Dfile.encoding=UTF-8 -jar APP.jar --reset-password
```

### '인식할 수 없는 시작 인수'라는 메시지

시작 인수는 엄격하게 검증합니다. `--no-guii` 같은 오타, `--username admin`처럼 `=`가 빠진 인수, 독립된 위치 인수는 모두 거부됩니다. `--help`로 지원 옵션을 확인하세요.

## 프록시 및 네트워크

### 프록시를 설정해도 다운로드할 수 없음

1. 프록시를 저장했는지 확인합니다. 데스크톱 GUI 저장이나 CLI `--setup`은 실시간 재로딩을 지원합니다. `config/config.yaml`을 수동 편집했다면 재시작하거나 GUI에서 저장을 눌러 재로딩해야 합니다.
2. 브라우저에서 실제 Pixiv 작품 페이지에 접근할 수 있는지 확인하고 `log/latest.log`에서 실패한 호스트와 오류 코드를 확인합니다.
3. 방화벽이 프록시 포트를 허용하는지 확인합니다. 컨테이너에서는 `127.0.0.1` 대신 `host.docker.internal`을 사용했는지 확인합니다.
4. 전역 프록시, 예약 작업의 개별 프록시, 플러그인 자체 프록시와 브라우저 직접 요청을 구분합니다. [네트워크 접근 및 외부 서비스](/ko/network-access)를 참고하세요.

### 리버스 프록시 뒤의 다중 사용자 모드에서 모든 사용자가 같은 요청 제한을 공유함

신뢰할 수 있는 프록시를 설정하지 않으면 백엔드는 TCP 출발지 IP로 요청을 제한합니다. `config/config.yaml`의 `server.trusted-proxy-cidrs`에 실제 리버스 프록시 출구 주소나 컨테이너 네트워크 대역(예: `172.18.0.0/16`)을 입력하고 리버스 프록시가 전체 `Forwarded` 또는 `X-Forwarded-For` + `X-Forwarded-Proto` + `X-Forwarded-Host`를 전달하도록 하세요. [설정 참조의 HTTPS 및 리버스 프록시](/ko/configuration#https-및-리버스-프록시)를 참고하세요.

### LAN의 다른 기기에서 접근할 수 없음

방화벽이 `server.port`(기본 `6999`)를 허용하는지, 서비스가 `127.0.0.1`에만 바인딩되어 있지 않은지 확인하세요. Docker는 기본적으로 호스트 루프백에만 바인딩하므로 리버스 프록시나 매핑 변경으로 공개해야 합니다. LAN 기기에서는 `http://<서버IP>:6999/`로 접속하세요.

## Cookie 및 다운로드

### 검색 결과가 없거나 Cookie 형식 오류가 표시됨

- 검색 다운로드, 빠른 가져오기와 R-18 작품에는 유효한 `PHPSESSID`가 포함된 Cookie가 필요합니다.
- 붙여넣을 때 선택한 형식(**Netscape** 또는 **Header String**)은 내보낸 내용과 일치해야 합니다. 일반 프런트엔드 스크립트가 읽는 `document.cookie`에는 HttpOnly인 `PHPSESSID`가 없습니다. [첫 다운로드](/ko/first-download#_2-pixiv-cookie-저장필요한-경우)에 따라 다시 가져오세요.
- Cookie를 지우려면 다운로드 페이지에서 명시적으로 지우기를 눌러야 합니다. 예약 작업은 별도의 Cookie 연결을 유지하므로 해당 작업에서도 연결을 해제해야 합니다.

### 움짤(Ugoira)을 변환할 수 없거나 소설 EPUB에 표지가 없음

- **움짤**: `ffmpeg -version`이 작동하는지 확인하거나 데스크톱 GUI의 '상태' 페이지에서 'FFmpeg 다운로드'를 누르세요. MP4에는 H.264 인코더도 필요합니다.
- **소설 표지**: 표지는 `.pximg.net`에서 가져오므로 백엔드 프록시가 이미지 도메인에 정상 접근할 수 있어야 합니다. 프록시를 복구한 후 소설을 다시 다운로드하세요.

### 듣기의 '온라인 엔진'에서 소리가 나지 않거나 합성 실패

1. 온라인 엔진(Edge 신경망 음성)은 백엔드 프록시로 Microsoft 서비스에 연결합니다. 먼저 `proxy.*` 설정을 확인하세요.
2. 핸드셰이크가 403을 반환하면 백엔드가 Edge 버전을 자동 갱신하고 시계 오차를 보정하여 재시도합니다. 계속 실패하면 로컬 시스템 시간을 맞추세요.
3. 재생 막대에서 '브라우저 엔진'으로 전환할 수 있습니다.
4. 초대된 게스트에는 `guest-invite.tts-request-limit-minute`(기본 분당 30회) 제한이 적용되며 초과 시 429를 반환합니다. 관리자는 이 제한을 받지 않습니다.

### 일괄 다운로드 일부 실패, 파일명 템플릿 미적용 또는 빠른 할당량 소진

- **일부 실패**: 작가가 작품을 삭제하거나 비공개로 바꿨는지, Cookie가 만료되었는지 확인하세요. 외부 서비스의 요청 제한에 걸리면 동시 작업 수를 낮추고 작품 간격을 늘리세요.
- **파일명 템플릿**: 변수에는 `{artwork_id}`처럼 중괄호가 필요하며 수정 이후의 새 다운로드에만 적용됩니다. 지원 변수는 [파일명 템플릿 변수](/ko/usage-guide#파일명-템플릿-변수)를 참고하세요.
- **다중 사용자 모드의 여러 이미지 할당량**: `multi-mode.quota.limit-image`가 `0`보다 크면 이 페이지 수를 넘는 다중 이미지 작품은 비율에 따라 여러 할당량으로 환산됩니다.

## 데스크톱 GUI 및 데이터베이스

### GUI가 계속 '시작 중'이거나 업데이트 실패 또는 오류 팝업 표시

- **느린 시작**: 10초가 넘으면 대기 초 수를 표시합니다. 데이터베이스 마이그레이션이나 플러그인 로드 중일 수 있습니다. `log/latest.log`를 확인하고 데이터와 로그를 보존하세요. **시작 지연을 해결하려고 데이터베이스를 삭제하지 마세요.**
- **온라인 업데이트 실패**: 백엔드 프록시 연결을 확인하거나 [Releases](https://github.com/Sywyar/PixivDownloader/releases)에서 새 설치 패키지를 직접 다운로드하여 덮어 설치하세요.
- **오류 상세**: 팝업의 '로그 파일 열기'를 눌러 `log/latest.log`의 전체 영어 진단 로그를 확인하세요.

### 데이터베이스 위치, 손상 처리 및 백업 복원

- **위치**: 기본 SQLite는 `data/pixiv_download.db`에 있으며 `-wal` / `-shm`이 동반됩니다. PostgreSQL은 설정한 데이터베이스 서버에 있습니다.
- **데이터베이스 손상**: 프로그램을 먼저 중지하고 원본 데이터베이스와 동반 파일을 모두 백업합니다. **백업 사본**에만 `PRAGMA integrity_check;`를 실행하세요. 이 명령은 검사만 하고 복구하지 않습니다. 손상이 확인되면 검증된 백업을 우선 복원하세요. 작품 인식, 페이지 수, 경로와 연결은 모두 데이터베이스를 기준으로 하므로 **데이터베이스를 잃으면 작품 폴더만으로 갤러리를 복원하거나 재다운로드를 확실히 건너뛸 수 없습니다.**
- **백업, 컴퓨터 이전 및 업그레이드**: 전체 백업 범위와 폴더 이전은 [저장소 및 백업](/ko/storage)을 참고하세요. Java 배포 패키지를 업그레이드할 때는 압축을 모두 풀고 주 프로그램과 `plugins/`를 함께 교체하며 `config/`, `state/`와 `data/`를 보존해야 합니다. 주 JAR 하나만 교체하지 마세요.

## 사용자 스크립트 및 보안

### 사용자 스크립트가 표시되지 않거나 패널이 두 개이거나 백엔드에 연결되지 않음

- Tampermonkey와 스크립트가 활성화되어 있는지, 현재 페이지가 `@match`에 맞는지 확인하고 새로고침하세요. 예를 들어 User Batch는 `/users/`에만 적용됩니다.
- **패널 두 개**: All-in-One과 개별 다운로드 스크립트를 동시에 활성화하지 말고 하나만 유지하세요.
- **백엔드 연결 실패**: 백엔드가 시작되었고 개인용 모드로 로그인했는지 확인하세요. `localhost:6999`가 아닌 환경에서는 스크립트의 백엔드 주소를 변경하고 `@connect` 권한도 갱신해야 합니다. [사용자 스크립트](/ko/userscripts)를 참고하세요.

### 계정 보안, 신원 격리 및 HTTPS

- 이 도구는 사용자가 제공한 Cookie로 Pixiv에 요청합니다. 동시 작업 수와 간격을 적절히 설정하고 플랫폼 규칙을 준수하세요.
- **신원 구분**: `multi` 모드에서 로그인하지 않았고 초대 코드도 없는 사용자는 **익명 방문자**입니다. UUID와 `multi-mode.*`로 격리합니다. 초대 코드를 가진 사용자는 **게스트**이며 `solo` / `multi` 모두에서 허용 목록의 콘텐츠에 읽기 전용으로 접근하고 `guest-invite.*` 요청 제한을 받습니다.
- **HTTPS 활성화**: `config/config.yaml`에 `server.ssl.enabled: true`, `server.ssl.certificate`와 `server.ssl.certificate-private-key`를 설정하세요([설정 참조](/ko/configuration#https-및-리버스-프록시) 참고).
