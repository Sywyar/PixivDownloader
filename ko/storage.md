# 저장 원칙

## 최상위 디렉터리

- `config/`: 호스트와 플러그인 설정
- `state/`: 초기 설정과 재생성 가능한 실행 상태
- `data/`: 플러그인 데이터베이스와 캐시
- `plugins/`: 외부 플러그인 원본 및 검증 정보
- 다운로드 루트: 사용자 작품 파일과 메타데이터

## 작업 디렉터리 배치

### Configuration

`config/`에는 비밀 값과 런타임 설정이 포함될 수 있습니다. 백업 파일을 공개 저장소에 올리지 마세요.

### State

`state/`는 설치·복구에 필요한 상태를 보관합니다. 삭제하면 초기 설정이 다시 필요할 수 있습니다.

### Data

`data/{pluginId}`는 해당 플러그인이 소유하는 SQLite와 캐시입니다. 플러그인 간 데이터베이스를 교환하거나 호스트 DB에 직접 접근하지 마세요.

### 외부 플러그인

`plugins/*.jar`와 `.zip`은 원본 아티팩트이며, provenance와 서명 정보는 오프라인 검증에 사용됩니다. 수동으로 이름을 바꾸거나 내부 파일을 수정하지 마세요.

## 다운로드 작품 구조

작품별 디렉터리에는 이미지·소설·Ugoira 결과와 `{id}.meta.json`이 저장될 수 있습니다. 메타데이터는 페이지, 원본 주소, 게시 시각과 Pixiv 번역 정보를 보존합니다.

## 경로 인코딩

설정의 다운로드 루트와 작품·작가 이름은 OS 파일명 규칙에 맞게 정규화됩니다. 실제 경로는 상태 페이지와 로그에서 확인하세요.

## 위치 변경

### 전체 배포판 이동

프로세스를 종료하고 배포판 전체를 이동한 뒤 `config/`, `state/`, `data/`, `plugins/`와 실행 스크립트가 함께 있는지 확인합니다.

### 다운로드 루트만 이동

설정에서 새 루트를 지정하고 기존 파일을 보존하세요. 이미 다운로드한 기록과 디스크 파일이 일치하지 않으면 재검증 후 다시 구성됩니다.

## 백업과 복원

프로세스를 중지한 뒤 `config/`, `state/`, `data/`, 플러그인 provenance와 필요한 다운로드 파일을 백업합니다. 복원 후 앱 버전과 플러그인 API 계약이 호환되는지 확인하세요.
