# 예약 작업

예약 작업은 백엔드가 실행되는 동안 고정 주기 또는 Cron 시간에 따라 새 작품을 자동으로 **찾아 다운로드**합니다. 생성할 때 소스, 필터 조건과 다운로드 설정의 스냅샷을 저장하므로 이후 다운로드 페이지 설정을 바꿔도 기존 작업에는 반영되지 않습니다. 브라우저를 닫아도 실행되지만 백엔드를 중지하면 실행되지 않습니다.

스케줄러와 관리 API는 애플리케이션 호스트가 제공합니다. `download-workbench`를 비활성화하면 다운로드 페이지, Pixiv 소스와 일러스트 실행기가 철회됩니다. 이 기능에 의존하는 작업은 데이터와 진행 상황을 유지한 채 일시 중단되고 다른 플러그인이 완전히 지원하는 작업은 계속 실행됩니다. 필요한 기능이 복구되면 스케줄러가 다시 확인하여 기능 부재로 중단한 작업을 자동 복구합니다. 수동 일시 중지, 자격 증명 만료와 정책 중단은 여전히 명시적으로 처리해야 합니다.

## 사전 조건

1. 관리자 계정으로 로그인해야 합니다. 게스트는 사용할 수 없습니다.
2. 백엔드가 실행 중이고 전체 스위치 `schedule.enabled`가 켜져 있어야 합니다.
3. 계정의 비공개 소스(북마크, 내 작품, 팔로우 새 작품, 컬렉션) 및 R-18 등 제한 콘텐츠에는 유효한 `PHPSESSID`가 포함된 Cookie를 작업에 연결해야 합니다. 유효한 Cookie가 없으면 비공개 소스는 중단되며 익명 상태로 빈 작업을 실행하지 않습니다.

## 첫 예약 작업 만들기

예약 작업은 다운로드 페이지의 현재 설정을 스냅샷으로 저장하여 만듭니다. 신구 다운로드 페이지 모두 동일합니다. 다음은 작가의 새 작품을 정기적으로 추적하는 예입니다.

1. 다운로드 페이지에서 '사용자 모드'로 전환하고 작가 프로필 링크나 숫자 ID를 입력합니다. 예시 `https://www.pixiv.net/users/123456`은 실제 작가 ID로 바꾸세요.
2. '다운로드 설정'을 펼쳐 필요에 따라 설정합니다.
   - **파일명 템플릿**: 기본값 `{artwork_id}_p{page}`.
   - **컬렉션**, **최대 동시 작업 수**, **작품 간격**(밀리초, 예: `1000`). 간격을 설정해도 외부 서비스의 제한을 피한다고 보장하지 않습니다.
   - **삭제된 작품 다시 다운로드 허용**: 갤러리에서 삭제한 작품은 [삭제 표시](/ko/gallery#작품-삭제)를 유지하여 기본적으로 건너뜁니다. 선택하면 각 실행에서 자동으로 다시 다운로드합니다. 이 항목은 스냅샷에 저장되며 이전 버전의 작업을 업그레이드하면 기본적으로 선택하지 않은 상태로 보완됩니다.
3. '추가 필터'를 펼쳐 콘텐츠 등급, AI 제외 또는 태그 조건을 설정합니다.
4. 페이지 하단의 '예약 작업으로 저장' 카드로 이동합니다.
   - **작업 이름**을 입력합니다.
   - **트리거 방식**으로 고정 주기(예: `60`분마다) 또는 6필드 Cron 표현식(매일 03:00은 `0 0 3 * * *`)을 선택합니다.
   - 필요하면 [첫 가져오기 한도](#첫-가져오기-한도)과 [전용 프록시/Cookie 지정](#전용-프록시cookie-지정)을 설정합니다.
   - '작업 생성'를 누릅니다.
5. '예약 작업' 목록에서 스냅샷을 확인하고 먼저 '지금 실행'을 한 번 눌러 대기열의 성공, 건너뜀과 실패 이유를 확인한 다음 다음 실행 시간을 확인합니다. 작업은 만들어졌지만 프록시나 Cookie 저장이 실패했다면 해당 작업에서 설정을 이어가세요. 중복 생성하지 마세요.

## Cron 표현식 형식

첫 필드가 '초'인 Spring 6필드 Cron 형식을 사용합니다.

```text
초  분  시  일  월  요일
0   0   3   *   *   *   매일 03:00:00
0   30  8   *   *   1   매주 월요일 08:30:00
0   0   */6 *   *   *   6시간마다
0   0   9   1   *   *   매월 1일 09:00:00
```

| 필드 | 범위 | 자주 사용하는 기호 |
| --- | --- | --- |
| 초 / 분 | `0–59` | `*` 매초/매분, `/n` n초/분마다 |
| 시 | `0–23` | `*` 매시간, `/n` n시간마다 |
| 일 | `1–31` | `*` 매일 |
| 월 | `1–12` | `*` 매월 |
| 요일 | `0–7` | `0` 또는 `7`은 일요일, `*` 매일 |

## 소스 유형별 동작

| 소스 유형 | 실행 방식 |
| --- | --- |
| 작가 새 작품(사용자 모드) / 내 작품 | 첫 실행에 조건에 맞는 미다운로드 작품 수집. 이후에는 **워터마크 기반 증분 수집**으로 이전 실행에서 처리한 최신 작품까지만 검사 |
| 작가 커미션 작품(User의 '커미션' / 빠른 가져오기의 '내 커미션') | 실행마다 완료되어 공개된 커미션 결과물을 나열하고 일반 일러스트 흐름으로 다운로드하며 기존 다운로드는 건너뜀. 순서의 단조성이 보장되지 않아 워터마크를 사용하지 않음 |
| 검색 키워드(검색 모드) | 선택한 페이지 수에 따라 수집. '최신순'이며 마지막 페이지가 `-1`이면 워터마크 증분 수집 사용 |
| 만화 / 소설 시리즈(시리즈 모드) | 실행마다 시리즈 장 목록을 확인하고 다운로드한 장을 건너뛰며 새 장 추가 |
| 내 북마크 / 팔로우 새 작품 / 컬렉션 | [빠른 가져오기](/ko/quick-access)에서 해당 소스를 펼친 후 생성. 컬렉션은 일러스트와 소설을 모두 다운로드. 작업 편집 시 소스는 읽기 전용이며 변경하려면 삭제 후 재생성 |

## 첫 가져오기 한도

이전 작품이 많은 소스에는 '첫 가져오기 한도'을 설정할 수 있습니다. `0`은 개수 제한 없음입니다.

- **첫 실행만 제한**(작가 새 작품, 팔로잉한 사용자의 새 작품, '최신순 + 마지막 페이지 `-1`' 검색): 첫 실행에서 최신 N개 작품까지만 수집하고 워터마크를 전진시킵니다. 이후에는 그 뒤에 게시된 새 작품만 추적하며 더 오래된 기록은 추가 수집하지 않습니다.
- **매 실행 제한**(내 북마크, 컬렉션, 커미션 작품, 최신순이 아닌 '마지막 페이지 `-1`' 검색): 단조로운 최신 순서가 없으므로 실행마다 새 작품 N개까지만 받아들이고 여러 번에 걸쳐 기존 작품을 처리합니다.
- **고정 페이지 검색**: 상한은 매 실행에 적용합니다. `0`은 개수 제한만 없애며 선택한 페이지 범위를 넓히지 않습니다. 1페이지만 선택했다면 자동으로 다음 페이지를 가져오지 않습니다.

!> 기존 다운로드를 건너뛴 작품은 허용 개수를 소모하지 않지만 추가 필터로 건너뛴 작품은 소모합니다. 페이지 제한이 없거나 여러 페이지인 소스에 `0`을 지정하면 많은 이전 작품을 가져올 수 있으므로 저장 전에 확인을 요구합니다.

## 기존 작업 관리

'예약 작업' 목록에서 작업 카드 오른쪽 위의 상태 표시등은 현재 상태를 나타냅니다.

| 표시등 | 의미 |
| --- | --- |
| 회색 | 다음 실행 대기, 비활성화 또는 수동 일시 중지 |
| 녹색 | 실행 중 또는 마지막 실행 성공 |
| 노란색 | 여러 작업의 실행 시점이 겹쳐 순서를 기다리는 중 |
| 빨간색 | 실행 실패, Cookie 만료, 중단 또는 과도한 접근으로 일시 중지. 카드를 눌러 이유 확인 |

카드에서는 **지금 실행**, **전용 프록시/Cookie 지정**, 예약 실행 **활성화 / 비활성화**, **수동 일시 중지 / 재개**, **스냅샷 보기**, **편집**, **재시도 대기**(실패하여 재시도할 작품 확인), **삭제**(다운로드한 파일에는 영향 없음)를 사용할 수 있습니다.

## 전용 프록시/Cookie 지정

개인용 모드에서 작업을 만들 때 유효한 Cookie가 저장되어 있고 개별 설정을 선택하지 않았다면 현재 Cookie가 자동 연결됩니다. 생성 시 또는 작업 카드의 '전용 프록시/Cookie 지정' 대화상자에서 별도로 설정할 수도 있습니다.

- **개별 프록시 설정**: `127.0.0.1:7890` 같은 `host:port`를 입력하면 해당 작업의 모든 Pixiv 요청(발견, 메타데이터, 이미지/소설 다운로드, 메시지함의 과도한 접근 검사)이 해당 HTTP 프록시를 사용합니다. 선택하지 않으면 전역 프록시를 사용합니다.
- **개별 Cookie 설정**: `PHPSESSID`가 포함된 Cookie를 붙여넣거나 '현재 저장된 Cookie 사용'을 누릅니다. 이미 연결된 Cookie는 다시 표시하지 않습니다. 비워 둔 채 저장하면 유지하고 새 값을 입력하면 교체합니다.

적용 중인 선택을 해제하고 저장하면 해당 설정을 지웁니다. 프록시는 전역 설정으로 돌아가고 Cookie 연결을 해제한 작업은 익명 '제한 모드'가 됩니다. R-18을 가져올 수 없으며 계정 비공개 소스는 실행할 수 없습니다. 작업이 Cookie 만료를 감지하면 자동으로 일시 중지하고 '로그인 상태 만료'를 표시합니다. 새 Cookie를 가져와 연결한 후 재개하세요. 같은 만료 Cookie를 다시 제출하면 거부됩니다.

## 과도한 접근 일시 중지 및 알림

Pixiv가 보낸 '과도한 접근' 메시지 경고를 감지하면 시스템이 **같은 계정의 모든 예약 작업**을 자동으로 일시 중지합니다. 목록 상단 배너에는 '위험을 무시하고 즉시 재개'와 'N분 후 계속'이 표시됩니다. 최소값 및 기본값은 60분이며 대기 후 재개를 권장합니다.

데스크톱의 '설정 → 이메일 / SMTP' 또는 '설정 → 푸시'를 설정하면 다음 이벤트에 대해 알림을 병렬로 보냅니다. Bark, DingTalk, Telegram, Feishu, WeCom, PushPlus, ServerChan, Webhook을 지원하며 본문에는 Cookie나 비밀번호를 절대 포함하지 않습니다.

- **과도한 접근 일시 중지**: 영향받은 작업의 이름, ID, 개수와 경고 시간.
- **로그인 상태 만료 / 연속 실패 차단**: 작업 이름, ID, 유형, 트리거 규칙과 다음 실행 시간.
- **실패 작품 재시도 상한 도달**: 해당 작품의 Pixiv 링크도 포함.

## 문제 해결 및 관련 설정

작업이 실행되지 않으면 백엔드 프로세스, 전역 스위치, 작업 활성화 상태와 카드의 중단 이유를 순서대로 확인하세요. 유효한 Cookie로 바꿔도 자격 증명으로 인한 중단만 해제하며 다른 이유의 중단을 자동 해제하지는 않습니다. 다운로드 페이지의 전역 Cookie를 지워도 기존 작업의 개별 자격 증명 연결은 자동 해제되지 않습니다. 작업 소스나 필터 조건을 편집하면 증분 워터마크가 초기화되며 다음 실행에서 다시 검사하고 로컬 다운로드 기록으로 중복을 판정합니다.

| 설정 항목(`config/config.yaml`) | 기본값 | 설명 |
| --- | --- | --- |
| `schedule.enabled` | `true` | 예약 작업 전체 스위치 |
| `schedule.tick-interval-ms` | `60000` | 실행 시점이 된 작업의 검사 간격. 밀리초, 변경 시 재시작 필요 |
| `schedule.max-tasks` | `100` | 생성 가능한 최대 작업 수 |
| `schedule.inbox-check-every` | `500` | 이 수만큼 작품을 성공적으로 다운로드할 때마다 과도한 접근 메시지 검사 |
| `schedule.auth-failure-circuit-breaker` | `5` | 연속 발견 실패가 차단 중단을 유발하는 횟수 |
| `schedule.pending-max-attempts` | `5` | 실패 작품의 최대 자동 재시도 횟수 |
| `schedule.overuse-defer-default-minutes` | `60` | 과도한 접근 일시 중지 후 기본 대기 시간(분). 최소 60 |

전체 설정은 [설정 참조](/ko/configuration)를 참고하세요.
