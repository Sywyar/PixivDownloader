# 예약 작업

백엔드가 실행 중일 때 고정 간격이나 Cron으로 작품을 발견하고 다운로드합니다. 생성 시 원본·필터·다운로드 설정의 스냅샷을 저장하므로 다운로드 페이지를 나중에 바꿔도 기존 작업은 바뀌지 않습니다. 브라우저를 닫아도 실행되지만 백엔드를 종료하면 실행하지 않습니다.

스케줄러와 관리 API는 애플리케이션 호스트가 제공합니다. 다운로드 작업대를 끄면 해당 페이지, Pixiv 원본 및 일러스트 실행기가 사라집니다. 이 기능에 의존하는 예약 작업은 데이터와 진행 상황을 보존한 채 보류되고, 다른 플러그인만으로 실행 가능한 작업은 계속됩니다. 원본이나 실행기의 부재 또는 중지로 보류된 작업은 필요한 기능이 모두 돌아오면 스케줄러가 다시 확인하여 재개합니다. 수동, 자격 증명 또는 정책에 따른 보류는 명시적인 조치가 필요합니다.

작가 신작, 검색, 만화·소설 시리즈, 북마크·컬렉션·팔로우 신작을 정기적으로 확인할 수 있습니다. 관리자만 사용할 수 있습니다. 작업과 전체 스위치가 켜져 있어야 하며 계정 전용 원본과 제한 콘텐츠는 작업에 연결한 유효 `PHPSESSID` Cookie가 필요합니다. 공개 원본은 각 규칙에 따라 익명으로 실행할 수 있지만 전용 원본은 Cookie 없이 실행하지 않고 보류합니다.

## 작업 만들기

현재 다운로드 설정을 저장하는 방식입니다. 작가를 예로 들면 다음과 같습니다.

1. 다운로드 페이지의 User 모드를 열고 실제 작가 링크나 ID를 입력합니다. 예시 형식은 `https://www.pixiv.net/users/123456`입니다.
2. 파일명(기본 `{artwork_id}_p{page}`), 컬렉션, 동시 작업 수, 작품 사이 간격을 설정합니다. 기본 동시 수는 전역값을 따릅니다. 간격은 밀리초이며 1000은 1초지만 상위 서비스 제한을 피한다고 보장하지 않습니다.
3. 필요하면 콘텐츠 등급·AI·태그 필터를 정합니다.
4. 아래 예약 작업 저장 카드에서 이름과 고정 주기 또는 Cron을 선택합니다. 예를 들어 60분마다 또는 매일 03시의 `0 0 3 * * *`입니다.
5. 필요하면 최초 가져오기 상한과 전용 프록시·Cookie를 정합니다.
6. 생성 후 예약 작업 목록에서 스냅샷을 확인합니다. 즉시 실행으로 성공·건너뜀·실패를 확인하고 다음 시각을 확인하세요.

두 다운로드 화면은 같은 예약 설정을 사용합니다. 삭제한 작품 재다운로드 허용도 스냅샷에 저장됩니다. 기본적으로 [삭제 표시](/ko/gallery?id=작품-삭제)가 있으면 이미 다운로드한 것으로 보고 건너뜁니다. 허용하면 다시 다운로드합니다. 과거 작업에는 업그레이드 후 첫 실행에서 기본 해제값을 보충합니다.

작업 생성은 성공했지만 프록시·Cookie 저장이 실패했다고 표시되면 그 작업의 설정을 마저 완료하세요. 다시 생성하지 마세요.

## Cron 형식

Spring의 **6개 필드**이며 맨 앞은 초입니다.

```text
초  분  시  일  월  요일
0   0   3   *   *   *
0   30  8   *   *   1
0   0   */6 *   *   *
0   0   9   1   *   *
```

차례로 매일 03:00, 월요일 08:30, 6시간마다, 매월 1일 09:00입니다. 초·분은 0~59, 시는 0~23, 일은 1~31, 월은 1~12, 요일은 0~7이며 0과 7은 일요일입니다. `*`는 모든 값, 지원 필드의 `/n`은 n 간격입니다.

## 원본별 처리

| 원본 | 처리 방식 |
| --- | --- |
| 작가 신작 | 첫 실행에 조건에 맞는 미다운로드 작품, 이후 마지막 처리 위치까지의 새 작품만 확인 |
| 작가 의뢰 / 내 의뢰 | 완료·공개한 결과물을 매번 전체 발견하고 이미 받은 작품 제외. 순서가 단조롭지 않아 증분 위치를 사용하지 않음 |
| 검색 | 선택한 페이지 범위 조회. 최신순+`-1`이면 증분 위치 사용 |
| 만화·소설 시리즈 | 전체 구성원을 확인하고 누락된 장 다운로드 |
| 내 북마크 | 공개·비공개와 일러스트·소설별 미다운로드 작품 |
| 내 작품 | 자신의 계정을 작가 신작처럼 처리 |
| 팔로우한 사용자의 신작 | 최신 일러스트·만화·Ugoira |
| 컬렉션 | 일러스트와 소설 구성원을 모두 확인하고 누락 작품 다운로드 |

북마크·내 작품·팔로우 신작·컬렉션은 [빠른 가져오기](/ko/quick-access)에서 해당 원본을 펼친 뒤 저장합니다. 별도 모드 탭은 없으며 편집 시 원본은 읽기 전용입니다. 바꾸려면 삭제 후 다시 만드세요. 계정 전용 원본은 유효 Cookie가 없으면 로그인 만료 상태로 보류하며 익명으로 빈 실행하지 않습니다.

## 최초 가져오기 상한

`0`은 수량 제한 없음입니다. 원본의 정렬 안정성에 따라 의미가 다릅니다.

- 작가 신작, 팔로우 신작, 최신순+`-1` 검색은 **첫 실행에만** 최신 N작품을 받고 증분 위치를 최신으로 옮깁니다. 더 오래된 과거 작품은 다음 실행에서 보충하지 않습니다.
- 북마크, 컬렉션, 의뢰, 최신순이 아닌 `-1` 검색은 **매 실행** 최대 N개의 새 작품을 받아 여러 번에 걸쳐 과거 항목을 처리합니다. 0도 원본 범위·필터는 유지합니다.
- 고정 페이지 검색은 매 실행 수량 제한입니다. 0으로 해도 페이지 범위를 넓히지 않으며 첫 페이지만 선택했다면 자동으로 다음 페이지를 읽지 않습니다.
- 시리즈는 구성원 범위 안에서 처리합니다. 화면은 원본 능력에 맞는 상한과 설명을 보여 줍니다.

여러 페이지·무제한 원본에서 0은 많은 과거 요청을 만들 수 있어 저장 전 확인합니다. 첫 페이지 검색은 자체 페이지 경계가 있어 같은 확인이 필요하지 않습니다. 이미 다운로드해 건너뛴 작품은 접수 수량에 포함하지 않지만 필터로 건너뛴 작품은 포함합니다.

## 상태와 관리

| 표시 | 상태 |
| --- | --- |
| 회색 | 대기, 비활성화, 일시 중지 |
| 초록 | 실행 중, 이전 실행 성공 |
| 노랑 | 실행 순서 대기 |
| 빨강 | 실패, Cookie 만료, 중단, 과도한 접근 보류 |

즉시 실행, 전용 프록시·Cookie 변경, 활성·비활성, 협력적 일시 중지·재개, 스냅샷 보기, 편집, 재시도 대기 작품 보기, 작업 삭제를 제공합니다. 작업을 삭제해도 받은 파일은 보존합니다. 보류 이유를 해결한 뒤 명시적으로 재개해야 합니다.

## 전용 프록시와 Cookie

개인 모드에서 생성 시 현재 유효 Cookie가 있고 전용 Cookie를 선택하지 않았다면 자동 연결됩니다.

전용 프록시는 `host:port` 형식입니다. 예를 들어 `127.0.0.1:7890`입니다. 설정하면 해당 실행의 Pixiv 작품 발견, 메타데이터, 이미지·소설, 과도한 접근 쪽지 검사 전체에 적용합니다. 선택하지 않으면 전역 프록시를 사용합니다. 네트워크 출구 선택일 뿐 Pixiv 제한을 없애지는 않습니다.

전용 Cookie는 `PHPSESSID`가 포함되어야 하며 현재 저장된 Cookie를 불러올 수 있습니다. 다른 계정용으로도 사용할 수 있습니다. 이미 연결된 값은 다시 표시하지 않습니다. 선택한 상태에서 비워 저장하면 유지하고 새 값을 입력하면 교체합니다.

이미 적용한 선택을 해제해 저장하면 확인 후 해당 설정을 지웁니다. 프록시는 전역으로 돌아가고 Cookie는 연결 해제되어 익명 제한 모드가 됩니다. R-18과 계정 전용 북마크·팔로우 신작·컬렉션은 접근할 수 없습니다. 생성·편집 카드에서도 같은 설정을 사용할 수 있습니다.

Cookie 만료가 확인되면 자동 중지하고 로그인 만료로 표시하며 설정된 메일·푸시로 알립니다. 새 유효 Cookie를 연결해 복구하세요. 이미 연결된 것과 같은 만료 Cookie는 거부합니다.

## 과도한 접근 보류

Pixiv의 과도한 접근 경고 쪽지를 감지하면 같은 계정의 모든 예약을 보류합니다. 이 보호가 계정 제한을 피한다고 보장하지는 않습니다.

배너에서 위험을 무시하고 즉시 재개하거나 N분 후 재개를 선택할 수 있습니다. 대기 재개는 최소·기본 60분입니다. 일정 시간 기다린 뒤 재개하는 편을 권장합니다.

## 메일과 푸시

Cookie 만료, 과도한 접근, 연속 실패 임계값에 따른 보류, 실패 작품 재시도 상한에 도달할 때 알립니다. 설정된 메일과 Bark·DingTalk·Telegram·Feishu·WeCom·PushPlus·ServerChan·Webhook은 병렬 전송합니다.

과도한 접근은 영향받은 작업 이름·ID·수·경고 시각을, 인증·연속 실패는 작업 유형·주기·다음 실행을 포함합니다. 재시도 상한에는 작품 Pixiv 링크도 포함합니다. Cookie·비밀번호는 포함하지 않습니다.

설정 → 메일/SMTP와 푸시에서 채널을 준비하세요. 미설정 채널은 조용히 건너뜁니다. 각 설정의 테스트로 실제 알림을 확인할 수 있습니다.

## 예상대로 실행되지 않을 때

백엔드, 전체 스위치, 작업 활성 상태를 확인하고 보류 이유를 읽습니다. 자격 증명은 유효 Cookie를, 위험 보류는 배너 조치를, 기능 누락은 해당 플러그인 복구를 처리합니다. 작품 조치 대기라면 작품별 처리 방식을 먼저 선택하세요. Cookie 교체는 자격 증명 이유만 해제하며 다른 보류를 자동 해제하지 않습니다.

원본·필터 정의를 편집하면 증분 위치가 초기화되어 다음 실행에서 다시 발견하고 로컬 이력으로 중복을 제거합니다. 작업 Cookie는 독립 연결이므로 다운로드 페이지 Cookie를 지워도 모든 작업에서 해제되지는 않습니다. 작업별로 명시적으로 지우세요.

## 호스트 설정

| 키 | 기본값 | 의미 |
| --- | --- | --- |
| `schedule.enabled` | `true` | 전체 스위치 |
| `schedule.tick-interval-ms` | `60000` | 만료 확인 간격, 밀리초, 변경 후 재시작 |
| `schedule.max-tasks` | `100` | 최대 작업 수 |
| `schedule.inbox-check-every` | `500` | 이만큼 다운로드 후 경고 쪽지 확인 |
| `schedule.auth-failure-circuit-breaker` | `5` | 연속 실패 보류 기준 |
| `schedule.pending-max-attempts` | `5` | 실패 작품 자동 재시도 상한 |
| `schedule.overuse-defer-default-minutes` | `60` | 과도한 접근 대기 재개 기본 분, 최소 60 |

GUI 예약 설정 또는 `config/config.yaml`에서 변경합니다. [설정](/ko/configuration)을 참고하세요.
