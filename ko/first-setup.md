# 최초 설정

최초 설정에서는 PixivDownloader 관리자 계정과 백엔드의 HTTP 프록시를 설정합니다. 이 계정은 프로그램 로그인용입니다. Pixiv Cookie는 다운로드 페이지에 들어간 뒤 따로 저장합니다.

[설치](/ko/installation)를 마친 뒤 실행 방식에 맞는 방법을 선택하세요.

| 사용 방식 | 초기화 | 그다음 |
| --- | --- | --- |
| 로컬 데스크톱 | 데스크톱 안내에서 관리자 계정 생성 | 다운로드 페이지에 로그인 |
| 화면 없는 서버 또는 `--no-gui` | 먼저 `--setup` 실행 | `--no-gui`로 실행 |
| Docker | `docker compose run --rm app --setup` | `docker compose up -d` |

## 데스크톱에서 설정

1. 프로그램을 실행하고 백엔드가 준비될 때까지 기다립니다. 필수 플러그인 누락이나 데이터베이스 오류가 표시되면 [플러그인 관리](/ko/plugin-management)에 따라 복구하세요. 계정을 다시 초기화해도 이 문제는 해결되지 않습니다.
2. 관리자 이름과 비밀번호를 입력합니다. 최소 8자이며 12자 이상을 권장합니다. 권장 길이보다 짧으면 다시 확인합니다.
3. 실제 네트워크에 맞는 HTTP 프록시 호스트와 포트를 입력합니다. 로컬 프록시가 실제로 `7890`에서 수신한다면 `127.0.0.1`, `7890`을 사용합니다. 필요한 서비스에 직접 접속할 수 있으면 프록시를 끌 수 있습니다.
4. 저장한 뒤 `http://localhost:6999/pixiv-batch.html`을 열고 방금 만든 계정으로 로그인합니다.

데스크톱과 브라우저 초기화 화면은 개인 사용 모드(`solo`)를 사용하며 다중 사용자 모드를 선택하는 항목은 없습니다. 탭과 단계는 데스크톱 화면에 따라 다르므로 현재 안내를 따르세요.

로컬 브라우저의 `http://localhost:6999/setup.html`에서도 계정과 프록시를 설정할 수 있습니다. 저장하면 로그인 페이지로 이동합니다. 이 페이지는 로컬 접속만 허용합니다. 초기화 전 무화면 실행은 종료되므로 아래 CLI 명령을 먼저 사용하세요.

프록시는 호스트 또는 작업의 프록시 경로를 사용하는 요청에만 적용됩니다. 브라우저, SMTP, 데이터베이스 연결, 명시적 직접 연결 요청은 각자 다른 경로를 사용합니다. [네트워크 안내](/ko/network-access)를 참고하세요. 이후 일반 설정은 데스크톱 설정 화면에서 저장하고 적용 또는 재시작 안내를 따릅니다.

## 명령줄에서 설정

배포 파일을 모두 압축 해제한 디렉터리로 이동하고 같은 인스턴스를 중지합니다. 다음 명령은 PowerShell과 Bash에서 사용할 수 있습니다. `APP.jar`를 실제 주 프로그램 JAR 이름으로 바꾸고 같은 디렉터리의 `plugins/`를 보존하세요.

```text
java -Dfile.encoding=UTF-8 -jar APP.jar --setup --mode=solo
```

이름, 비밀번호, 프록시를 차례로 입력합니다. 비밀번호는 최소 8자이며 권장 길이 12자 미만이면 변경하거나 계속할지 확인합니다. CLI는 `--mode=solo`와 `--mode=multi`를 받습니다. 여기서는 `solo`를 사용합니다. 다른 사람을 초대하려면 [고급 사용 안내](/ko/usage-guide)를 참고하세요.

성공하면 계정 상태는 `state/setup_config.json`, 제출한 프록시는 `config/config.yaml`에 저장됩니다. 이후 서비스를 실행합니다.

```text
java -Dfile.encoding=UTF-8 -jar APP.jar --no-gui
```

자동화가 필요하면 모든 인수를 명시할 수 있습니다.

```text
java -Dfile.encoding=UTF-8 -jar APP.jar --setup --username=admin --password=REPLACE_WITH_A_UNIQUE_PASSWORD --mode=solo --proxy-enabled=true --proxy-host=127.0.0.1 --proxy-port=7890
```

비밀번호, 호스트, 포트를 자신의 값으로 바꾸세요. 프록시가 필요 없으면 `--proxy-enabled=false`를 사용합니다. 명령줄 비밀번호는 Shell 기록과 프로세스 목록에 남을 수 있으므로 일반 사용에서는 대화형 입력을 권장합니다.

## Docker에서 설정

[Docker 설치 안내](/ko/installation)에 따라 이미지와 쓰기 가능한 마운트 디렉터리를 준비한 뒤 `docker-compose.yml`이 있는 디렉터리에서 실행합니다.

```bash
docker compose run --rm app --setup --mode=solo
docker compose up -d
docker compose logs -f app
```

컨테이너의 `127.0.0.1`은 컨테이너 자신입니다. 호스트 프록시를 쓴다면 compose 설정에 맞춰 `host.docker.internal`과 실제 프록시 포트를 입력하고 호스트가 해당 연결을 허용하는지 확인하세요.

초기화 전에 무화면 서비스를 실행하면 종료 코드 `78`로 끝납니다. 자동 재시작 정책이 있는 컨테이너는 재시작을 반복할 수 있습니다. 서비스를 중지하고 `--setup`을 완료한 다음 다시 실행하세요.

## 성공 여부 확인

관리자 계정으로 다운로드 페이지에 로그인하여 작업대가 표시되는지 확인합니다. 이어서 [첫 다운로드](/ko/first-download)로 작품 하나를 추가하세요. 로그인 성공은 프로그램 계정만 확인합니다. Pixiv 연결과 Cookie 유효성은 따로 확인해야 합니다.

저장이나 실행이 실패하면 오류와 `log/`의 해당 로그를 보존하세요. 다른 인스턴스 실행 여부, 설정 디렉터리 쓰기 권한, 필수 플러그인과 데이터베이스 상태를 먼저 확인하고 초기화 파일을 반복해서 삭제하지 마세요.

## 비밀번호 변경 또는 재설정

같은 인스턴스를 중지한 뒤 배포 디렉터리에서 아래 명령 중 하나를 실행합니다. 변경에는 기존 비밀번호가 필요하며, 잊었다면 로컬 재설정을 사용합니다.

```text
java -Dfile.encoding=UTF-8 -jar APP.jar --change-password
java -Dfile.encoding=UTF-8 -jar APP.jar --reset-password
```

성공하면 기존 세션이 무효화됩니다. 프로그램을 다시 실행하고 새 비밀번호로 로그인하세요. 작품과 데이터베이스는 삭제되지 않습니다.

초기화 상태 자체를 다시 만들어야 한다면 프로그램을 중지하고 `state/setup_config.json`을 백업한 뒤 해당 파일을 다른 곳으로 옮기고 초기화합니다. 계정, 실행 모드, 로그인 상태가 초기화됩니다. 비밀번호 복구에는 먼저 `--reset-password`를 사용하세요.
