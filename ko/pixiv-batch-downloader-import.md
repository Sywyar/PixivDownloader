# PixivBatchDownloader 가져오기 지원

공식 `pixiv-batch-downloader-import` 플러그인과 사용자 스크립트를 함께 사용하면 PixivBatchDownloader에서 이후 다운로드를 완료한 일러스트, 만화, Ugoira, 소설이 로컬 갤러리에 자동 등록됩니다. 처음에 다운로드 디렉터리만 설정하면 됩니다. 원본 파일은 복사하거나 이동하지 않으며 갤러리 기록을 삭제해도 보존됩니다.

브라우저와 프로그램은 같은 컴퓨터에서 실행하고 프로그램은 개인 모드여야 합니다. 스크립트는 로컬 서비스에만 연결하며 대기 정보를 사용자 스크립트 저장소에 보관합니다. 파일 URL 접근 권한은 필요하지 않습니다. 설치 전 다운로드는 자동 검색하지 않습니다.

## 설치와 사용

일반 배포 패키지에는 기본 설치되지 않으며 full-offline 패키지에는 포함됩니다.

1. 프로그램의 플러그인 마켓에서 공식 **PixivBatchDownloader 가져오기 지원**을 설치하고 프로그램을 완전히 종료한 뒤 다시 실행합니다. 이미 설치하고 활성화했다면 건너뜁니다.
2. 브라우저에 PixivBatchDownloader와 Tampermonkey를 설치·활성화하고 Tampermonkey가 Pixiv에서 실행되도록 허용합니다. Chrome 138+에서는 확장 프로그램 → Tampermonkey → 세부정보의 사용자 스크립트 허용도 켭니다. 다른 버전은 [Tampermonkey 권한 안내](https://www.tampermonkey.net/faq.php?ext=dhdg&q=Q209)를 따릅니다.
3. 데스크톱 설정의 가져오기 지원 항목에서 브라우저 다운로드 루트를 선택합니다. 첫 다운로드 후 제안된 디렉터리를 확인해도 됩니다. 하위 디렉터리도 사용할 수 있습니다. 직접 편집한다면 `config/plugins/pixiv-batch-downloader-import.properties`의 `pixiv-batch-downloader-import.source-root`에 절대 경로를 씁니다. Windows에서는 `D:/Downloads`처럼 슬래시를 사용하세요. 저장 즉시 적용되며 백엔드 재시작은 필요 없습니다.
4. 브라우저에서 로컬 서비스에 로그인한 뒤 [가져오기 스크립트 설치 주소](http://localhost:6999/api/scripts/pixiv-batch-downloader-import.user.js)를 열고 Tampermonkey에서 설치 및 활성화하세요. 포트가 다르면 주소를 변경하세요. 작업대가 활성화되어 있으면 더 보기 → 사용자 스크립트에서도 설치할 수 있습니다. 스크립트와 설치 API는 다운로드 작업대에 의존하지 않습니다.
5. 열린 Pixiv 페이지를 새로 고칩니다. 스크립트는 설치 출처의 로컬 호스트, 프로토콜, 포트를 사용합니다. 직접 저장한 주소가 우선하며 스크립트 메뉴의 로컬 서버 주소 설정에서 변경할 수 있습니다. 소스 파일을 직접 설치하면 기본 주소는 `http://localhost:6999`입니다.
6. 로컬 백엔드를 실행한 채 평소처럼 PixivBatchDownloader로 가져오고 다운로드합니다. 한 작품의 모든 파일이 완료되면 해당 갤러리에 자동 등록됩니다. JSON을 복사할 필요는 없습니다.

루트를 설정하지 않았다면 첫 완전한 성공 기록의 절대 경로로 데스크톱 확인을 요청합니다. 창에 초점을 요청하고 설정의 디렉터리 창을 열어 후보를 보여 주며 다른 경로를 선택할 수도 있습니다. 이후 다운로드를 포함할 루트를 선택하고 확인·저장을 눌러야 설정에 기록되고 가져오기를 재시도합니다.

취소하면 저장하지 않으며 같은 기록의 재시도 때 창을 반복해서 띄우지 않습니다. 나중에 설정에서 직접 선택할 수 있습니다. 상대 경로, GUI 없는 실행, 안전하지 않은 후보는 수동 설정이 필요합니다. 후보 표시, 저장 확인, 실제 가져오기에서 모두 경로를 검사하며 심볼릭 링크와 junction은 일반 디렉터리로 허용하지 않습니다.

## 다운로드가 갤러리에 나타나지 않을 때

스크립트를 설치하거나 활성 상태를 바꾼 뒤 Tampermonkey 상태를 확인하고 다운로드 페이지와 Pixiv 페이지를 새로 고치세요. Pixiv의 사용자 스크립트 메뉴에서 자동 가져오기 상태를 확인합니다.

| 코드 | 조치 |
| --- | --- |
| `SOURCE_ROOT_REQUIRED` | 제안된 디렉터리를 확인하거나 설정에서 루트 지정 |
| `SERVER_UNAVAILABLE` | 백엔드 실행 여부와 서비스 주소 확인 |

서비스에 연결할 수 없으면 등록 대기 정보를 사용자 스크립트 저장소에 보존합니다. Pixiv 페이지가 열려 있으면 자동 재시도하며 새로 고쳐도 저장된 기록은 유지됩니다. 메뉴는 대기, 미완료, 확인 필요 수를 표시합니다.

메타데이터 불명, 페이지 누락, 다운로드 건너뜀, 경로 충돌은 완전한 작품으로 등록하지 않습니다. 다시 가져와 완전한 정보를 확보해야 합니다. 스크립트는 과거 다운로드 디렉터리를 검색하거나 PixivBatchDownloader의 상태를 수정하지 않습니다.

## 통계와 백업

데스크톱 홈의 가져온 작품 수는 이 플러그인이 성공적으로 가져온 고유 작품 수입니다. 여러 페이지 만화는 한 작품이며 같은 ID의 일러스트와 소설은 별개입니다. 재시작해도 유지되고 갤러리 기록 삭제로 줄지 않습니다. 기존 작품, 실패, 건너뜀은 세지 않으며 과거 가져오기 수를 소급 채우지 않습니다.

통계는 `data/pixiv-batch-downloader-import/plugin.db`에 있으므로 함께 백업하세요. 통계 쓰기가 일시적으로 실패하면 사용 불가로 표시하고, 스크립트 재시도에서 통계를 보충한 뒤 성공을 확인합니다. 작품 등록과 통계는 별도 커밋이므로 그 사이 프로세스가 강제 종료되면 해당 횟수가 누락될 수 있습니다.

## 형식과 읽기 전용 제한

- 실제 파일은 설정한 루트 안에 있어야 하며 이름과 하위 디렉터리는 자유롭습니다. 링크, junction, 루트 밖 경로, 누락 파일, 지원하지 않는 파일 헤더는 거부합니다.
- 이미지는 JPEG, PNG, WebP, GIF를 지원합니다. Ugoira는 WebP, GIF, APNG, WebM, MP4, ZIP을 지원합니다. 소설은 TXT와 EPUB을 지원하며 본문은 같은 가져오기에서 얻은 메타데이터를 사용합니다. ZIP 썸네일은 첫 이미지 항목만 읽고 원본은 ZIP으로 유지합니다.
- 소설 표지, 첨부 파일, 원래 게시 시각은 가져오지 않습니다. 현재 소설 페이지는 등록 시각을 업로드 시각으로 표시합니다.
- 데이터베이스에는 페이지별 실제 경로와 메타데이터를 기록합니다. 원본은 변경하지 않으며 미디어 유지 관리도 외부 읽기 전용 작품은 건너뜁니다. 원본을 이동하면 위치를 복구해야 하며 프로그램이 새 경로를 추측하지 않습니다.
- 소프트 삭제를 포함한 기존 기록은 덮어쓰거나 중복 등록하지 않습니다. 소설 기능이 없으면 대기 정보를 보존하고 성공으로 응답하지 않습니다.
- 파일 하나는 최대 1 GiB, 작품 하나는 최대 8 GiB와 1000페이지입니다. 브라우저의 현재 메타데이터는 최대 1000작품·8 MiB, 대기열은 최대 1000작품·5000파일·8 MiB입니다. 가득 차면 알리고 새 기록 접수를 중지합니다.
- HTTP 요청은 최대 12 MiB, JSON 깊이는 20, 소설 본문은 300만 문자입니다. 항목별로 전송하고 실패 간격을 최대 60초까지 늘립니다. 토큰은 한 번만 사용하며 1분 동안 유효합니다. 주소는 loopback만 허용하고 Pixiv Cookie나 관리자 비밀번호는 보내지 않습니다.

이벤트는 [고정된 PixivBatchDownloader 소스](https://github.com/xuejianxianzun/PixivBatchDownloader/tree/e3bbdfdd2fb452cc9073450b8aa1ad065f982b64)에 대응합니다. 상위 프로젝트의 내부 이벤트이므로 같은 배치의 다운로드 성공 이벤트 전에 메타데이터가 도착해야 합니다. 실제 확장 이벤트 호환성은 브라우저와 사용자 스크립트 관리자에 따라 달라집니다.

## 유저스크립트에서 기록 가져오기

1. 로컬 백엔드를 실행하고 플러그인 설정의 외부 다운로드 폴더에 원본 파일의 루트 폴더를 저장하세요. 연동 스크립트를 설치하거나 업데이트한 뒤 Pixiv를 새로 고치고 해당 작품에 접근할 수 있는 계정으로 로그인하세요.
2. PixivBatchDownloader를 사용하던 브라우저와 프로필에서 원래 Pixiv 사이트를 여세요. 외부 다운로드를 일시 중지하고 Tampermonkey 메뉴에서 “브라우저 다운로드 기록 읽기”, “읽고 확인”을 선택한 뒤 로컬 미리보기를 기다리세요. 기록 내보내기나 파일 선택은 필요하지 않습니다.
3. 대상, 이미 존재, 누락 또는 충돌 건수를 확인하고 “가져오기 시작”을 누르세요. 브라우저가 작품 정보를 순서대로 가져오면 로컬 서버가 파일을 검증하고 등록합니다. Pixiv 쿠키는 브라우저에 남습니다.

세부 내용에는 최대 100개 작품의 확인 결과가 표시됩니다. 대상이 0개이면 확인은 끝난 상태이며 “가져오기 시작”은 비활성화된 채로 유지됩니다. 더 기다릴 필요는 없습니다. 누락 또는 충돌이 반드시 파일 이동을 뜻하지는 않습니다. 설정한 루트 폴더에 기록의 상대 경로 `n`을 붙인 위치가 실제 파일과 일치하는지, 파일 이름과 페이지 기록이 완전한지 확인하세요. 세션이 해제되면 “읽고 확인”을 다시 누를 수 있습니다. 해제에 실패하면 결과를 확인할 수 없다는 메시지가 표시됩니다.

현재 Pixiv 사이트의 기록 데이터베이스를 읽기 전용으로 나누어 읽고 세션당 최대 1 GiB를 로컬 서버에 전송합니다. 읽는 동안 기록을 지우거나 수정하지 마세요. 동시에 변경되는 기록의 일관된 스냅샷은 보장하지 않습니다. 원본 작품 파일을 읽거나 업로드하지 않으며 기록 데이터베이스를 생성·업그레이드·수정하지 않습니다. 다른 브라우저 프로필이나 사이트 출처의 기록, 삭제된 기록은 읽을 수 없습니다. 원본은 읽기 전용으로 참조하고 소프트 삭제된 기록을 포함한 기존 작품은 건너뜁니다. 파일이나 페이지가 없거나 작품 정보를 얻을 수 없으면 등록하지 않습니다. 등록 후 기존 보완 도구로 지원 필드를 채울 수 있지만 누락된 원본은 복구할 수 없습니다.

가져오는 동안 페이지를 열어 두세요. 취소, 페이지 이동, 서버 주소 변경은 중지를 요청하며 이미 등록한 작품은 유지됩니다. 기록 작업은 스크립트 대기열에 저장되지 않고 새로 고친 뒤 자동 재개되지 않습니다. 통신 실패 시 결과가 확인되지 않았을 수 있으므로 로컬 서버를 확인하세요. 작업 생성 응답이 유실되었다면 약 15분의 유휴 정리와 현재 작업 종료를 기다린 뒤 다시 시도하세요. 임시 파일은 `data/pixiv-batch-downloader-import/browser-history/`에 저장하며 정상 종료 또는 유휴 만료 후 정리합니다. 강제 종료 후 남은 파일은 앱을 완전히 종료한 상태에서 삭제할 수 있습니다.
