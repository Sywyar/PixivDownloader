# 작업 CAPTCHA

공식 `captcha` 플러그인은 로그인 등 보호된 양식에 Turnstile, reCAPTCHA v2, ALTCHA SHA-256, ALTCHA PBKDF2, 문자 CAPTCHA(오프라인), 슬라이더 퍼즐(오프라인)의 여섯 가지 검증 컴포넌트를 제공합니다. 일반 배포 패키지에는 사전 설치되지 않으며 필요하면 플러그인 마켓에서 설치하거나 오프라인 전체 패키지를 사용할 수 있습니다. 호환되는 양식에 컴포넌트를 끌어 넣고 페이지를 게시하면 프런트엔드와 백엔드가 챌린지 증명을 강제로 검증합니다.

CAPTCHA는 자동 제출의 비용을 높이는 기능이며 네트워크 계층의 DDoS 방어, 리버스 프록시 요청 제한이나 접근 제어를 대신하지 않습니다. 관련 외부 요청은 [네트워크 접근 및 외부 서비스](/ko/network-access)를 참고하세요.

## 검증 방식 비교

| 컴포넌트 | 사용자 동작 | 검증 위치 | 사전 준비 |
| --- | --- | --- | --- |
| ALTCHA SHA-256(오프라인) | 클릭 후 브라우저가 SHA-256 작업 증명을 완료할 때까지 대기 | 로컬에서 챌린지 발급 및 서명 검증. 외부 서비스 불필요 | 최초 활성화 시 로컬 서명 키 자동 생성 |
| ALTCHA PBKDF2(오프라인) | 클릭 후 브라우저가 PBKDF2/SHA-256 키 파생 증명을 완료할 때까지 대기 | 로컬에서 챌린지 발급 및 서명 검증. 외부 서비스 불필요 | SHA-256과 로컬 서명 키 공유 |
| 문자 CAPTCHA(오프라인) | 이미지의 5자리 영문자 또는 숫자를 입력하고 확인. 대소문자 구분 없음 | 로컬 Hutool로 이미지 생성, 서버 메모리에서 대조 | 추가 설정 없음 |
| 슬라이더 퍼즐(오프라인) | 슬라이더를 끌거나 방향키 + Enter로 퍼즐을 빈칸에 맞추고 확인 | 로컬 Tianai로 퍼즐 생성, 서버 메모리에서 대조 | 추가 설정 없음 |
| Turnstile 온라인 검증 | 관리형 모드에서 '검증 시작'을 눌러 Cloudflare 위젯 로드 | 브라우저가 Cloudflare 로드, 서버가 Siteverify 호출 | Cloudflare 계정, Sitekey, Secret key와 허용 호스트 이름 |
| reCAPTCHA v2 온라인 검증 | 체크박스 선택. Google 정책에 따라 이미지 문제가 나올 수 있음 | 브라우저가 Google 위젯 로드, 서버가 Siteverify 호출 | Google reCAPTCHA v2 Checkbox 공개 키, 비밀 키와 호스트 이름 |

!> 보통 양식마다 한 종류의 컴포넌트면 충분합니다. **같은 양식에 여러 CAPTCHA 컴포넌트를 넣으면 모두 완료해야 제출할 수 있습니다.** 온라인 서비스를 사용할 수 없다고 오프라인 컴포넌트로 자동 전환하지 않습니다.

## 설치 및 양식 연결

1. [플러그인 관리](/ko/plugin-management)에서 '작업 CAPTCHA'와 '페이지 편집기'를 설치하고 활성화합니다.
2. Turnstile이나 reCAPTCHA v2를 사용한다면 먼저 데스크톱의 '설정 → 작업 CAPTCHA'에서 아래 키와 호스트 이름을 설정하고 저장합니다. 오프라인 컴포넌트는 미리 설정할 필요가 없습니다.
3. [페이지 편집기](/ko/page-editor)를 열고 로그인 페이지 등 대상 페이지를 선택합니다. 왼쪽의 '구성 요소 추가 → CAPTCHA'에서 원하는 컴포넌트를 끌어 넣고 오른쪽의 '보호 작업'이 대상 양식에 연결되어 있는지 확인합니다.
4. '게시'를 누르고 필요한 외부 리소스 권한을 확인합니다. 초안만 저장해도 정식 페이지의 CAPTCHA 보호가 켜지는 것은 아닙니다.
5. 로그인하지 않은 창에서 정식 로그인 페이지를 열고 사용자 이름과 비밀번호를 입력한 다음 CAPTCHA를 완료하고 '로그인'을 누릅니다.

사용자 이름, 비밀번호 또는 '로그인 상태 유지'를 바꾸면 이번 증명이 지워집니다. 비밀번호 오류, 검증 실패나 챌린지 만료 후에는 다시 검증해야 합니다.

## 오프라인 컴포넌트 설정 및 설명

- **ALTCHA(SHA-256 / PBKDF2)**: 최초 활성화 시 32바이트 무작위 서명 키를 자동 생성하고 호스트가 `config/credentials/captcha.properties`에 암호화하여 저장합니다. 만료 시간이 없고 일상적으로 수정할 필요가 없습니다. 수동 교체 시 최소 32자여야 하며 자격 증명을 지우면 플러그인을 다시 활성화해야 새 키를 생성합니다. Worker 스크립트는 플러그인에 내장되어 외부 CDN이 필요하지 않습니다. 브라우저 계산은 [Web Crypto `SubtleCrypto`](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto)에 의존하므로 `localhost`, `127.0.0.1` 또는 HTTPS로 접근하세요. 일반 LAN 평문 HTTP에서는 브라우저가 Web Crypto를 비활성화할 수 있습니다.
- **문자 입력 및 슬라이더 퍼즐**: 이미지는 로컬에서 생성하며 챌린지는 120초 동안 유효하고 한 번만 사용할 수 있습니다. '다른 이미지'를 누르면 현재 양식의 모든 검증 상태가 초기화됩니다. 두 방식은 기본적인 자동화 방지 기능만 제공하며 슬라이더에는 행동 궤적 모델이 없습니다. 요청 제한과 함께 사용하는 것이 좋으며 접근성이 필요한 경우 이미지 판별이 필요 없는 ALTCHA를 우선 사용하세요.

## Cloudflare Turnstile 설정

1. [Cloudflare 콘솔](https://dash.cloudflare.com/)에 로그인하고 **Turnstile → Add widget**으로 이동합니다. `localhost`나 `download.example.com`처럼 실제 접근 호스트 이름을 추가합니다. 프로토콜, 포트나 경로는 포함하지 마세요. 모드는 **Managed**를 선택하고 생성 후 Sitekey와 Secret key를 받습니다.
2. 데스크톱의 '설정 → 작업 CAPTCHA'에서 Cloudflare Turnstile을 선택하고 **사이트 공개 키**(Sitekey), **서명 검증 비밀 키**(Secret key)와 **예상 호스트 이름**을 입력합니다. 호스트 이름은 브라우저가 실제 접근하는 이름과 정확히 일치해야 하며 `localhost`와 `127.0.0.1` 사이를 전환하면 함께 바꿔야 합니다. '공식 테스트 설정 허용'을 끄고 저장합니다.
3. 페이지 편집기에서 Turnstile이 연결된 페이지를 게시합니다. 공개 키, 예상 호스트 이름이나 테스트 스위치를 바꾸면 페이지를 다시 게시해야 합니다. 비밀 키만 교체하면 다시 게시할 필요가 없습니다.

**공식 테스트 키(제출 흐름 통합 테스트 전용이며 자동화 방지 보호 없음)**: 공개 키 `1x00000000000000000000AA`, 비밀 키 `1x0000000000000000000000000000000AA`, 예상 호스트 이름 `example.com`을 입력하고 '공식 테스트 설정 허용'을 켠 후 페이지를 다시 게시합니다. 실제 운영 전에 반드시 실제 키로 바꾸고 테스트 설정을 끈 후 다시 게시하세요.

## Google reCAPTCHA v2 설정

1. [Google reCAPTCHA 관리 콘솔](https://www.google.com/recaptcha/admin/create)에서 **v2 → '로봇이 아닙니다' 체크박스** 사이트를 만듭니다. v3나 Invisible을 선택하지 마세요. 실제 접근 호스트 이름을 추가하며 로컬 테스트에는 `localhost`를 입력합니다.
2. 데스크톱의 '설정 → 작업 CAPTCHA'에서 Google reCAPTCHA v2를 선택하고 **사이트 공개 키**, **서명 검증 비밀 키**와 **예상 호스트 이름**을 입력한 후 'reCAPTCHA 공식 테스트 설정 허용'을 끄고 저장합니다.
3. 페이지 편집기에서 'reCAPTCHA v2 온라인 검증'을 끌어 넣고 페이지를 게시합니다.

**공식 테스트 키(통합 테스트 전용이며 실제 보호 없음)**: 공개 키 `6LeIxAcTAAAAAJcZVRqyHh71UMIEGNQ_MXjiZKhI`, 비밀 키 `6LeIxAcTAAAAAGG-vFI1TnRWxMZNFuojJ4WifJWe`를 입력합니다. 예상 호스트 이름은 비워 둘 수 있으며 `testkey.google.com`을 검증합니다. 'reCAPTCHA 공식 테스트 설정 허용'을 켜고 페이지를 다시 게시하세요.

## 문제 해결

| 현상 또는 로그 오류 코드 | 확인 및 처리 |
| --- | --- |
| 편집기에는 컴포넌트가 있지만 정식 로그인 페이지에는 없음 | 초안 저장만 한 것이 아닌 '게시'를 눌렀는지 확인하고 정식 페이지 새로고침 |
| `CAPTCHA_CREDENTIAL_MISSING` / `CAPTCHA_CREDENTIAL_INVALID` | 로그에 표시된 키 이름에 따라 비밀 키가 비어 있거나 너무 짧은지 확인. 비밀 키를 로그나 Issue에 붙여넣지 말 것 |
| `CAPTCHA_CONFIG_INVALID` | 공개 키, 예상 호스트 이름과 테스트 모드 스위치가 맞는지 확인. 테스트 키에는 테스트 스위치가 필요 |
| `PUBLISHED_POLICY_CHANGED` | CAPTCHA 설정 변경 후 페이지 편집기에서 해당 페이지 다시 게시 |
| `CAPTCHA_REMOTE_UNAVAILABLE` 또는 위젯이 로드되지 않음 | 브라우저와 백엔드에서 Cloudflare / Google로 연결하는 네트워크 및 프록시 설정 확인 |
| `HOSTNAME_MISMATCH` | 브라우저 주소 표시줄의 호스트 이름, 공급자 콘솔의 허용 도메인과 플러그인의 '예상 호스트 이름'이 모두 같은지 확인 |
| ALTCHA를 추가해도 정책을 사용할 수 없다고 표시 | 같은 양식에 미설정 Turnstile이나 reCAPTCHA 컴포넌트가 남아 있는지 확인하고 불필요한 컴포넌트를 제거한 후 다시 게시 |

`captcha` 플러그인을 비활성화하거나 제거해도 게시된 페이지의 검증 요구를 우회할 수 없습니다. 보호된 작업은 계속 거부됩니다. CAPTCHA를 없애려면 페이지 편집기에서 컴포넌트를 제거하고 페이지를 다시 게시해야 합니다.
