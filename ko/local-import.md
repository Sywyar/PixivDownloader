# 로컬 작품 가져오기와 프리셋

내 폴더에 이미 저장된 이미지를 경로에 포함된 작품 ID로 작품 라이브러리에 등록할 수 있습니다. 가져오기는 원래 폴더와 파일을 그대로 둡니다. 제목이나 작가 정보가 없어도 먼저 등록하고 나중에 메타데이터를 보완할 수 있습니다.

?> '로컬 작품 가져오기' 도구가 있는 버전을 사용하고 백엔드를 실행해 두세요. Compose와 Swing 모두 데스크톱 도구 페이지에서 엽니다. HTTP API에 전달하는 경로도 백엔드가 실행 중인 컴퓨터의 경로입니다.

Compose에서는 '빠른 도구'의 대화상자로 열립니다. 닫아도 시작한 스캔이나 가져오기는 계속됩니다. 도구를 다시 열어 진행 상황을 확인하거나 취소할 수 있습니다.

저장된 경로가 있으면 세 입력란을 모두 비운 채 바로 검색할 수 있습니다. 임시 경로 템플릿, 작품 ID, 지정 파일은 '이번 가져오기 옵션'에 모여 있습니다. 기본적으로 접혀 있으며 필요할 때 직접 펼칠 수 있습니다.

저장된 프리셋이 없으면 경로 템플릿을 입력해야 합니다. 비운 채 검색 및 미리보기를 누르면 옵션이 펼쳐지고 템플릿 입력란에 빨간 테두리와 오류 메시지가 표시됩니다. 작품 ID와 지정 파일은 비워 둘 수 있습니다.

## 실제 경로를 경로 템플릿으로 바꾸기

**경로 템플릿**은 경로에서 달라지는 부분을 중괄호로 표시합니다. 앱은 그 위치에서 정보를 읽습니다. 모든 템플릿에는 `{artwork_id}`가 필요하며 폴더명이나 파일명에 넣을 수 있습니다.

| 기존 파일의 실제 경로 | 입력할 경로 템플릿 | 읽어 오는 정보 |
| --- | --- | --- |
| `D:/xxx/12345/pic.png` | `D:/xxx/{artwork_id}/` | 작품 ID 12345. 해당 폴더와 하위 폴더의 지원 파일 수집 |
| `D:/xxx/12345_xxx.png` | `D:/xxx/{artwork_id}_xxx.{extension}` | 작품 ID 12345, 확장자 png. `_xxx`는 고정 문자열 |
| `D:/678/12345/pic.png` | `D:/{author_id}/{artwork_id}/` | 작가 ID 678, 작품 ID 12345 |
| `D:/xxx/12345_p0.jpg` | `D:/xxx/{artwork_id}_p{page}.{extension}` | 작품 ID 12345, 페이지 번호 0 |

`/`로 끝나지 않는 템플릿은 폴더가 아닌 파일을 지정하는 템플릿으로 처리됩니다. 폴더와 그 하위 디렉터리의 지원 파일을 찾으려면 끝의 `/`를 유지하세요. 파일 템플릿은 파일명과 확장자까지 적습니다. 절대 경로를 사용하며 Windows에서는 `/`와 `\`를 모두 쓸 수 있습니다. 템플릿은 폴더를 만들거나 파일명을 바꾸지 않습니다.

## 한 번만 가져오기: 임시 템플릿 입력

1. 데스크톱에서 '도구 → 로컬 작품 가져오기'를 엽니다.
2. '이번 가져오기 옵션'을 펼치고 임시 경로 템플릿에 `D:/xxx/{artwork_id}/`처럼 입력합니다. 여러 개라면 한 줄에 하나씩 적습니다.
3. 한 작품만 가져오려면 작품 ID에 `12345`를 입력합니다. 여러 작품은 줄바꿈, 공백 또는 쉼표로 구분합니다. 비우면 일치하는 모든 작품을 검색합니다.
4. 파일 하나만 등록하려면 지정 파일 항목도 입력합니다. 해당 파일의 ID를 읽을 수 있는 템플릿은 여전히 필요합니다.
5. 검색 후 미리보기에서 작품 ID, 경로, 처리 내용을 확인하고 가져오기를 시작합니다.

임시 템플릿을 입력하면 해당 템플릿만 사용합니다. 임시 템플릿이 비어 있을 때 프리셋을 사용합니다. 도구 페이지의 입력은 이번 작업에만 적용되며 설정에 저장되지 않습니다.

## 반복해서 사용하기: 로컬 가져오기 프리셋 저장

**로컬 가져오기 프리셋**은 저장된 경로 템플릿 목록입니다. 입력한 경로가 그대로 표시되며 가져올 때 저장된 모든 경로를 자동으로 사용합니다.

1. '도구 → 로컬 작품 가져오기'를 열고 대화상자 안의 '로컬 가져오기 프리셋'을 누릅니다.
2. '경로 추가'를 누르고 `D:/{author_id}/{artwork_id}/` 같은 절대 경로 템플릿을 한 줄에 하나씩 입력합니다. 경로를 두 번 클릭하여 편집하거나 행을 제거할 수 있습니다.
3. '프리셋 저장'을 누릅니다. 다시 시작하지 않아도 다음 검색부터 적용됩니다. 취소하면 저장된 경로는 바뀌지 않습니다.
4. '로컬 작품 가져오기'를 열고 세 입력란을 모두 비우면 저장된 모든 경로를 검색합니다. 작품을 제한하려면 옵션을 펼치고 `12345` 또는 ID 목록을 입력하세요.
5. 도구에 저장된 모든 경로가 표시되고 모두 사용됩니다. 미리보기를 확인한 뒤 시작합니다.

ID를 `12345`로 제한하면 작가 ID를 입력하지 않아도 `D:/`의 작가 폴더에서 해당 작품을 찾습니다. 검색 범위를 줄이려면 실제 작품이 있는 작은 범위의 폴더를 지정하세요. 설정 키는 `local-import.presets`이며 로컬 작품 가져오기 도구 안의 프리셋 편집기에서 수정할 수 있습니다.

## 사용할 수 있는 변수

| 변수 | 의미 |
| --- | --- |
| `{artwork_id}` | 필수. 양의 정수 작품 ID |
| `{author_id}` | 양의 정수 작가 ID |
| `{artwork_title}` | 경로에 이미 포함된 작품 제목 |
| `{author_name}` | 경로에 이미 포함된 작가 이름 |
| `{page}` | 0부터 시작하는 페이지 번호 |
| `{extension}` | 앞의 점을 제외한 확장자 |
| `{name}` | 경로 한 구간의 다른 이름. 작품 제목으로 사용하지 않음 |

변수명은 표에 나온 소문자와 밑줄 표기와 정확히 일치해야 합니다. 인접 변수 사이에는 고정 문자를 넣어 `{artwork_id}_{name}`처럼 적으세요. `{artwork_id}{name}`는 사용할 수 없습니다. `*`는 와일드카드가 아닙니다.

## 미리보기, 다시 검색, 결과 확인

- JPG, JPEG, PNG, APNG, GIF, WebP, WebM, MP4, ZIP을 검색합니다. 파일은 가져오기 검증도 통과해야 합니다. ZIP 지원은 임의의 압축 파일을 풀어서 가져오는 기능이 아닙니다.
- 미리보기는 새 작품, 파일 추가, 이미 등록됨, 충돌, 파일 없음으로 구분합니다. 충돌을 먼저 해결하세요. 기존 등록을 강제로 덮어쓰지 않습니다.
- 최근 검색 인덱스는 메모리에 5분간 유지되며 폴더 변경을 자동으로 감시하지 않습니다. 파일을 추가, 이동, 삭제했다면 다시 검색하여 인덱스를 갱신하는 옵션을 선택한 후 미리보기를 실행하세요.
- 취소하면 현재 작품의 등록이 끝날 때까지 기다리며, 이미 등록된 작품은 유지합니다. 범위가 너무 크면 폴더나 ID 목록을 나누세요.
- 외부 파일은 읽기 전용으로 참조합니다. 앱에서 작품 등록을 삭제해도 원본 파일은 삭제하지 않습니다. 나중에 원본을 이동하거나 삭제하면 참조가 끊길 수 있으므로 데이터베이스와 외부 폴더를 함께 백업하세요.
- 경로만으로는 제목, 작가, 전체 페이지 수를 알 수 없을 때가 있습니다. 메타데이터 보완 대기는 등록 실패가 아닙니다. 이후 온라인 보완에 관한 내용은 [네트워크 접근](/ko/network-access)을 참고하세요.

## HTTP API

관리자는 `/api/local-import`로 같은 작업을 수행할 수 있습니다. 앱의 인증 및 CSRF 보호가 적용됩니다.

1. `GET /api/local-import/presets`로 저장된 프리셋을 읽습니다.
2. `POST /api/local-import/previews`에 JSON을 보내 미리보기 ID를 받습니다.
3. `GET /api/local-import/previews/{id}`에서 `phase`가 `READY`가 될 때까지 확인합니다. 상세 목록은 `/previews/{id}/items?offset=0&limit=20`에서 확인합니다.
4. `POST /api/local-import/tasks`에 `{"previewId":"반환된 미리보기 UUID"}`를 보냅니다.
5. `GET /api/local-import/tasks/{id}`로 결과를 확인합니다. 취소는 `POST /api/local-import/tasks/{id}/cancel`입니다.

저장된 모든 경로로 두 작품을 검색하는 요청 본문:

```json
{
  "templates": [],
  "artworkIds": [12345, 12346],
  "refreshIndex": false,
  "selectedFile": ""
}
```

`202`는 요청 수락을 의미하므로 결과를 계속 확인해야 합니다. 인스턴스마다 한 번에 하나의 가져오기 작업만 실행합니다. 미리보기와 인덱스는 프로세스를 다시 시작하면 사라집니다. 이 설명은 HTTP API에 관한 것이며 별도의 MCP 도구가 제공된다는 뜻은 아닙니다.

다운로더의 기록 JSON을 사용하려면 [외부 다운로드 가져오기](/ko/pixiv-batch-downloader-import)를 참고하세요.
