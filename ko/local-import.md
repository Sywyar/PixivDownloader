# 로컬 작품 가져오기와 프리셋

로컬 작품 가져오기는 파일 경로에 포함된 작품 ID를 기준으로 디스크에 이미 있는 일러스트, 만화와 움짤을 **읽기 전용 참조**로 작품 라이브러리에 일괄 등록합니다(원래 폴더와 파일은 그대로 유지되며 갤러리에서 삭제해도 원본 파일은 삭제되지 않음. 경로에서 추출할 수 없는 제목, 작가, 태그 등의 메타데이터는 가져온 뒤 [메타데이터 보충](#metadata-backfill)으로 채울 수 있음). PixivBatchDownloader에서 내보낸 기록 JSON 가져오기는 [외부 다운로드 가져오기](/ko/pixiv-batch-downloader-import)를 사용하세요.

?> 로컬 작품 가져오기는 백엔드가 실행 중일 때 작동하는 온라인 도구입니다(중지 유지 관리 모드로 들어가지 않음). Compose('도구 → 빠른 도구'에서 대화상자로 열리며 닫아도 시작된 작업은 백그라운드에서 계속 실행됨)와 Swing 모두 데스크톱 도구 페이지에서 열며, HTTP API의 경로도 백엔드가 실행되는 서버의 로컬 경로를 가리킵니다.

## 경로 템플릿 및 사용 가능한 변수

**경로 템플릿**은 경로에서 바뀌는 부분을 중괄호 `{변수}`로 표시해 프로그램이 거꾸로 작품 정보를 읽어 오게 합니다:

- 모든 템플릿에는 `{artwork_id}`(폴더 이름 또는 파일명 안)가 반드시 포함되어야 하며 절대 경로를 사용합니다(Windows에서는 `/`와 `\` 모두 지원). 템플릿은 매칭과 분석에만 쓰이며 폴더를 만들거나 파일명을 바꾸지 않습니다.
- **폴더 템플릿과 단일 파일 템플릿**: `/`로 끝나는 템플릿은 **폴더 템플릿**(해당 폴더와 하위 폴더의 지원 파일을 재귀적으로 수집), `/`로 끝나지 않는 템플릿은 **단일 파일 템플릿**(파일명과 `.{extension}`까지 작성)으로 처리됩니다.
- 변수 이름은 소문자 밑줄(`snake_case`) 표기와 정확히 일치해야 합니다. **인접한 변수 사이에는 고정 구분 문자가 있어야 하며**(`{artwork_id}_{name}`은 가능, `{artwork_id}{name}`은 불가) `*`는 와일드카드가 아닙니다.

| 기존 파일의 실제 경로 | 입력할 경로 템플릿 | 분석 결과 |
| --- | --- | --- |
| `D:/xxx/12345/pic.png` | `D:/xxx/{artwork_id}/` | 작품 ID `12345`, 해당 폴더와 하위 폴더의 지원 파일 수집 |
| `D:/xxx/12345_xxx.png` | `D:/xxx/{artwork_id}_xxx.{extension}` | 작품 ID `12345`, 확장자 `png`(`_xxx`는 고정 문자) |
| `D:/678/12345/pic.png` | `D:/{author_id}/{artwork_id}/` | 작가 ID `678`, 작품 ID `12345` |
| `D:/xxx/12345_p0.jpg` | `D:/xxx/{artwork_id}_p{page}.{extension}` | 작품 ID `12345`, `0`페이지 |

| 변수 | 의미 |
| --- | --- |
| `{artwork_id}` | 필수, 양의 정수 작품 ID |
| `{author_id}` | 양의 정수 작가 ID |
| `{artwork_title}` | 경로에 포함된 작품 제목 |
| `{author_name}` | 경로에 포함된 작가 이름 |
| `{page}` | 페이지 번호(`0`부터 시작) |
| `{extension}` | 파일 확장자(앞의 `.` 제외) |
| `{name}` | 한 경로 구간 안의 기타 이름(작품 제목으로 저장하지 않음) |

## 사용 순서

대화상자의 '이번 가져오기 옵션'(임시 경로 템플릿, 작품 ID, 특정 파일)은 기본적으로 접혀 있습니다. 프리셋을 저장해 두었다면 세 입력란을 모두 비운 채 바로 '스캔 및 미리보기'를 누를 수 있으며, 프리셋이 없고 임시 템플릿도 비어 있을 때 스캔을 누르면 옵션 영역이 펼쳐지면서 템플릿 입력란이 빨간색으로 표시됩니다.

### 방법 1: 일회성 가져오기를 위해 임시 템플릿 직접 입력

1. 데스크톱 '도구 → 로컬 작품 가져오기'를 열고 '이번 가져오기 옵션'을 펼칩니다.
2. '임시 경로 템플릿'에 절대 경로 템플릿을 한 줄에 하나씩 입력합니다(예: `D:/xxx/{artwork_id}/`. 임시 템플릿을 입력하면 임시 템플릿만 사용하며 설정 파일에는 저장하지 않음).
3. **작품 ID(선택 사항)**: 작품 하나는 `12345`, 여러 작품은 줄바꿈·공백·쉼표로 구분해 입력합니다. 비워 두면 일치하는 모든 작품을 스캔합니다.
4. **특정 파일(선택 사항)**: 파일 하나만 등록할 때 경로를 입력합니다(해당 파일을 분석할 수 있는 템플릿도 함께 필요).
5. '스캔 및 미리보기'를 누르고 작품 ID, 경로와 상태를 확인한 뒤 '가져오기 시작'을 누릅니다.

### 방법 2: 로컬 가져오기 프리셋 저장(자주 가져오는 폴더용)

**로컬 가져오기 프리셋**(설정 키 `local-import.presets`)은 경로 템플릿 목록을 저장하고 스캔 시 저장된 모든 경로를 자동으로 사용합니다:

1. '도구 → 로컬 작품 가져오기'를 열고 대화상자 안의 '로컬 가져오기 프리셋'을 누릅니다.
2. '경로 추가'를 눌러 `D:/{author_id}/{artwork_id}/` 같은 절대 경로 템플릿을 한 줄에 하나씩 입력합니다(두 번 클릭해 편집하거나 행 삭제 가능. 스캔 범위를 줄이도록 실제 작품이 있는 하위 폴더를 지정하세요).
3. '프리셋 저장'을 누릅니다(재시작 없이 다음 스캔부터 바로 적용되며 취소하면 저장된 경로가 바뀌지 않음).
4. 가져오기 대화상자로 돌아와 세 입력란을 모두 비운 채 스캔하면 저장된 모든 경로를 스캔합니다. '작품 ID'에 `12345`를 입력하면 작가 ID를 몰라도 `D:/` 아래 각 작가 폴더에서 해당 작품을 찾습니다.

## 미리보기 상태, 캐시 및 집계 방식

- **지원 형식**: `JPG`, `JPEG`, `PNG`, `APNG`, `GIF`, `WebP`, `WebM`, `MP4`, `ZIP`(파일 헤더 검증을 통과해야 하며 ZIP은 움짤 프레임 패키지용으로만 처리되고 일반 압축 파일처럼 압축을 풀어 가져오지 않음).
- **스캔 색인 캐시**: 최근 디렉터리 스캔 색인은 메모리에 5분 동안 유지되며 디스크 변경을 자동 감시하지 않습니다. 파일을 추가·이동·삭제한 뒤에는 '디렉터리를 다시 스캔하여 색인 새로 고침'을 선택한 후 미리 보세요.
- **취소 및 백업**: 취소하면 현재 등록 중인 작품 처리가 끝날 때까지 기다린 뒤 중단하고 이미 등록된 작품은 유지합니다. 외부 파일은 읽기 전용으로 참조하므로 원본 파일을 이동하거나 삭제하면 참조가 깨질 수 있습니다. 백업할 때 데이터베이스와 외부 폴더를 함께 백업하세요.

| 미리보기 결과 | 의미 | 실행 시 집계 항목(작품 단위 집계) |
| --- | --- | --- |
| `NEW` | 새 작품 등록 | 기록 성공 시 `imported`, 실행 시 변경 없으면 `skipped`, 오류 시 `failed` |
| `SUPPLEMENT` | 이미 가져온 작품에 외부 파일이나 페이지 추가 | 기록 성공 시 `imported`, 실행 시 변경 없으면 `skipped`, 오류 시 `failed` |
| `DUPLICATE` | 모든 파일이 이미 등록됨 | `skipped` |
| `CONFLICT` | 등록 충돌(예: 같은 페이지에 두 파일이 매칭됨. 기존 등록을 덮어쓰지 않음) | `failed` |
| `MISSING` | 일치하는 파일 없음 | `failed` |

예를 들어 작품 4개가 모두 `CONFLICT`이면 결과는 `imported: 0, skipped: 0, failed: 4`가 됩니다. 상세 원인은 미리보기 항목의 `reason`이나 작업의 `problems`에서 확인할 수 있습니다.

## HTTP API

관리자나 `core:local-import.*` 권한이 있는 프로그램 키는 `/api/local-import`로 같은 절차를 실행할 수 있습니다(인스턴스당 동시에 하나의 가져오기 작업만 실행되며 미리보기와 색인은 프로세스 재시작 후 유지되지 않음):

1. `GET /api/local-import/presets`: 저장된 프리셋을 읽습니다.
2. `POST /api/local-import/previews`: 스캔 요청을 제출합니다(`202`와 미리보기 ID 반환. `templates`를 빈 배열로 보내면 저장된 모든 프리셋 사용):

   ```json
   {
     "templates": [],
     "artworkIds": [12345, 12346],
     "refreshIndex": false,
     "selectedFile": ""
   }
   ```

3. `GET /api/local-import/previews/{id}`: `phase`가 `READY`가 될 때까지 폴링하고 `GET /api/local-import/previews/{id}/items?offset=0&limit=20`으로 상세 항목을 확인합니다.
4. `POST /api/local-import/tasks`: `{"previewId": "<미리보기 UUID>"}`를 제출해 가져오기를 시작합니다.
5. `GET /api/local-import/tasks/{id}`: 결과를 조회합니다(스캔 또는 작업 취소는 `POST /api/local-import/previews/{id}/cancel` 또는 `POST /api/local-import/tasks/{id}/cancel`).

가져온 일러스트의 원본 파일은 `GET /api/downloaded/rawfile/{artworkId}/{page}`로 페이지별(첫 페이지는 `0`)로 읽을 수 있습니다(등록 기록의 `folder`는 템플릿의 고정 접두사일 수 있으며 각 페이지가 서로 다른 폴더에 있을 수도 있음).

## 가져온 작품의 메타데이터 보충 :id=metadata-backfill

`{artwork_id}`만으로 가져오면 작품은 즉시 갤러리 개수에 포함되지만 제목, 작가, 태그와 시리즈는 비어 있습니다. 제목, 태그나 시리즈로 검색하려면 데스크톱 '도구 → 데이터 보완'을 실행하거나(시작 시 보완을 켜 두면 다음 시작 때도 후보 확인), HTTP API로 가져온 작품 ID를 지정해 보완을 실행하세요(`12345`를 실제 작품 ID로 치환. `artworkIds`를 생략하면 전체 일러스트와 소설에서 `limit`만큼 후보 선택):

1. **후보 수 확인**(`core:backfill.read` 필요): `POST /api/tools/backfill/candidates`에 `{"artworkIds": [12345]}` 전송.
2. **사전 시뮬레이션**(`core:backfill.execute` 필요): `POST /api/tools/backfill/tasks`에 `{"artworkIds": [12345], "dryRun": true}`를 보내고 `202` 응답의 `Location`을 끝날 때까지 폴링.
3. **실제 보완 실행**(`core:backfill.execute` 필요): `POST /api/tools/backfill/tasks`에 `{"artworkIds": [12345], "dryRun": false}`를 보내고 마찬가지로 `Location`을 끝날 때까지 폴링.

보완은 등록된 로컬 메타데이터를 먼저 확인하고 부족한 항목만 Pixiv에 조회합니다(자세한 내용은 [네트워크 접근 및 외부 서비스](/ko/network-access) 참고). 한 번에 하나의 보완 작업만 실행되며 완료 기록은 원래 `Location`에서 1시간 동안(최대 64개) 조회할 수 있습니다. 만료되거나 밀려나거나 서비스가 재시작된 뒤 ID로 조회하면 `404`를 반환합니다.
