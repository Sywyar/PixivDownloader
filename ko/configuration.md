# 설정 참고

## 호스트 설정

### 서비스, 디버그 및 다운로드

`server.port`, 바인드 주소, GUI/CLI 모드, 디버그 로깅, 다운로드 루트, 동시 다운로드 수를 설정합니다. 운영 환경에서는 필요한 주소에만 바인드하고 다운로드 루트의 권한을 제한하세요.

### 이미지와 Ugoira 저장

데스크톱의 설정 → 다운로드에서 기본 형식, 품질, WebP 무손실, 최대 변 길이를 선택하고 저장한 뒤 백엔드를 재시작합니다. 형식 드롭다운은 여러 항목을 선택할 수 있으며 최소 하나는 남겨야 합니다.

- 이미지: 원본 형식(기본), PNG, JPG, WebP. 원본 형식을 해제할 수 있습니다. 선택한 출력이 모두 성공해야 원본을 삭제하며, 실패하거나 취소하면 보존합니다. 원본과 같은 형식은 기존 파일을 재사용합니다.
- Ugoira: WebP(기본), GIF, APNG, MP4, 원본 ZIP. MP4에는 현재 FFmpeg의 H.264 인코더가 필요합니다. ZIP을 저장하면 오프라인 변환에 필요한 프레임 시간 파일도 보존합니다.
- 품질 기본값은 90(1–100), WebP 무손실은 기본 해제, 최대 변은 기본 0(크기 유지) 또는 1–16,383입니다. 새로 인코딩하는 사본에만 적용하며 재사용하는 원본은 다시 인코딩하지 않습니다.

두 Web 다운로드 화면에서도 이번 다운로드와 새 예약의 형식을 선택할 수 있습니다. 기본값은 `config/plugins/download-workbench.properties`에 저장합니다. 키는 `download-workbench.media.image-formats`, `ugoira-formats`, `quality`, `webp-lossless`, `maximum-edge`이며 모두 같은 접두사를 사용합니다.

FFmpeg 공유 동시 실행 수는 기본 2이고 데스크톱 다운로드 설정에서 1–8로 바꿀 수 있습니다. 저장 후 백엔드를 재시작해야 적용됩니다. 호스트 키는 `config/config.yaml`의 `ffmpeg.max-concurrent`이며 변환과 미디어 분석이 한도를 공유합니다.

기존 작품은 Compose 데스크톱의 “도구 → FFmpeg 및 도구 → 다운로드한 미디어 처리”에서 대상 형식을 선택하고 누락 항목을 찾습니다. 작품 ID는 입력하지 않아도 됩니다. 결과를 확인한 뒤 직접 시작하면 누락된 형식과 썸네일만 추가하고 기존 파일은 보존합니다. 뒤로 가도 작업은 계속됩니다. Swing도 도구 페이지에서 같은 검색과 처리를 제공합니다. Ugoira 추가 변환에는 보관된 ZIP과 프레임 타이밍이 필요합니다. FFmpeg 관리에서 실제 코덱 지원을 확인할 수 있으며 MP4에는 H.264 인코더가 필요합니다.

한 번에 해당 작품 500개, 후보 파일 10,000개까지 처리하며 작업은 하나씩 실행합니다. 한도에 도달하면 처리 후 다시 검색합니다. 검색만으로 파일을 생성하지 않습니다. 선택을 변경하면 다시 검색해야 하며 다운로드 설정 변경만으로 기존 작품 처리를 시작하지 않습니다.

Ugoira ZIP은 100 MiB, 500개 항목/프레임, 항목별 압축 해제 32 MiB, 전체 200 MiB, 프레임별 25,000,000픽셀까지 허용합니다. 변환 프로세스는 최대 10분, 출력 100 MiB입니다. 한도를 넘으면 임시 파일을 정리하되 저장 대상으로 선택한 ZIP과 프레임 시간은 보존합니다.

갤러리는 보존된 원본, WebP, PNG, JPG 순서로 실제 파일을 선택하며 MP4는 동영상 플레이어로 표시합니다.

### 플러그인 마켓

공식 저장소 URL, 사용자 지정 저장소, 프록시, 최대 응답 크기와 타임아웃, 서명 신뢰 루트를 설정합니다. 서명 검증을 우회하는 설정은 제공되지 않습니다.

### 외부 프록시

Pixiv, 업데이트, FFmpeg 및 일부 온라인 TTS 요청에 사용할 HTTP 프록시를 설정합니다. 호스트, 포트, 인증 및 적용 범위는 배포 환경에 맞게 지정하세요. 브라우저의 직접 연결과 SMTP는 별도 경로일 수 있습니다.

### 다중 모드 할당량과 속도 제한

다중 사용자 모드에서는 사용자별 요청 제한과 전역 동시성을 설정할 수 있습니다. 프록시 뒤에 배포할 때는 신뢰할 수 있는 프록시 CIDR만 지정해야 실제 클라이언트 주소가 올바르게 계산됩니다.

### 유지보수 시간

예약 작업을 실행하지 않을 시간대를 지정할 수 있습니다. 이미 실행 중인 작업의 중단 여부와 알림은 각 작업 정책을 따릅니다.

### HTTPS와 역방향 프록시

HTTPS 종료를 프록시에서 수행하는 경우 `Forwarded` 또는 `X-Forwarded-*` 헤더를 신뢰할 프록시만 설정하세요. 공개 클라이언트 네트워크를 신뢰 목록에 넣지 마세요.

### 언어와 데스크톱 UI

`app.language`에 `ko-KR`, `en-US`, `zh-CN`, `zh-Hant`, `ja-JP` 같은 BCP 47 태그를 지정할 수 있습니다. 비워 두면 시스템 언어를 따르며, 현재 UI 언어와 콘텐츠 번역 언어는 서로 독립적입니다.

`app.gui-provider`의 기본값은 `gui-swing`입니다. GUI의 선택지는 현재 활성화된 `DesktopUiProvider` 플러그인이 동적으로 제공하며 호스트에 내장된 목록이 아닙니다. 공식 `gui-swing`은 기본 설치이고 `gui-compose`는 필요할 때 설치합니다. provider 전환에는 전체 애플리케이션 재시작이 필요하며, 설정한 provider를 사용할 수 없으면 유일한 기본 provider로만 fallback합니다.

### 업데이트 및 예약 호스트

온라인 업데이트 채널, 확인 주기, 예약 작업의 호스트 주소와 기본 프록시를 설정합니다. 변경 후 즉시 적용되는지 여부는 설정 항목과 플러그인의 수명 주기 정책에 따라 다릅니다.

### 플러그인 활성화 상태

`plugins.<plugin-id>.enabled`로 선택적 플러그인을 활성화하거나 비활성화합니다. 필수 플러그인은 비활성화할 수 없으며, 일부 변경은 백엔드 또는 소프트웨어 재시작이 필요합니다.

## 플러그인 업무 설정

각 플러그인은 자체 설정 네임스페이스를 소유합니다. 플러그인의 `GuiConfigContribution`은 field, group, layout, action, preset을 포함한 해당 설정 section 전체의 기준입니다. 애플리케이션 셸이 core 설정과 하나의 toolkit-neutral desktop document로 병합하고 저장하며 Swing / Compose는 같은 문서를 렌더링할 뿐 별도 플러그인 페이지를 유지하지 않습니다.

## 플러그인 인증 정보

SMTP, 푸시, LLM 및 기타 자격 증명은 해당 플러그인의 전용 설정에 저장합니다. 로그, URL, 원격 콘텐츠 및 지원 요청에 비밀 값을 포함하지 마세요.

## 현재 계약 확인

설정 변경 후 상태 페이지와 로그에서 실제 적용된 값, 플러그인 상태, 프록시 적용 범위 및 재시작 필요 여부를 확인하세요. 저장 성공만으로 런타임 적용을 가정하지 마세요.
