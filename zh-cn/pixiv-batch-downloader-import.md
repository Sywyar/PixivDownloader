# PixivBatchDownloader 导入支持

官方 `pixiv-batch-downloader-import` 插件配合油猴脚本，将 PixivBatchDownloader 此后下载完成的插画、漫画、动图和小说自动加入本机画廊。首次使用配置一次下载目录，之后无需手动导入。源文件不复制、不移动；删除画廊记录也保留原文件。

## 使用

普通发行包不预装此插件，离线全量包包含它。

1. 在本程序的插件市场安装官方 **PixivBatchDownloader 导入支持**，然后完全退出并重新启动本程序。已安装并启用该插件时可跳过此步。
2. 在浏览器中安装并启用 PixivBatchDownloader 和 Tampermonkey，允许 Tampermonkey 在 Pixiv 网站运行。Chrome 138+ 还需在「扩展程序 → Tampermonkey → 详情」中开启“允许用户脚本”；其它版本按 [Tampermonkey 的权限说明](https://www.tampermonkey.net/faq.php?ext=dhdg&q=Q209)操作。
3. 可先在本程序桌面设置的“PixivBatchDownloader 导入支持”中选择浏览器下载根目录，也可等首次下载完成后确认候选目录。文件可保存在该目录的子目录中。手动编辑配置时，在 `config/plugins/pixiv-batch-downloader-import.properties` 设置绝对路径 `pixiv-batch-downloader-import.source-root`；Windows 下使用正斜杠，例如 `D:/Downloads`。保存后立即生效，无需重启后端。
4. 先在浏览器登录本机服务，再打开[导入脚本安装地址](http://localhost:6999/api/scripts/pixiv-batch-downloader-import.user.js)，在 Tampermonkey 中确认并启用；端口不同请替换地址。下载工作台启用时，也可从「更多 → 油猴脚本」安装。本脚本及安装 API 不依赖下载工作台。
5. 刷新已打开的 Pixiv 页面。脚本自动使用安装来源的本机主机、协议和端口；已手动保存的地址优先，可在油猴菜单“设置本机服务地址”中修改。直接安装源文件时，默认连接 `http://localhost:6999`。
6. 保持本机后端运行，正常使用 PixivBatchDownloader 抓取和下载。整部作品的所有文件下载完成后会自动加入对应画廊，无需复制或粘贴 JSON。

浏览器与本程序必须在同一台机器上，本程序使用单人模式。脚本只连接本机服务，并使用油猴存储保存待处理信息；不需要开启“允许访问文件网址”。安装前的历史下载不会自动扫描。

未配置目录时，首次完整成功记录中的绝对路径会触发桌面确认：程序请求窗口焦点并打开设置中的目录弹窗，显示候选目录，允许改选。请选择能包含后续下载文件的根目录，点击“确认并保存”后才写入配置并自动重试导入。取消不会保存，也不会因同一记录重试而反复弹窗；之后可在设置中手动选择。相对路径、无 GUI 运行或不安全的候选目录需要手动配置。候选展示、确认保存和实际文件导入都会校验路径，符号链接和 junction 不会被当作普通目录接受。

安装或启停脚本后，确认 Tampermonkey 中的启用状态，并刷新下载页和 Pixiv 页面。下载完成却未出现在画廊时，先在 Pixiv 页面的油猴菜单查看“自动导入状态”：`SOURCE_ROOT_REQUIRED` 表示需要确认候选目录或在设置中选择下载目录；`SERVER_UNAVAILABLE` 表示需检查后端是否运行、服务地址是否正确。

服务暂时不可用时，待登记信息保存在油猴存储中；Pixiv 页面打开后自动重试，刷新页面不会丢失已保存的待登记记录。“自动导入状态”菜单显示待处理、未完成和需要检查的数量。未知元数据、缺页、跳过下载或冲突路径不会被记为完整作品；需要重新抓取取得完整信息。脚本不扫描旧下载目录，也不修改 PixivBatchDownloader 的状态。

## 文件与数据

桌面首页的数据概览提供“已导入的作品”，统计此插件成功导入的唯一作品。多页漫画算一部；插画与小说的相同 ID 分别计数。重启后保留计数，删除画廊记录不会减少；已有作品、失败和跳过不计数，启用统计前已登记的作品不会追补计数。统计保存在插件自己的 `data/pixiv-batch-downloader-import/plugin.db`，备份时需一起保留。

统计写入暂时失败时显示不可用，脚本重试会先补写计数再确认成功。作品登记与统计分别提交；若进程在两次提交之间被强制终止，该次导入可能漏计。

- 浏览器实际保存路径必须位于配置的根目录内；允许任意文件名和子目录。宿主拒绝链接、junction、越界路径、缺失文件和不受支持的文件头。
- 图片支持 JPEG、PNG、WebP、GIF；动图支持 WebP、GIF、APNG、WebM、MP4、ZIP；小说支持 TXT、EPUB，正文来自同次抓取的元数据。ZIP 缩略图只读首个图片条目，源文件仍是 ZIP。
- 小说封面、附件和原始发布时间尚未导入；当前小说页会将登记时间显示为上传时间。
- 数据库保存逐页真实路径和作品元数据，原文件保持不变。媒体维护跳过外部只读作品。移动原文件后，需要修复文件位置；应用不会猜测新路径。
- 已有记录（包括软删除）不覆盖、不重复登记。小说能力不可用时保留待处理信息，不返回成功。
- 单页文件最多 1 GiB，单作品最多 8 GiB、1000 页。浏览器当前元数据最多 1000 部作品、8 MiB；待处理队列最多 1000 部作品、5000 个文件、8 MiB。队列满时提示并停止接纳新记录。
- HTTP 请求最多 12 MiB，JSON 深度 20，小说正文最多 300 万字符。客户端逐项发送，失败间隔逐步增加到 60 秒；令牌单次使用、有效一分钟。连接地址仅限 loopback，不发送 Pixiv Cookie 或管理员密码。

事件对应 [PixivBatchDownloader 的固定源码](https://github.com/xuejianxianzun/PixivBatchDownloader/tree/e3bbdfdd2fb452cc9073450b8aa1ad065f982b64)。这些是上游内部事件；元数据必须先于同批下载成功事件到达。真实扩展事件兼容性取决于浏览器和油猴管理器。

## 导入历史记录

安装并启用插件后，启动后端，在 Swing 或 Compose 的「工具」中打开「PixivBatchDownloader 历史导入」。此入口不依赖配套油猴脚本。

1. 在 PixivBatchDownloader 中导出下载记录。选择导出的 JSON；如果导出生成了多份分片，将这些 JSON 放入一个独立目录并选择该目录，目录中不要混入其它 JSON。
2. 选择原文件根目录。例如记录中的 `n` 是 `作者/123_p0.jpg`，文件实际位于 `D:/Downloads/作者/123_p0.jpg`，根目录就应选择 `D:/Downloads`。此次选择不会改写自动采集设置。
3. 点击「检查并预览」。此时只检查本地记录、文件和已有作品，不请求 Pixiv，也不登记作品。界面展示总数和最多 100 个样本；多页及重复记录按作品合并，包括同目录内不同分片的页面。
4. 需要登录的作品可填写本次使用的 Pixiv Cookie，再点击「开始导入」。插件逐个获取元数据，核验完整页数后通过已有文件导入服务登记。Cookie 不保存到配置、临时文件或结果中。
5. 查看成功、跳过和失败计数。取消会等待当前操作退出，已登记作品保留；关闭界面不会取消。进程重启不会续跑，可重新预览同一份记录，已有作品（含软删除记录）会跳过。

登录失效、访问被拒、限流、服务端错误或网络传输失败会停止剩余请求，不会自动重试。处理原因后，可重新预览并启动，已登记的作品会跳过。

记录没有完整元数据，历史中的日期字段也不代表下载日期。缺文件、缺页、路径冲突、作品已删除或无法取得完整元数据时不会凭空创建已下载记录。小说导入需要启用小说插件。成功登记的作品可再使用现有回填工具补充其支持的字段；回填不能代替首次登记，也不能恢复缺失原文件。

单个 JSON 最多 512 MiB（536870912 字节），一次最多 64 个 JSON、合计 1 GiB（1073741824 字节）。目录只读取当前层的 `.json` 文件。插件在 `data/pixiv-batch-downloader-import/history-import/` 临时整理记录，最多保留一份预览或一个执行任务；替换预览、执行结束及正常关闭会清理。强制终止可能留下暂存目录，可在程序完全退出后删除；暂存不用于恢复任务。单批过度集中的作品也会触发资源保护，检查失败时不会部分导入。

此入口采用本页相同的文件格式和只读引用规则。文件名与内容是否确实对应原作品仍取决于导出记录及原文件；程序不会根据图片内容猜测作品身份。成功导入计入插件累计统计；每次最多展示前 100 项执行失败。

## 从油猴导入历史记录

1. 保持本机后端运行，在插件设置中保存“外部下载目录”，指向原文件所在的根目录。安装或更新配套脚本后刷新 Pixiv，并登录能访问这些作品的 Pixiv 账号。
2. 在使用 PixivBatchDownloader 的同一浏览器、同一用户配置中打开原来的 Pixiv 网站。暂停外部下载，在 Tampermonkey 菜单选择“读取浏览器下载历史”，点击“读取并检查”，等待本地预览。无需导出或选择历史文件。
3. 核对待导入、已存在及缺失或冲突数量，点击“开始导入”。浏览器逐项获取作品元数据，本机核验文件后登记。Pixiv Cookie 留在浏览器，不发送给本机服务。

检查明细最多显示 100 部作品及其判定结果。“待导入”为 0 时，检查即结束，“开始导入”保持禁用，无需继续等待。缺失或冲突并不一定表示文件被移动：请核对配置根目录拼接历史记录中的相对路径 `n` 后是否对应实际文件，并检查文件名与页记录是否完整。会话释放后可再次点击“读取并检查”；释放失败时会提示结果尚未确认。

脚本只读访问当前 Pixiv 网站的下载历史库，分批传给本机，单次合计最多 1 GiB。读取期间不要清空或修改历史；分批扫描不提供并发修改时的完整快照。它不读取或上传原作品文件，也不创建、升级或改写历史库。浏览器配置或网站来源不同、记录已被清除时，无法读取原来的历史。原文件、重复作品及回填的规则与桌面导入相同。

导入期间保持此页打开。取消、离页或切换服务地址会请求停止，已登记作品保留；再次操作会跳过已有记录。历史任务不保存到油猴待处理队列，刷新后不自动续跑。通信失败时结果可能尚未确认，请先检查本机服务；如果创建会话的回执丢失，需等待约 15 分钟的空闲清理及当前操作退出后再试。上传副本和候选清单位于插件的 `data/pixiv-batch-downloader-import/browser-history/`，正常结束或空闲过期后清理，强制退出后的残留可在完全停机时删除。
