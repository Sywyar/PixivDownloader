# 计划任务

计划任务在后端运行期间按固定周期或 Cron 时间自动**发现并下载**新作品。任务创建时会保存来源、筛选条件和下载设置的快照；后续修改下载页面设置不会改变已有任务。关闭浏览器不影响执行，停止后端则不会运行。

调度器与管理 API 由应用宿主提供。停用 `download-workbench` 会撤回下载页面、Pixiv 来源与插画执行器，依赖这些能力的任务会保留数据与进度并挂起，由其他插件完整支持的任务继续运行；待所需能力恢复后，调度器会自动复核并恢复因能力缺席挂起的任务。手动暂停、凭据失效和策略挂起仍需显式处理。

## 前提条件

1. 已使用管理员账号登录（访客不可用）。
2. 后端保持运行，且 `schedule.enabled` 总开关已启用。
3. 账号私有来源（收藏、我的作品、关注新作、珍藏集）及 R-18 等受限内容必须为任务绑定含有效 `PHPSESSID` 的 Cookie；缺少有效 Cookie 时私有来源会挂起，不会匿名空跑。

## 创建第一个计划任务

计划任务通过将下载页当前配置保存为快照来创建（新旧两版下载页通用）。以下以「定期跟踪画师新作」为例：

1. 打开下载页，切换到「User 模式」，输入画师主页链接或数字 ID（如 `https://www.pixiv.net/users/123456`，请替换为实际画师 ID）。
2. 展开「下载设置」，按需配置：
   - **文件名模板**：默认 `{artwork_id}_p{page}`。
   - **收藏夹**、**最大并发数**、**作品间隔**（毫秒，如 `1000`；间隔不能保证避免上游限制）。
   - **允许已删除的作品被重新下载**：画廊删除的作品保留[删除标记](/zh-cn/gallery#删除作品)，默认跳过；勾选后每轮自动重新下载（该项随快照保存，旧版本任务升级后默认补为未勾选）。
3. 展开「附加筛选」，按需设置内容分级、排除 AI 或标签条件。
4. 滚动到页面底部「存为计划任务」卡片：
   - 填写**任务名称**；
   - 选择**触发方式**：固定周期（如每 `60` 分钟）或 6 位 Cron 表达式（如每天 03:00 填 `0 0 3 * * *`）；
   - 按需设置[首次抓取上限](#首次抓取上限)与[指定单独的 代理/cookie](#指定单独的-代理cookie)；
   - 点击「创建任务」。
5. 切换到「计划任务」列表查看快照，先点一次「立即运行」，核对队列中的成功、跳过和失败原因，再确认下次触发时间。若任务已创建但代理或 Cookie 保存失败，直接在该任务上继续配置，不要重复创建。

## Cron 表达式格式

使用 Spring 6 位 Cron 格式（首位为「秒」）：

```text
秒  分  时  日  月  周
0   0   3   *   *   *   每天 03:00:00
0   30  8   *   *   1   每周一 08:30:00
0   0   */6 *   *   *   每 6 小时
0   0   9   1   *   *   每月 1 日 09:00:00
```

| 字段 | 范围 | 常用符号 |
| --- | --- | --- |
| 秒 / 分 | `0–59` | `*` 每秒/每分，`/n` 每隔 n 秒/分 |
| 时 | `0–23` | `*` 每小时，`/n` 每隔 n 小时 |
| 日 | `1–31` | `*` 每天 |
| 月 | `1–12` | `*` 每月 |
| 周 | `0–7` | `0` 或 `7` 表示周日，`*` 每天 |

## 来源类型的工作方式

| 来源类型 | 执行方式 |
| --- | --- |
| 画师新作（User 模式） / 我的作品 | 首轮抓取符合条件的未下载作品；后续轮次使用**水位线增量**，只扫描到上轮已处理的最新作品为止 |
| 画师约稿作品（User「约稿」/ 快捷获取「我的约稿」） | 每轮列出已完成并公开的约稿成品，按普通插画链路下载并跳过已下载；因次序不保证单调，不使用水位线 |
| 搜索关键词（Search 模式） | 按所选页数抓取；「最新」排序且结束页设为 `-1` 时同样使用水位线增量 |
| 漫画 / 小说系列（系列模式） | 每轮检查系列章节列表，跳过已下载章节，补齐新章节 |
| 我的收藏 / 关注新作 / 珍藏集 | 在[快捷获取](/zh-cn/quick-access)中展开对应来源后创建；珍藏集会同时下载插画与小说。编辑任务时来源只读，更换来源需删除后重建 |

## 首次抓取上限

针对历史作品较多的来源，可设置「首次抓取上限」（`0` 表示不限制数量）：

- **首轮封顶**（画师新作、已关注用户的新作、「最新排序 + 结束页 `-1`」的搜索）：仅首次运行最多抓取最新 N 件作品并推进水位线，后续轮次只追更之后发布的新作，不再补抓更早历史。
- **每轮上限**（我的收藏、珍藏集、约稿作品、非最新排序的「结束页 `-1`」搜索）：没有单调最新次序，每次运行最多接纳 N 件新作品，分多轮逐步消化存量。
- **固定页数搜索**：上限按每轮生效；`0` 只取消数量限制，不扩大所选页码范围（仅选第 1 页时不会自动向后翻页）。

!> 已下载作品跳过不消耗接纳额度，附加筛选跳过仍消耗额度。不限页或多页来源设为 `0` 时可能拉取大量历史，保存前会要求确认。

## 管理已有任务

在「计划任务」列表中，任务卡片右上角状态灯表示当前状态：

| 状态灯 | 含义 |
| --- | --- |
| 灰 | 等待下次触发、已停用或已手动暂停 |
| 绿 | 正在运行或上次执行成功 |
| 黄 | 多个任务同时到期，排队等待执行 |
| 红 | 执行失败、Cookie 失效、被中断或触发过度访问暂停（点击卡片查看原因） |

卡片支持：**立即运行**、**指定单独的 代理/cookie**、**启用 / 停用**定时触发、**手动暂停 / 恢复**、**查看快照**、**编辑**、**待重试**（查看失败待重试作品）与**删除**（不影响已下载文件）。

## 指定单独的 代理/cookie

在单人模式下创建任务时，若已保存有效 Cookie 且未勾选单独设置，任务会自动绑定当前 Cookie。也可在创建时或任务卡片的「指定单独的 代理/cookie」弹窗中独立配置：

- **设置单独的代理**：填写 `host:port`（如 `127.0.0.1:7890`），使该任务的所有 Pixiv 请求（发现、元数据、图片/小说下载、站内信过度访问检查）走该 HTTP 代理；不勾选则使用全局代理。
- **设置单独的cookie**：粘贴含 `PHPSESSID` 的 Cookie，或点击「使用当前保存的cookie」填入。已绑定 Cookie 不回显；留空保存保持不变，填入新值则替换。

取消已生效的勾选并保存会清除对应设置：代理回退全局配置；Cookie 解绑后任务转为匿名「受限模式」（无法获取 R-18，且账号私有来源无法运行）。当任务检测到 Cookie 失效时会自动暂停并标记「登录态失效」，重新获取并绑定新 Cookie 后恢复（重复提交同一份已失效 Cookie 会被拒绝）。

## 过度访问暂停与通知

当检测到 Pixiv 发送「过度访问」站内信警告时，系统会自动暂停**同一账号下的所有计划任务**。列表顶部横幅提供「无视风险，立即恢复」和「N 分钟后继续」（最少及默认 60 分钟，推荐使用冷却恢复）。

配置桌面「配置 → 邮件 / SMTP」或「配置 → 推送」（支持 Bark、钉钉、Telegram、飞书、企业微信、PushPlus、Server 酱、Webhook）后，以下事件会并行发送通知（正文绝不包含 Cookie 或密码）：

- **过度访问暂停**：列出受影响任务名称、ID、数量与警告时间。
- **登录态失效 / 连续失败熔断**：列出任务名称、ID、类型、触发规则与下次运行时间。
- **失败作品重试达上限**：额外附带该作品的 Pixiv 链接。

## 排障与相关配置

任务未运行时，依次核对后端进程、全局开关、任务启用状态和卡片上的挂起原因。更换有效 Cookie 只解除凭据挂起，不会自动解除其它原因的挂起；清除下载页上的全局 Cookie 也不会自动解绑已有任务的独立凭证。编辑任务来源或筛选条件会重置增量水位线，下一轮重新扫描并按本地下载记录判重。

| 配置项（`config/config.yaml`） | 默认值 | 说明 |
| --- | --- | --- |
| `schedule.enabled` | `true` | 计划任务总开关 |
| `schedule.tick-interval-ms` | `60000` | 检查到期任务的间隔（毫秒，修改需重启） |
| `schedule.max-tasks` | `100` | 最大可创建任务数 |
| `schedule.inbox-check-every` | `500` | 每成功下载多少件作品检查一次过度访问站内信 |
| `schedule.auth-failure-circuit-breaker` | `5` | 连续发现失败触发熔断挂起的次数 |
| `schedule.pending-max-attempts` | `5` | 失败作品最大自动重试次数 |
| `schedule.overuse-defer-default-minutes` | `60` | 过度访问暂停后的默认冷却分钟数（最小 60） |

完整配置说明见[配置参考](/zh-cn/configuration)。
