# 本地作品导入与本地导入预设

已有图片放在自己的目录里，可以通过路径中的作品 ID 将它们登记到作品库。导入保留原目录和原文件；缺少标题、作者等信息时先登记，等待后续补全。

?> 需要使用带有「本地作品导入」工具的版本，并保持后端运行。Compose 和 Swing 都从桌面工具页进入。HTTP API 中的路径也指运行后端的机器上的路径。

## 把实际路径写成路径模板

**路径模板**用花括号标出路径中会变化的部分，软件反过来从这些位置读取信息。每条模板必须含 `{artworkId}`，位置可以在目录名或文件名中。

| 已有文件的实际路径 | 填入的路径模板 | 解析结果 |
| --- | --- | --- |
| `D:/xxx/12345/pic.png` | `D:/xxx/{artworkId}/` | 作品 ID 为 12345，收集该目录及子目录中的支持文件 |
| `D:/xxx/12345_xxx.png` | `D:/xxx/{artworkId}_xxx.{extension}` | 作品 ID 为 12345，扩展名为 png；`_xxx` 是固定文字 |
| `D:/678/12345/pic.png` | `D:/{authorId}/{artworkId}/` | 作者 ID 为 678，作品 ID 为 12345 |
| `D:/xxx/12345_p0.jpg` | `D:/xxx/{artworkId}_p{page}.{extension}` | 作品 ID 为 12345，第 0 页 |

目录模板以 `/` 结尾；文件模板写到文件名和扩展名。使用绝对路径，Windows 可以使用 `/` 或 `\`。模板不会创建目录或重命名文件。

## 偶尔导入：直接填写临时模板

1. 打开桌面「工具 → 本地作品导入」。
2. 在「临时路径模板」中输入模板，每行一条，例如 `D:/xxx/{artworkId}/`。
3. 只导入一件作品时，在「作品 ID」填 `12345`；批量导入时填写多个 ID，用换行、空格或逗号分隔。留空会扫描所有匹配作品。
4. 只想登记一个文件时，填写「指定文件（可选）」。仍需提供能解析该文件的模板。
5. 点击「扫描并预览」，核对作品 ID、路径和处理结果，再点击「开始导入」。

填写了临时模板时，只使用这些模板；临时模板留空时才使用预设。工具页的输入只作用于当次操作，不会保存到配置。

## 经常导入：保存本地导入预设

**本地导入预设**是有名称、可启用或停用的路径模板。保存以后，下次通常只需填写作品 ID。

1. 在设置页找到「本地导入预设」，点击「编辑预设」。
2. 点击「添加预设」，填写名称，例如「按作者归档」，路径模板填 `D:/{authorId}/{artworkId}/`，勾选启用。
3. 确认预设编辑，返回设置页保存，并按提示重启后端。
4. 打开「本地作品导入」，将「临时路径模板」留空，在「作品 ID」填写 `12345` 或 ID 列表。
5. 可选择要使用的预设；未选择时使用全部已启用预设。扫描预览无误后开始导入。

上例会在 `D:/` 的作者目录下查找作品 `12345`，不要求你先输入作者 ID。尽量将模板指向实际存放作品的较小目录，以减少扫描范围。配置键是 `local-import.presets`，建议通过设置编辑。

## 可用变量

| 变量 | 含义 |
| --- | --- |
| `{artworkId}` | 必填，正整数作品 ID |
| `{authorId}` | 正整数作者 ID |
| `{artworkTitle}` | 路径中已有的作品标题 |
| `{authorName}` | 路径中已有的作者名称 |
| `{page}` | 页码，从 0 开始 |
| `{extension}` | 扩展名，不含前面的点 |
| `{name}` | 匹配一个路径片段中的其他名称，不作为作品标题 |

变量名不区分大小写，也忽略下划线，因此 `{artWorkId}`、`{artwork_id}` 与 `{artworkId}` 等价。相邻变量之间需要固定分隔文字，例如 `{artworkId}_{name}`；不要写成 `{artworkId}{name}`。`*` 不是通配符。

## 预览、刷新和导入结果

- 支持扫描 JPG、JPEG、PNG、APNG、GIF、WebP、WebM、MP4 和 ZIP；文件仍需通过导入校验，ZIP 不能当作任意压缩包解包导入。
- 预览会区分新增作品、补充文件、已登记、冲突和未找到文件。先处理冲突，不会强行覆盖已有登记。
- 最近的扫描索引在内存中保留 5 分钟，不会自动监视目录变化。新添、移动或删除文件后，勾选「重新扫描目录，刷新索引」再预览。
- 取消时等待当前作品登记结束，已登记作品保留。扫描范围过大时应拆分目录或 ID 列表。
- 导入的外部文件以只读方式引用；应用删除作品登记不会删除这些原文件。原文件以后移动或被删除，引用可能失效，请同时备份数据库和外部目录。
- 标题、作者和完整页数不一定能从路径推断。元数据待补全不代表本地登记失败；后续联网补全的访问见[网络访问说明](/zh-cn/network-access)。

## HTTP API

管理员可通过 `/api/local-import` 使用相同流程，沿用应用的登录鉴权与 CSRF 保护。调用顺序如下：

1. `GET /api/local-import/presets` 读取已保存预设。
2. `POST /api/local-import/previews` 提交 JSON 请求，取得预览 ID。
3. `GET /api/local-import/previews/{id}` 等待 `phase` 为 `READY`；通过 `/previews/{id}/items?offset=0&limit=20` 查看明细。
4. `POST /api/local-import/tasks` 提交 `{"previewId":"返回的预览 UUID"}`。
5. `GET /api/local-import/tasks/{id}` 查询结果；`POST /api/local-import/tasks/{id}/cancel` 取消。

使用已启用预设扫描两个作品的请求体：

```json
{
  "templates": [],
  "artworkIds": [12345, 12346],
  "presetNames": [],
  "refreshIndex": false,
  "selectedFile": ""
}
```

`202` 表示请求已接纳，需继续查询结果。同一实例同时只运行一个导入任务；预览和索引不跨进程重启保留。本页描述 HTTP 接口，不代表已经提供独立 MCP 工具。

下载器历史 JSON 的导入是另一种入口，见[导入外部下载](/zh-cn/pixiv-batch-downloader-import)。
