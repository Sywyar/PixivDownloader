# Network access and third-party services

This page describes the destinations each feature connects to, data sent, proxy routing and ways to disable access. The first part covers **runtime requests** from the installed application. Engineering requests for builds, tests, CI and community submissions are listed separately under [Network access during development, builds and releases](#network-access-during-development-builds-and-releases); normal application use does not trigger them.

?> This page lists fixed default addresses in the code and controlled ranges of dynamic addresses. Third-party services may distribute assets through DNS, CDNs, redirects or temporary download links. Administrator-configured custom URLs depend on the actual settings.

## Runtime overview and proxy routing

- **Triggers**: AI, translation, TTS, push, mail, CAPTCHA and Douyin connect only when enabled and invoked. When enabled, `notification` periodically fetches a signed announcement index in the background. With online updates and automatic checks enabled, the host checks GitHub Releases after startup is ready. Desktop and headless services backfill missing metadata for registered works in the background as needed after becoming ready.
- **Plugin market**: `plugin-catalog.enabled` and the official and community repositories are enabled by default, but application startup itself does not fetch remote manifests. Repository requests occur only when administrators check plugin updates, open/refresh the market, preview a repository, install plugins or manually refresh revocations.
- **PostHog surveys**: public parameters for the layout survey (`download-workbench`) and multi-mode survey (`multi-mode-decision-survey`) are stored in each plugin's source `posthog-config.js`. `release-activation.js` generated by ordinary source and fork builds defaults to `false`, so they do not connect to PostHog by default.
- **Outbound proxy routing**:
  - Pixiv, online updates, automatic FFmpeg downloads, official/community plugin repositories, server-side CAPTCHA verification and announcement synchronization use host or task-level proxy settings.
  - AI, translation, TTS and Douyin support feature-level or task-level direct/proxy selection; `direct-strict` custom plugin repositories always connect directly.
  - SMTP uses the `mail` plugin's own connection and optional SOCKS proxy. PostgreSQL JDBC connects directly to the target database server, without the HTTP proxy.
  - Same-origin browser APIs, Google Fonts on the introduction page, browser Web Speech API, frontend CAPTCHA widgets, PostHog and userscripts are requested directly by the browser, outside the Java backend proxy.

Host-managed plugin HTTP clients do not automatically replay requests after rate limits, service failures or connection errors. Features that retry control their own attempt counts and delays, as described in their respective sections.

## Core host and default requests

- **Same-origin authentication and internationalization**: the login page checks sessions and submits authentication through same-origin `/api/auth/check`, `/api/auth/login` and `/api/auth/invite-redeem` (return destinations accept only same-origin internal paths). Frontend pages load dictionaries through `/api/i18n/meta`, `/api/i18n/messages/{namespace}` and same-origin `i18n-static/` (10-second timeout per request; missing dictionaries retry up to 3 rounds at 1.5, 5 and 15 seconds). They do not connect to external translation services.
- **Local GUI channel**: desktop mode polls status and submits operations through `http://127.0.0.1:{random port}/api/gui/**`, carrying a backend-generated GUI token. It enforces direct local access and rejects proxies, redirects and forwarding headers. `--no-gui` does not create this port.
- **External-link confirmation**: clicking an external HTTP(S) link on an application Web page first shows a destination confirmation dialog. The browser opens it only after confirmation.

## Third-party and optional feature plugins

### `douyin` plugin (third-party, installed on demand)

Not bundled in default distributions. Access occurs only after manual installation and enabling, when a Douyin operation is performed:

- `https://www.douyin.com/aweme/v1/web/**`: retrieves user works, likes, collections, searches, music, bookmarks, account details and work details (with the user's configured Douyin cookie, UIFID extracted from it, and locally calculated `x-secsdk-web-signature`).
- HTTPS `*.douyin.com`, `*.iesdouyin.com` (such as `v.douyin.com`): resolves short links through restricted redirects.
- HTTPS `*.douyinvod.com`, `*.douyinpic.com`, `*.douyinstatic.com`, `*.amemv.com`, `*.byteimg.com`, `*.bytedance.com`, `*.bytecdn.cn`, `*.pstatp.com`, `*.snssdk.com`: downloads videos, image sets, covers and live photos.

Routing follows "task-specific proxy → source default route → host global proxy". Stop the task or disable the plugin to stop access.

### `ai` and `translation` plugins

The AI plugin uses the OpenAI-compatible protocol. Connection tests, novel translation and multi-character analysis send text, prompts, model names and API Keys to `/chat/completions` at the selected base URL (novel translation includes at most 1,000 term mapping entries). Clicking to fetch the model list in desktop settings sends GET to `/models` at the draft base URL (an anonymous request first; on 401/403, retries once with the Bearer key if one has been entered. `https://api.anthropic.com/v1` uses `anthropic-version`, `x-api-key` and `after_id` pagination according to the [Anthropic protocol](https://platform.claude.com/docs/en/api/models/list)). No request stores cookies or follows redirects.

The `translation` plugin invokes the selected engine for manual or automatic translation. AI reuses the configuration above. Youdao sends a single text to `https://openapi.youdao.com/api` and batches to `https://openapi.youdao.com/v2/api`, with text, application ID and a locally calculated v3 signature, not the application secret. LibreTranslate receives JSON with a text or text array and optional `api_key` at the administrator-configured `{libretranslate-url}/translate`. Each engine has its own `translation.<engine>.use-proxy` and `read-timeout-seconds` (defaults: proxy off, read timeout 120 seconds); the connection timeout is 30 seconds. See [Novels and reading aloud](/en/novel) for character, batch, concurrency, pacing and rate-limit retry settings. Response reads are bounded by the larger of 1 MiB and 16 bytes per actual input code point in the batch, up to 16,000,000 bytes; oversized responses are rejected. Only explicit rate limits receive bounded retries; timeouts and other errors are not replayed automatically.

With LibreTranslate selected, opening the translation dialog or reloading languages makes the `translation` plugin send GET `/languages` to the same configured service. It sends no novel text or API key and uses the proxy, timeouts and 1 MiB response limit above. Leave the dialog closed or select another engine to avoid this query. Youdao options use the bundled official language table without an extra request.

### Plugin market, FFmpeg, databases, page editor and CAPTCHA

- **Plugin market and revocation checks**:
  - The official repository reads `https://raw.githubusercontent.com/Sywyar/PixivDownloader-plugins/master/manifest.json` (`nightly-manifest.json` for nightly), on-demand history shards `history/<pluginId>-<sha256>.json`, market-document/screenshot attachments in version Releases, and plugin package URLs.
  - The community repository reads `https://raw.githubusercontent.com/Sywyar/PixivDownloader-community-plugins/master/generated/current.json`, generation-directory shards, revocation manifests, review records and signed Release assets.
  - Custom repositories read the administrator-imported `repository.json` (64 KiB limit) and its declared `manifest-v1` / `paged-v2` endpoints, `revocations.json` and `repository-update.json`.
  - Installed-plugin update checks are cached for 5 minutes (30 seconds for partial failures). Compatible older-version fallback queries read at most 10 pages per plugin within a shared 10-second budget. Disable `plugin-catalog.enabled` or the corresponding repository switch to stop.
- **Automatic FFmpeg installation**: downloading from the desktop status page or selecting the FFmpeg task in the Windows installer requests `https://github.com/Sywyar/PixivDownloader-Remote-Content/releases/download/ffmpeg-stable/ffmpeg-release.json`, `.sig` and the platform's `ffmpeg-*.zip`. The official Ed25519 signature, size and SHA-256 are verified before extraction (desktop uses the host proxy; the Windows installer prefers the current user's system HTTP/HTTPS proxy).
- **Userscript updates**: for individual scripts installed from the repository, Tampermonkey accesses `https://raw.githubusercontent.com/Sywyar/PixivDownloader/master/*.user.js`; backend-installed scripts point to that backend's `/api/scripts/*.user.js`.
- **Official PostHog survey plugin**: only when activated in an official release build (`release-activation.js` is `true`) and an administrator opens an inbox message with a valid survey or triggers the download-page layout survey does the browser directly access `https://layout-survey.sywyar.top` and `https://us.posthog.com` (sends only a derived survey-scoped anonymous identifier and answers, not the installation UUID, account, cookies or paths; disable `posthog` to stop).
- **PostgreSQL database plugin**: connects by JDBC to the administrator-configured `database.jdbc-url` (default port 5432, 10-second connection preflight timeout), sending database authentication material, business data and private database data. Connects directly to the server without the HTTP proxy. See [Configuration reference](/en/configuration#main-database-and-engine-switching).
- **Plugins without fixed external public destinations**: `gallery`, `gallery-tools`, `gui-compose`, `gui-swing`, `page-editor` (bundled local GrapesJS and CodeMirror, CDN and telemetry disabled) themselves access only same-origin APIs on the current instance and make no fixed third-party public requests.
- **`captcha` operation verification plugin**:
  - **ALTCHA (SHA-256 / PBKDF2), character CAPTCHA (Hutool), slider puzzle (Tianai)**: run entirely within the current instance and local browser, without third-party services.
  - **Cloudflare Turnstile**: after binding and publishing, the browser loads `https://challenges.cloudflare.com/turnstile/v0/api.js` and an iframe. On submission, the server sends the secret and ticket to `/turnstile/v0/siteverify` through managed HTTP (inherits the application proxy, rejects redirects and cookies).
  - **Google reCAPTCHA v2**: after binding and publishing, the browser loads `https://www.google.com/recaptcha/api.js?render=explicit` (plus `www.gstatic.com`, `recaptcha.google.com`). On submission, the server sends the secret and ticket to `https://www.google.com/recaptcha/api/siteverify` through managed HTTP. Remove the component and republish the page to stop external requests.

## Network access during development, builds and releases

The following requests occur only when developers or CI build source, resolve dependencies, test, package, sign, publish or run community submission tools. **Installed clients do not make these requests at runtime**:

| Engineering activity | Destinations and purpose |
| --- | --- |
| Maven / Gradle / sbt and npm dependency resolution | Maven Wrapper and Java modules download build tools and dependencies (such as Tink, PostgreSQL/SQLite/H2 JDBC, Hutool/Tianai/ALTCHA, Cupertino, WebP/JSON Schema/JCS and sbt-launch) from configured Maven repositories/mirrors (defaults `https://repo.maven.apache.org/maven2`, `https://repo1.maven.org/maven2`, `https://plugins.gradle.org`). Frontend checks and plugin resource builds download dependencies from npm registries configured in lockfiles (currently `https://registry.npmmirror.com`, occasionally `https://registry.npmjs.org` for Web resource maintenance) |
| Browser and database integration acceptance | Playwright browser installation downloads Chromium from `cdn.playwright.dev` / `playwright.download.prss.microsoft.com`. Explicitly running CAPTCHA acceptance with `page-editor-acceptance.mjs` accesses Cloudflare Turnstile and Google reCAPTCHA test endpoints using official public test keys. PostgreSQL container acceptance pulls Docker `postgres:17` and connects only to the isolated `PIXIV_TEST_POSTGRES_URL` database |
| Maintainer directory, licenses and local packaging scripts | Application resource builds obtain allowlisted contributor information and avatars through the GitHub API (`api.github.com/repos/Sywyar/PixivDownloader`) and `avatars.githubusercontent.com` (uses system/environment HTTP(S) proxies, 30-second timeout, automatically skipped for offline builds). License maintenance scripts read `spdx/license-list-data` as needed. `package-local.ps1` downloads and verifies `ffmpeg-stable` assets for offline packages. `package-installer-with-plugins.ps1 -PluginSource Catalog` downloads signed manifests and packages from the official plugin repository |
| CI dependency caches and acceptance artifacts | `actions/cache` and `gradle/actions/setup-gradle` use GitHub Actions cache URLs supplied by the runner to store and restore third-party Maven dependencies, Gradle dependencies, compiled build scripts, and compilation and ProGuard outputs whose inputs match. Dependency configuration changes on the main branch trigger dependency downloads on Linux and Windows. Gradle setup also contacts the official Wrapper checksum service. The SDK build uploads frozen inputs to the GitHub Actions artifact service; downstream acceptance jobs download them by artifact ID from the same run and verify SHA-256. Build Scans and dependency graphs are not uploaded |
| SDK verification, publishing and cross-repository Pages builds | `sdk-legacy-plugin.mjs` downloads pinned `gui-swing-v1.0.2` assets for binary compatibility validation. `sdk-consumer.mjs` fetches a pinned commit of `Sywyar/PixivDownloader-Plugin-Douyin.git` to validate an isolated consumer. | Main repository CI, Gate Checks, Releases and announcement renewal | GitHub Actions runs Quality Gate, distribution E2E, signed plugin publishing and `Gate Checks` (uses the GitHub API and App token to issue required checks for open PRs).
