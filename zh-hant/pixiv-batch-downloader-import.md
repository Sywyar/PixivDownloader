# PixivBatchDownloader 匯入支援

官方 `pixiv-batch-downloader-import` 外掛搭配使用者腳本，將 PixivBatchDownloader 此後下載完成的插畫、漫畫、動圖和小說自動加入本機畫廊。首次使用設定一次下載目錄，之後不必手動匯入。來源檔案不會被複製或移動；刪除畫廊紀錄也會保留原始檔案。

瀏覽器與本程式必須在同一台機器上，本程式使用單人模式。腳本只連線至本機服務，並透過腳本管理器的儲存空間保留待處理資訊；不必開啟「允許存取檔案網址」。安裝前的歷史下載不會被自動掃描。

## 使用方式

一般發行套件不預裝此外掛，離線完整套件包含它。

1. 在本程式的外掛市場安裝官方「PixivBatchDownloader 匯入支援」，然後完全結束並重新啟動程式。已安裝且啟用時，可略過此步。
2. 在瀏覽器安裝並啟用 PixivBatchDownloader 和 Tampermonkey，允許 Tampermonkey 在 Pixiv 網站執行。Chrome 138+ 還需在「擴充功能 → Tampermonkey → 詳細資料」開啟「允許使用者腳本」；其他版本請依 [Tampermonkey 權限說明](https://www.tampermonkey.net/faq.php?ext=dhdg&q=Q209)操作。
3. 可先在桌面設定的「PixivBatchDownloader 匯入支援」選擇瀏覽器下載根目錄，也可在首次下載完成後確認候選目錄。檔案可以位於其子目錄。手動編輯時，在 `config/plugins/pixiv-batch-downloader-import.properties` 設定絕對路徑 `pixiv-batch-downloader-import.source-root`；Windows 使用正斜線，例如 `D:/Downloads`。儲存後立即生效，不必重新啟動後端。
4. 先在瀏覽器登入本機服務，再開啟[匯入腳本安裝網址](http://localhost:6999/api/scripts/pixiv-batch-downloader-import.user.js)，在 Tampermonkey 確認安裝並啟用；連接埠不同時請修改網址。工作台啟用時也可從「更多 → 使用者腳本」安裝。本腳本與安裝 API 不依賴下載工作台。
5. 重新整理已開啟的 Pixiv 頁面。腳本自動使用安裝來源的本機主機、協定及連接埠；已手動儲存的位址優先，可在腳本選單「設定本機服務位址」中修改。直接安裝原始檔時，預設連線至 `http://localhost:6999`。
6. 保持本機後端執行，正常使用 PixivBatchDownloader 取得資料並下載。整部作品的所有檔案下載完成後，會自動加入對應畫廊，不必複製或貼上 JSON。

尚未設定目錄時，首次完整成功紀錄中的絕對路徑會觸發桌面確認：程式要求視窗焦點並開啟設定中的目錄對話框，顯示可更換的候選目錄。請選擇能包含後續下載檔案的根目錄；只有點選「確認並儲存」才會寫入設定並自動重試匯入。取消不會儲存，也不會因同一筆紀錄重試而反覆彈出；之後可在設定中手動選擇。相對路徑、無 GUI 執行或不安全的候選目錄需要手動設定。候選顯示、確認儲存和實際匯入都會檢查路徑，符號連結和 junction 不會被當成一般目錄接受。

## 下載完成後未出現在畫廊

安裝或啟停腳本後，確認 Tampermonkey 中的啟用狀態，並重新整理下載頁和 Pixiv 頁面。下載完成卻未出現在畫廊時，先在 Pixiv 頁面的腳本選單查看「自動匯入狀態」：`SOURCE_ROOT_REQUIRED` 表示需要確認候選目錄或在設定中選擇下載目錄；`SERVER_UNAVAILABLE` 表示應檢查後端是否執行、服務位址是否正確。

服務暫時無法使用時，待登記資訊保留在腳本儲存空間；Pixiv 頁面開啟後會自動重試，重新整理不會遺失已儲存的待登記紀錄。「自動匯入狀態」選單顯示待處理、未完成和需要檢查的數量。未知中繼資料、缺頁、略過下載或路徑衝突不會被記為完整作品，需要重新取得完整資訊。腳本不會掃描舊下載目錄，也不修改 PixivBatchDownloader 的狀態。

## 匯入統計與備份

桌面首頁的資料概覽提供「已匯入的作品」，統計此外掛成功匯入的唯一作品。多頁漫畫算一部，插畫和小說即使 ID 相同也分別計數。重新啟動後保留計數，刪除畫廊紀錄不會減少；既有作品、失敗和略過不計數，歷史匯入不會自動補算。統計儲存在外掛自己的 `data/pixiv-batch-downloader-import/plugin.db`，備份時應一起保留。

統計暫時寫入失敗時顯示無法使用，腳本重試會先補寫計數再確認成功。作品登記與統計分別提交；若程式在兩次提交之間遭強制終止，該次匯入可能漏計。

## 檔案格式、唯讀參照與限制

- 瀏覽器實際儲存路徑必須位於設定的根目錄內，可使用任意檔名和子目錄。宿主拒絕連結、junction、越界路徑、缺失檔案和不支援的檔頭。
- 圖片支援 JPEG、PNG、WebP、GIF；動圖支援 WebP、GIF、APNG、WebM、MP4、ZIP；小說支援 TXT、EPUB，正文取自同次取得的中繼資料。ZIP 縮圖唯讀第一個圖片項目，來源檔案仍是 ZIP。
- 小說封面、附件和原始發佈時間尚未匯入；目前小說頁會將登記時間顯示為上傳時間。
- 資料庫保存逐頁真實路徑和作品中繼資料，原始檔案保持不變。媒體維護略過外部唯讀作品。移動原始檔案後，需要修復檔案位置，程式不會猜測新路徑。
- 既有紀錄（含軟刪除）不覆寫，也不重複登記。小說能力無法使用時保留待處理資訊，不回報成功。
- 單頁檔案最多 1 GiB，單部作品最多 8 GiB、1000 頁。瀏覽器目前中繼資料最多 1000 部作品、8 MiB；待處理佇列最多 1000 部作品、5000 個檔案、8 MiB。佇列滿時會提示並停止接納新紀錄。
- HTTP 請求最多 12 MiB，JSON 深度 20，小說正文最多 300 萬字元。用戶端逐項傳送，失敗後的間隔逐步增加至 60 秒；權杖僅供單次使用，有效一分鐘。連線位址限於 loopback，不傳送 Pixiv Cookie 或管理員密碼。

事件對應 [PixivBatchDownloader 的固定原始碼](https://github.com/xuejianxianzun/PixivBatchDownloader/tree/e3bbdfdd2fb452cc9073450b8aa1ad065f982b64)。這些是上游內部事件；中繼資料必須先於同批下載成功事件抵達。真實擴充功能的事件相容性取決於瀏覽器和腳本管理器。

## 從使用者腳本匯入歷史記錄

1. 保持本機後端執行，在外掛設定中儲存「外部下載目錄」，指向原始檔案的根目錄。安裝或更新配套腳本後重新整理 Pixiv，並登入能存取這些作品的帳號。
2. 在使用 PixivBatchDownloader 的同一瀏覽器、同一使用者設定檔中開啟原來的 Pixiv 網站。暫停外部下載，在 Tampermonkey 選單選擇「讀取瀏覽器下載歷史」，按「讀取並檢查」並等待本機預覽。無需匯出或選取歷史檔案。
3. 核對待匯入、已存在及缺失或衝突數量，按「開始匯入」。瀏覽器逐項取得作品中繼資料，本機核驗檔案後登記。Pixiv Cookie 留在瀏覽器，不傳送至本機服務。

檢查明細最多顯示 100 部作品及其判定結果。「待匯入」為 0 時，檢查即結束，「開始匯入」保持停用，無需繼續等待。缺失或衝突不一定表示檔案被移動：請核對設定根目錄接上歷史記錄的相對路徑 `n` 後是否對應實際檔案，並檢查檔名與頁面記錄是否完整。工作階段釋放後可再次按「讀取並檢查」；釋放失敗時會提示結果尚未確認。

腳本唯讀存取目前 Pixiv 網站的下載歷史資料庫，分批傳給本機，單次合計最多 1 GiB。讀取期間不要清空或修改歷史；分批掃描不提供同時修改時的完整快照。腳本不讀取或上傳原作品檔案，也不建立、升級或改寫歷史資料庫。瀏覽器設定檔或網站來源不同、記錄已清除時，無法讀取原來的歷史。原始檔案保持唯讀；已有作品（含軟刪除記錄）略過。缺檔、缺頁或中繼資料不可用的作品不會登記。登記後可使用既有回填工具補齊其支援的欄位，不能還原缺失的原始檔案。

匯入期間保留此頁。取消、離頁或切換服務位址會請求停止，已登記作品會保留；歷史任務不存入腳本佇列，重新整理後不自動續跑。通訊失敗時結果可能尚未確認；請先檢查本機服務。如果建立會話的回覆遺失，需等待約 15 分鐘的閒置清理及目前操作退出後再試。上傳副本與候選清單位於 `data/pixiv-batch-downloader-import/browser-history/`，正常結束或閒置到期後清理；強制退出後的殘留僅可在程式完全停止時刪除。
