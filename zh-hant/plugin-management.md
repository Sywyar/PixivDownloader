# 外掛管理

管理員在 `/plugin-market.html` 瀏覽並安裝外掛，在 `/plugin-manage.html` 核對已安裝版本、目前處理程序載入狀態與重新啟動要求，或上傳本地外掛套件。磁碟安裝成功不等於目前處理程序已載入，部分外掛需重新啟動後端或完全結束軟體後才會生效。

## 核准外掛的 HTTP Hook

在外掛詳細資料的「HTTP Hook 宣告」中查看回呼入口、目標介面、執行時機及所需欄位。選擇「預覽核准」，核對權限及受影響頁面，再「確認並發布」；取消不會變更正式設定。新宣告預設不執行。

已核准且相同的宣告會在外掛重新啟用後恢復；目標或契約變更時須重新核准。目標缺席或有歧義時不能核准。停用外掛會保留已核准的前置保護並拒絕受保護業務；若決定解除保護，選擇「預覽撤銷」並確認發布。每次操作只更新選取的宣告。開發方式見[外掛開發](/zh-hant/plugin-development)。


## 安裝外掛與自訂儲存庫

1. 在外掛市場選擇受信任儲存庫中的外掛，或在外掛管理頁上傳本地 `.jar` / `.zip`（可選擇附帶 `.sig`）。
2. 查看外掛用途、所需 SDK 版本、來源、相依性與執行模式。
3. 核對安裝計畫（目標套件、相依來源與版本、反向依賴者、衝突及重新啟動影響）並確認；若出現執行信任確認視窗，核對發布者公鑰指紋或套件 SHA-256。
4. 依回執提示執行所需的重新啟動，返回管理頁確認載入版本與功能入口。失敗時先檢查原操作紀錄，勿盲目重複安裝。

在桌面 GUI「設定 → 外掛市場設定」中新增或編輯自訂儲存庫：可選擇「使用儲存庫描述檔」（預覽發布者、連網主機與公鑰完整指紋後加入草稿）或「自行填寫」（填寫 HTTPS 清單 URL、代理策略與 Ed25519 公鑰），統一儲存設定並重新啟動後生效。

相依套件依序使用獨立安裝交易：父套件失敗時，已安裝成功的相依套件會保留，並在結果中列出版本與 `transactionId`。市場操作紀錄儲存在目前處理程序記憶體中（最多 64 筆、非作用中紀錄保留 24 小時），關閉頁面不會取消已開始的後端安裝；處理程序重新啟動或紀錄過期後，請先核對管理頁的實際安裝狀態。

## 更新提示與歷史版本

下載頁導覽的數字徽章表示已安裝外掛有相容更新，驚嘆號表示有需要更高 SDK 的新版；管理頁橫幅會分別列出兩類提示。穩定版外掛預設只推薦穩定更新；手動安裝預先發行版後，才會跟隨對應預先發行管道（也可升至更高穩定版）。同版本手動修復包（`-f`）不會觸發一般更新徽章，需依修復說明重新安裝。

官方主清單保留最新版本、最新穩定版，以及固定舊 SDK 集合（`1.0.0`、`1.1.0`）的最新相容穩定版；其餘歷史版本儲存在依摘要命名的 `history/` 清單中（單檔上限 900 個版本或 1 MiB），在查看歷史或自動尋找相容舊版時依需求載入。

當外掛最新版不相容於目前 SDK 時，市場會自動查找同一儲存庫中最高的相容可安裝舊版，並在卡片與詳細資料中標示預設選擇；也可在詳細資料中展開閱讀經靜態隔離的 README、本次更新說明或 CHANGELOG，或手動選擇歷史版本。外掛授權與社群收錄規則見[第三方外掛 SDK](/zh-hant/plugin-development#外掛授權與發布管道)。

## 安全模型與套件准入上限

Ed25519 簽章證明發布者來源與位元組完整性，不代表程式碼安全審查或作業系統沙箱隔離；請僅安裝信任的發布者與儲存庫。宿主載入前會在資源限制內將外掛套件凍結至私有工作區，並對同一份凍結位元組核驗套件結構、`plugin.properties`、SHA-256、簽章、provenance、SDK 相容性與相依性。

### 執行模式

每個外部外掛必須在 `plugin.properties` 明確宣告 `pixiv.execution-mode`（缺少或未知值會在程式碼執行前被拒絕）：

| 值 | 執行位置 | 隔離與權限邊界 |
| --- | --- | --- |
| `host-process-full-trust` | 宿主 JVM | 繼承宿主處理程序的檔案、網路與作業系統權限（宿主以提高的權限執行時，管理頁會持續顯示警告） |
| `declarative-process` | 獨立 worker JVM | 共用宿主 OS 帳號，僅透過有界協定發布宣告式路由與能力（無完整 OS 沙箱；正式環境拒絕目錄形式，開發模式暫時降級為 full-trust 並如實顯示） |

從 `declarative-process` 升級為 `host-process-full-trust`、SDK 主版本變更或信任撤銷後，必須由管理員重新確認信任。worker 預設限制 128 MiB heap、128 MiB metaspace、64 MiB direct memory（OOM 時結束，最多自動重新啟動 3 次，退避 `500–10000` ms），初始化 / 命令 / 關閉逾時分別為 `10000` / `5000` / `2000` ms，同時僅允許 1 個進行中請求和 1 個排隊請求（可透過 `pixivdownload.plugin-worker.*` JVM 屬性調整）。

### 外掛套件預設資源上限

| JVM 屬性（前綴 `pixivdownload.plugin.package.`） | 預設上限 |
| --- | --- |
| `max-archive-bytes` | 192 MiB |
| `max-entries` | 48,000 個項目 |
| `max-total-uncompressed-bytes` | 672 MiB |
| `max-entry-uncompressed-bytes` | 64 MiB |
| `max-descriptor-bytes` | 1 MiB |
| `max-compression-ratio` | 200（僅檢查 ≥ 64 KiB 的項目） |
| `max-entry-name-length` / `max-entry-depth` | 1,024 個字元 / 64 層目錄 |

以上屬性僅接受正整數，非法值會直接阻止外掛執行期初始化。

## 安裝來源與市場狀態

- **發行包預置**：Windows 安裝包與 Java 標準包在 `plugins/` 預置預設官方外掛（`download-workbench`、`database-sqlite`、`gui-compose`、`gui-swing`、`gallery`、`novel` 等）；離線完整包額外包含 `database-postgresql`、[PixivBatchDownloader 匯入支援](/zh-hant/pixiv-batch-downloader-import)等官方選用外掛。`douyin` 為獨立第三方外掛，僅從自訂儲存庫或本地套件安裝。
- **本地上傳**：不建立自訂信任根；附帶簽章時須通過既有信任根核驗（依發布者指紋批准），未簽署套件標示為 `LOCAL_UPLOAD / UNSIGNED_ALLOWED`（僅批准目前精確 SHA-256）。遠端儲存庫套件強制要求清單簽章，不會降級為本地未簽署套件。開發模式下，若安裝包與原始碼模組同名衝突，僅儲存安裝包而不啟用，需移出衝突套件或排除原始碼模組後重新啟動。
- **市場狀態碼**：`NOT_INSTALLED`（有相容可安裝版本）、`INSTALLED`（已安裝且無更高相容版）、`UPDATE_AVAILABLE`（有更高相容版）、`INCOMPATIBLE`（無相容於目前 SDK 的版本）、`UNAVAILABLE`（無可安裝產物或相容查詢未完成）。

## 交易替換與生命週期策略

外掛安裝與更新採用原子交易：凍結候選位元組 → 核驗描述檔/簽章/相依性 → 停止舊世代接納新請求並等待處理完畢（drain） → 原子替換 artifact 與 provenance → 依策略啟用（失敗時完整回復舊世代）。

| `pixiv.lifecycle-policy` | 安裝 / 更新 | 啟用 / 停用 | 適用外掛 |
| --- | --- | --- | --- |
| `hot-reload`（預設） | 在目前處理程序即時替換並啟用 | 直接 start / stop | 可完整撤回貢獻並釋放背景任務與用戶端的外掛 |
| `backend-restart` | 在目前處理程序即時替換並啟用 | 儲存狀態後提示重新啟動後端 | 需重建 Spring 後端上下文的外掛 |
| `process-restart` | 寫入磁碟儲存，完全結束並重新啟動軟體後啟用 | 儲存狀態後提示完整重新啟動軟體 | `gui-compose`、`gui-swing`、資料庫 provider、契約載體與主題等處理程序層級外掛 |

可管理的 `hot-reload` 外掛支援 8 個動作：`load`、`start`、`quiesce`（停止接納新請求並等待處理完畢）、`stop`、`unload`、`remove`（刪除安裝包與 provenance，保留 `config/`、`state/`、`data/` 中的業務資料）、`restart`（同世代重新啟動）與 `reload`（建立新的 generation 與 classloader）。無 `purge` 動作。

## 復原模式、撤銷資訊與疑難排解

- **啟用狀態與復原模式**：開關儲存在 `config/config.yaml` 的 `plugins.{pluginId}.enabled`。必要外掛或目前選定的主資料庫 provider 缺少、損壞、不相容或啟動失敗時，應用程式會進入復原模式（保留登入、外掛管理與「換包修復」入口）；一般選用外掛故障僅隔離其自身能力。
- **撤銷資訊（`YANKED` / `REVOKED`）**：`YANKED` 阻止新安裝與更新，`REVOKED` 同時阻止後續載入與啟動；無有效撤銷快照或超過 24 小時寬限期時，禁止新安裝。重新整理撤銷資訊不會強制終止目前處理程序中已執行的 full-trust 程式碼，需完全結束應用程式並修復後再啟動。
- **常見故障**：
  - **安裝後頁面未出現**：核對回執中的 `effectiveAfterRestart`；`process-restart` 外掛必須完全結束軟體後重新開啟，僅重新整理網頁或重新啟動後端無效。
  - **提示不相容或驗證簽章失敗**：核對 `plugin.requires`（所需 SDK 版本，而非應用程式版本號）與相依版本，從原儲存庫重新取得完整套件，切勿手動修改 `plugin.properties`。
  - **`stop` / `reload` 長時間等待**：檢查 `log/latest.log` 中是否有未結束的佇列任務、HTTP/WebSocket 用戶端或排程執行緒。

外掛檔案儲存結構見[儲存與備份](/zh-hant/storage)，開發第三方外掛見[第三方外掛 SDK](/zh-hant/plugin-development)。
