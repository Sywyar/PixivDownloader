# 計劃任務

計劃任務讓後端按設定的時間間隔**自動發現並下載**新作品，無需每次手動操作。

**典型應用場景：**
- 關注了一位畫師，想自動下載他今後發佈的所有新作品
- 定期抓取某個搜索關鍵詞的最新結果
- 自動跟蹤一個漫畫/小說系列的更新
- 定期同步你的收藏 / 珍藏集 / 已關注用戶的新作（從「[快捷獲取](/zh-hant/quick-access)」創建）

?> 計劃任務僅管理員可使用。如果你是訪客，請讓管理員操作。

---

## 前提條件

1. **已登錄管理員賬號**
2. **已配置含 `PHPSESSID` 的 Cookie**（部分內容需要登錄態）

!> 沒有綁定 Cookie 的任務以「匿名模式」運行，只能下載全年齡公開內容，且無法訪問你的私有關注/收藏。如需下載 R-18 內容或完整關注列表，必須先配置好 Cookie。

---

## 創建第一個計劃任務

計劃任務**不是單獨填表創建**的，而是把你當前的下載配置「快照」下來作爲任務。具體步驟如下：

### 以「關注畫師」爲例

**第 1 步：進入畫師下載模式**

在 `pixiv-batch.html` 切換到「**👤 User 模式**」Tab。

**第 2 步：填入畫師來源**

在輸入框粘貼畫師主頁鏈接，例如：
```
https://www.pixiv.net/users/123456
```
也可以只填數字 ID（`123456`）。

**第 3 步：配置下載設置（可選）**

展開「下載設置」卡片，根據需要調整：
- **文件名模板**：默認 `{artwork_id}_p{page}`
- **收藏夾**：下載到哪個收藏夾
- **最大併發數**：一次同時下載幾個作品（默認跟隨全局設置）
- **作品間隔**：每個作品之間等多少毫秒（建議 500–2000，避免頻繁請求 Pixiv）
- **允許已刪除的作品被重新下載**：通過畫廊刪除的作品會保留[刪除標記](/zh-hant/gallery?id=刪除作品)，默認（不勾選）計劃任務把它們視爲已下載並跳過；勾選後視爲未下載、每輪自動重新下載。該設置隨「存爲計劃任務」一起快照保存，舊版本創建的任務在升級後首次啓動時自動補上該設置（默認不勾選）

**第 4 步：配置附加篩選（可選）**

展開「**附加篩選**」卡片，按需設置：
- 內容分級：只下載全年齡，還是包含 R-18？
- 排除 AI 生成作品？
- 限定特定標籤？

**第 5 步：存爲計劃任務**

向下滾動到頁面底部，找到「**⏰ 存爲計劃任務**」卡片：

1. 填寫**任務名稱**（方便區分，例如「畫師 Sywyar 每日更新」）
2. 選擇**觸發方式**：
   - **固定週期**：例如 `60` 分鐘執行一次
   - **Cron 表達式**：精確指定時間，例如每天凌晨 3 點 → `0 0 3 * * *`
3. （可選）設置**首次抓取上限**：限制首次運行抓取的作品數量，避免一次性下完整個歷史（詳見下文「[首次抓取上限](#首次抓取上限)」）；默認 `0` = 全量
4. （可選）勾選「**設置單獨的代理**」/「**設置單獨的cookie**」：爲這個任務指定獨立的 HTTP 代理（`host:port`，如 `127.0.0.1:7890`）與 Cookie，cookie 輸入框右側可點「**使用當前保存的cookie**」快捷填入；不勾選則分別使用全局代理設置 / 自動綁定的 Cookie（詳見下文「[指定單獨的 代理/cookie](#指定單獨的-代理cookie)」）
5. 點「**創建任務**」

?> 創建成功後頁面會彈出提示，切換到「⏰ 計劃任務」Tab 可以看到剛創建的任務。

## Cron 表達式格式

PixivDownloader 使用 Spring 的 **6 位 Cron 格式**（比常見的 5 位多了最前面的「秒」位）：

```
秒  分  時  日  月  周
0   0   3   *   *   *   → 每天 03:00:00
0   30  8   *   *   1   → 每週一 08:30:00
0   0   */6 *   *   *   → 每 6 小時
0   0   9   1   *   *   → 每月 1 日 09:00
```

| 字段 | 取值範圍 | 特殊值 |
|------|---------|-------|
| 秒   | 0–59 | `*`=每秒, `/n`=每n秒 |
| 分   | 0–59 | `*`=每分, `/n`=每n分 |
| 時   | 0–23 | `*`=每小時, `/n`=每n小時 |
| 日   | 1–31 | `*`=每天 |
| 月   | 1–12 | `*`=每月 |
| 周   | 0–7 | 0/7=週日, `*`=每天 |

## 來源類型的工作方式

> 除 User / Search / 系列外，「收藏 / 我的作品 / 關注新作 / 珍藏集」這幾類直接在「[快捷獲取](/zh-hant/quick-access)」Tab 展開對應來源後，由頁面底部的「⏰ 存爲計劃任務」卡片創建。

### 畫師新作（User 模式）

- **首輪**：下載該畫師所有符合篩選條件的未下載作品（可能較多）
- **後續**：使用「水位線增量」——每輪只掃描到上次已處理的最新作品爲止，只補新發布的，不重掃全部歷史
- 效果：首輪可能下載幾百張，之後每輪只下載新發的幾張

### 畫師約稿作品（User 模式「約稿」類別 / 快捷獲取「我的約稿」）

- 每輪列出該畫師**已完成並公開的約稿（リクエスト）成品**，跳過已下載的補下
- 約稿成品本質是普通插畫，按插畫的下載 / 判重 / 命名鏈路處理
- **不走水位線**（約稿成品次序不保證單調），按「全量發現 + 跳過已下載」執行；首次抓取上限按**每輪上限**生效

### 搜索關鍵詞（Search 模式）

- 按配置的頁數抓取最新搜索結果
- 按「最新」排序且頁數設爲 `-1` 時，同樣使用水位線增量，每輪只補最新的
- 效果：定期拉取該關鍵詞下的新作品

### 漫畫/小說系列（系列模式）

- 每輪列出系列全部章節，跳過已下載的，補充新章節
- 適合跟蹤連載中的漫畫或小說系列

### 我的收藏 / 我的作品 / 關注新作 / 珍藏集（從「快捷獲取」創建）

在「⚡ 快捷獲取」Tab 展開對應來源後（收藏 / 我的作品 / 關注新作，或點進某位關注畫師 / 某個珍藏集），頁面底部的「⏰ 存爲計劃任務」卡片即可創建：

- **我的收藏**：定期發現收藏夾（公開 / 不公開、插畫 / 小說）裏尚未下載的作品並補下
- **我的作品**：等同於按你自己賬號的「畫師新作」
- **已關注的用戶的新作**：定期下載關注畫師的最新插畫/漫畫/動圖
- **珍藏集**：列出珍藏集內的插畫與小說成員，跳過已下載的補下（**插畫與小說都會下載**）

!> 這幾類來源屬於**賬號私有**，對應任務必須已綁定含 `PHPSESSID` 的 Cookie（見下文「[指定單獨的 代理/cookie](#指定單獨的-代理cookie)」），否則會標記爲「登錄態失效」並暫停（不會以匿名模式空跑）。它們沒有獨立的模式標籤頁，**編輯時來源爲只讀**——要更換來源請刪除後重新創建。

## 首次抓取上限

對於可能一次性下完大量歷史的來源，可在「⏰ 存爲計劃任務」卡片填寫**首次抓取上限**，限制抓取數量、降低觸發 Pixiv「過度訪問」警告的風險。`0` 表示全量抓取（不限）。

行爲按來源是否有可靠的「最新」次序分兩類（頁面提示會自動只顯示與當前來源匹配的那一條說明）：

- **首輪封頂**（畫師新作 / 已關注用戶的新作 / 「最新排序 + 結束頁 -1」的搜索）：**僅首次運行**最多抓取最新的 N 個作品，水位線隨即推進到最新；之後每輪只增量追新，更早的歷史不再補下。適合「只想要最近 N 個、之後持續跟新」。
- **每輪上限**（我的收藏 / 珍藏集 / 畫師約稿作品 / 非最新排序的「結束頁 -1」搜索）：這些來源沒有可靠的「最新」次序，因此按**每輪上限**執行——每次運行最多抓取 N 個新作品，分多輪逐步把積壓抽乾。**若希望最終完整下載全部作品，把上限設爲 `0` 即可**（每輪不限）。

系列下載與固定頁數搜索本身範圍有界，不顯示該選項。

!> 把上限設爲 `0`（全量）時，首次運行可能一次性下完該來源的全部歷史；作品很多時仍有觸發過度訪問警告甚至封號的風險，保存時頁面會彈出確認。

## 管理已有任務

切換到「**⏰ 計劃任務**」Tab，可以看到所有任務。

每個任務卡片右上角有**狀態燈**：

| 顏色 | 狀態 | 含義 |
|------|------|------|
| 🔘 灰 | 等待 / 已停用 / 已暫停 | 任務正常待機，或被手動暫停 |
| 🟢 綠 | 運行中 / 上次成功 | 任務正常 |
| 🟡 黃 | 排隊中 | 多個任務同時到期，正在排隊等待依次執行 |
| 🔴 紅 | 失敗 / Cookie 失效 / 被中斷 / 過度訪問暫停 | 任務需要關注，點卡片查看詳情 |

### 常用操作

| 操作 | 說明 |
|------|------|
| **立即運行** | 不等定時，馬上執行一次 |
| **指定單獨的 代理/cookie** | 彈窗中爲該任務綁定 / 替換 / 清除獨立的 HTTP 代理與 Cookie |
| **啓用 / 停用** | 暫時停止某任務的定時觸發 |
| **手動暫停 / 恢復** | 與「停用」類似，但會在狀態燈上區分顯示 |
| **查看快照** | 查看任務創建時保存的來源和篩選配置 |
| **編輯** | 修改任務配置（重新走創建流程） |
| **待重試** | 查看本任務中失敗等待重試的作品 |
| **刪除** | 徹底刪除任務（已下載的文件不受影響） |

## 指定單獨的 代理/cookie

?> 如果你在 Solo 模式下**創建任務時**已有可用 Cookie 且未勾選「設置單獨的cookie」，任務會自動綁定當前 Cookie，無需手動操作。

每個任務卡片上的「**指定單獨的 代理/cookie**」按鈕會打開一個彈窗，包含兩個複選框：

- **設置單獨的代理**：填入 `host:port`（如 `127.0.0.1:7890`）。設置後該任務每輪運行中對 Pixiv 的**全部**訪問
  （作品發現、元數據、圖片 / 小說下載、站內信過度訪問檢測）都改走這個 HTTP 代理；不勾選則使用全局代理設置。
  適合給不同任務分配不同出口、分攤請求來源。
- **設置單獨的cookie**：粘貼含 `PHPSESSID` 的 Cookie，或點輸入框右側的「**使用當前保存的cookie**」把
  Cookie 卡片裏保存的那份快捷填入。適合讓某個任務用另一個 Pixiv 賬號運行。
  出於安全考慮，已綁定的 Cookie 不會回顯——已綁定時留空保存表示保持不變，填寫則替換。

取消已生效的勾選並保存會**清除**對應設置（會先彈窗確認後果）：代理回退全局設置；Cookie 解除綁定後任務轉爲
「受限模式」（匿名運行，R-18 等受限內容不可見，「我的收藏 / 已關注用戶的新作 / 珍藏集」類任務無法運行）。

「**⏰ 存爲計劃任務**」卡片裏也有同樣的兩個複選框，可以在創建 / 編輯任務時一併設置。

如果任務顯示「受限模式」，說明還沒綁定 Cookie：在任務卡片上點「**指定單獨的 代理/cookie**」，勾選
「設置單獨的cookie」填入（或快捷填入當前保存的）Cookie 並保存即可。

Cookie 失效（Pixiv 重新登錄或改密碼後）時：
- 任務會自動停止並標記「登錄態失效」（紅燈）
- 同時發送通知（郵件 / 推送，需先配置對應通道）
- 重新獲取有效 Cookie 後，在「指定單獨的 代理/cookie」彈窗中重新綁定即可恢復（提交與已綁定完全相同的失效 Cookie 會被拒絕）

## 過度訪問暫停

當 Pixiv 檢測到你的賬號請求過於頻繁時，會發送「過度訪問」站內信警告。PixivDownloader 會自動檢測並暫停**同賬號的所有計劃任務**，避免賬號被封禁。

此時任務管理 Tab 頂部會出現橫幅，提供兩個恢復選項：

1. **「無視風險，立即恢復」** — 把本次警告標記爲已放行，馬上繼續（仍有風險）
2. **「N 分鐘後繼續」** — 冷卻一段時間再恢復（最少 60 分鐘，默認 60 分鐘）

建議選第 2 項，等待一段時間再繼續。

## 通知（郵件 / 推送）

計劃任務在以下情況會發送通知，郵件與已配置的推送通道（Bark / 釘釘 / Telegram / 飛書 / 企業微信 / PushPlus / Server 醬 / Webhook）會**並行**送達：
- Cookie 失效（登錄態失效）
- 檢測到過度訪問
- 熔斷掛起（連續失敗次數達到閾值）
- 失敗作品重試達到上限

通知會附帶便於直接定位的關鍵信息：
- **過度訪問暫停**：逐條列出被掛起的計劃任務名稱與 ID、受影響任務數、警告時間
- **鑑權失效 / 熔斷掛起**：任務名稱與 ID、任務類型、觸發方式（每 N 分鐘 / Cron）、下次預定運行時間
- **失敗作品重試達上限**：在上述基礎上附帶該作品的 Pixiv 直鏈，方便直接打開覈對

通知正文絕不包含 Cookie / 密碼等任何憑證。

!> 郵件通知需要先在 GUI「配置 → 郵件 / SMTP」配置 SMTP 賬號、推送通知需在「配置 → 推送」配置對應通道，否則對應通道的通知會靜默跳過。兩類配置頁都提供測試按鈕可預覽各場景的實際呈現。

## 相關配置

計劃任務的相關配置在 GUI「配置 → 計劃任務」或 `config.yaml` 的 `schedule.*` 下：

| 配置項 | 說明 | 默認值 |
|--------|------|-------|
| `schedule.enabled` | 總開關 | `true` |
| `schedule.tick-interval-ms` | 檢查到期任務的間隔（毫秒），**修改需重啓** | `60000` |
| `schedule.max-tasks` | 最多可創建的任務數 | `100` |
| `schedule.inbox-check-every` | 每下載多少個作品檢測一次過度訪問站內信 | `500` |
| `schedule.auth-failure-circuit-breaker` | 連續失敗多少次觸發熔斷掛起 | `5` |
| `schedule.pending-max-attempts` | 失敗作品最多自動重試幾次 | `5` |
| `schedule.overuse-defer-default-minutes` | 過度訪問暫停後「稍後繼續」的默認分鐘數（最少 60） | `60` |

詳細配置說明見[配置參考](/zh-hant/configuration)。
