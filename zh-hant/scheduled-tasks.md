# 排程工作

排程工作在後端執行期間，依固定週期或 Cron 時間自動**探索並下載**新作品。建立任務時會儲存來源、篩選條件和下載設定的快照；後續修改下載頁面設定不會改變既有任務。關閉瀏覽器不影響執行，停止後端則不會執行。

排程器與管理 API 由應用程式宿主提供。停用 `download-workbench` 會撤回下載頁面、Pixiv 來源與插畫執行器，依賴這些能力的任務會保留資料與進度並暫停，由其他外掛完整支援的任務則會繼續執行；所需能力恢復後，排程器會自動複核並恢復因能力缺少而暫停的任務。手動暫停、憑證失效和策略暫停仍需明確處理。

## 前提條件

1. 已使用管理員帳號登入（訪客無法使用）。
2. 後端保持執行，且 `schedule.enabled` 總開關已啟用。
3. 帳號私人來源（收藏、我的作品、關注新作、珍藏集）及 R-18 等受限內容，必須為任務綁定含有效 `PHPSESSID` 的 Cookie；缺少有效 Cookie 時，私人來源會暫停，不會以匿名方式空跑。

## 建立第一個排程工作

排程工作透過將下載頁目前設定儲存為快照來建立（新舊兩版下載頁通用）。以下以「定期追蹤畫師新作」為例：

1. 開啟下載頁，切換到「User 模式」，輸入畫師首頁連結或數字 ID（如 `https://www.pixiv.net/users/123456`，請替換為實際畫師 ID）。
2. 展開「下載設定」，依需求設定：
   - **檔名範本**：預設 `{artwork_id}_p{page}`。
   - **收藏夾**、**最大並行數**、**作品間隔**（毫秒，如 `1000`；設定間隔不能保證避免上游限制）。
   - **允許重新下載已刪除的作品**：畫廊刪除的作品保留[刪除標記](/zh-hant/gallery#刪除作品)，預設略過；勾選後每輪自動重新下載（此項會隨快照儲存，舊版本任務升級後預設補為未勾選）。
3. 展開「附加篩選」，依需求設定內容分級、排除 AI 或標籤條件。
4. 捲動到頁面底部「儲存為排程工作」卡片：
   - 填寫**工作名稱**；
   - 選擇**觸發方式**：固定週期（如每 `60` 分鐘）或 6 欄 Cron 表達式（如每天 03:00 填 `0 0 3 * * *`）；
   - 依需求設定[首次擷取上限](#首次擷取上限)與[指定單獨的代理／cookie](#指定單獨的代理／cookie)；
   - 點擊「建立工作」。
5. 切換到「排程工作」清單查看快照，先點一次「立即執行」，核對佇列中的成功、略過和失敗原因，再確認下次觸發時間。若任務已建立但代理或 Cookie 儲存失敗，直接在該任務上繼續設定，不要重複建立。

## Cron 表達式格式

使用 Spring 6 欄 Cron 格式（首欄為「秒」）：

```text
秒  分  時  日  月  週
0   0   3   *   *   *   每天 03:00:00
0   30  8   *   *   1   每週一 08:30:00
0   0   */6 *   *   *   每 6 小時
0   0   9   1   *   *   每月 1 日 09:00:00
```

| 欄位 | 範圍 | 常用符號 |
| --- | --- | --- |
| 秒 / 分 | `0–59` | `*` 每秒/每分，`/n` 每隔 n 秒/分 |
| 時 | `0–23` | `*` 每小時，`/n` 每隔 n 小時 |
| 日 | `1–31` | `*` 每天 |
| 月 | `1–12` | `*` 每月 |
| 週 | `0–7` | `0` 或 `7` 表示週日，`*` 每天 |

## 來源類型的運作方式

| 來源類型 | 執行方式 |
| --- | --- |
| 畫師新作（User 模式） / 我的作品 | 首輪擷取符合條件的未下載作品；後續輪次使用**進度水位增量**，僅掃描至上輪已處理的最新作品為止 |
| 畫師約稿作品（User「約稿」/ 快速取得「我的約稿作品」） | 每輪列出已完成並公開的約稿成品，依一般插畫流程下載並略過已下載作品；因順序不保證單調，不使用進度水位 |
| 搜尋關鍵字（Search 模式） | 依所選頁數擷取；「最新」排序且結束頁設為 `-1` 時，同樣使用進度水位增量 |
| 漫畫 / 小說系列（系列模式） | 每輪檢查系列章節清單，略過已下載章節，補齊新章節 |
| 我的收藏 / 關注新作 / 珍藏集 | 在[快速取得](/zh-hant/quick-access)中展開對應來源後建立；珍藏集會同時下載插畫與小說。編輯任務時來源為唯讀，更換來源需刪除後重建 |

## 首次擷取上限

針對歷史作品較多的來源，可設定「首次擷取上限」（`0` 表示不限制數量）：

- **首輪上限**（畫師新作、已關注使用者的新作、「最新排序 + 結束頁 `-1`」的搜尋）：僅首次執行最多擷取最新 N 件作品並推進進度水位，後續輪次只追蹤之後發布的新作，不再補抓更早的歷史作品。
- **每輪上限**（我的收藏、珍藏集、約稿作品、非最新排序的「結束頁 `-1`」搜尋）：沒有單調的最新順序，每次執行最多接納 N 件新作品，分多輪逐步處理既有作品。
- **固定頁數搜尋**：上限於每輪生效；`0` 只取消數量限制，不擴大所選頁碼範圍（僅選第 1 頁時，不會自動向後翻頁）。

!> 略過已下載作品不會消耗接納額度，因附加篩選而略過仍會消耗額度。不限頁或多頁來源設為 `0` 時，可能擷取大量歷史作品，儲存前會要求確認。

## 管理既有任務

在「排程工作」清單中，任務卡片右上角狀態燈表示目前狀態：

| 狀態燈 | 含義 |
| --- | --- |
| 灰 | 等待下次觸發、已停用或已手動暫停 |
| 綠 | 正在執行或上次執行成功 |
| 黃 | 多個任務同時到期，排隊等待執行 |
| 紅 | 執行失敗、Cookie 失效、被中斷或觸發過度存取暫停（點擊卡片查看原因） |

卡片支援：**立即執行**、**指定單獨的代理／Cookie**、**啟用 / 停用**定時觸發、**手動暫停 / 恢復**、**查看快照**、**編輯**、**待重試**（查看失敗待重試作品）與**刪除**（不影響已下載檔案）。

## 指定單獨的代理／Cookie

在單人模式下建立任務時，若已儲存有效 Cookie 且未勾選獨立設定，任務會自動綁定目前的 Cookie。也可在建立時或任務卡片的「指定單獨的代理／Cookie」彈出視窗中獨立設定：

- **設定單獨代理**：填寫 `host:port`（如 `127.0.0.1:7890`），使該任務的所有 Pixiv 請求（探索、中繼資料、圖片/小說下載、站內信過度存取檢查）經由該 HTTP 代理；不勾選則使用全域代理。
- **設定單獨 Cookie**：貼上含 `PHPSESSID` 的 Cookie，或點擊「使用目前儲存的 Cookie」填入。已綁定 Cookie 不會回顯；留空儲存會保持不變，填入新值則替換。

取消已生效的勾選並儲存，會清除對應設定：代理退回全域設定；Cookie 解除綁定後，任務轉為匿名「受限模式」（無法取得 R-18，且帳號私人來源無法執行）。當任務偵測到 Cookie 失效時，會自動暫停並標示「登入狀態失效」，重新取得並綁定新 Cookie 後恢復（重複提交同一份已失效 Cookie 會被拒絕）。

## 過度存取暫停與通知

當偵測到 Pixiv 傳送「過度存取」站內信警告時，系統會自動暫停**同一帳號下的所有排程工作**。清單頂部橫幅提供「忽略風險，立即恢復」和「N 分鐘後繼續」（最少及預設 60 分鐘，建議等待冷卻後恢復）。

設定桌面「設定 → 郵件 / SMTP」或「設定 → 推播」（支援 Bark、釘釘、Telegram、飛書、企業微信、PushPlus、Server 醬、Webhook）後，以下事件會並行傳送通知（正文絕不包含 Cookie 或密碼）：

- **過度存取暫停**：列出受影響任務名稱、ID、數量與警告時間。
- **登入狀態失效 / 連續失敗熔斷**：列出任務名稱、ID、類型、觸發規則與下次執行時間。
- **失敗作品重試達上限**：額外附帶該作品的 Pixiv 連結。

## 疑難排解與相關設定

任務未執行時，依序核對後端處理程序、全域開關、任務啟用狀態和卡片上的暫停原因。更換有效 Cookie 只解除憑證暫停，不會自動解除其他原因的暫停；清除下載頁上的全域 Cookie，也不會自動解除既有任務的獨立憑證綁定。編輯任務來源或篩選條件會重設增量進度水位，下一輪重新掃描並依本地下載紀錄判定重複。

| 設定項目（`config/config.yaml`） | 預設值 | 說明 |
| --- | --- | --- |
| `schedule.enabled` | `true` | 排程工作總開關 |
| `schedule.tick-interval-ms` | `60000` | 檢查到期任務的間隔（毫秒，修改需重新啟動） |
| `schedule.max-tasks` | `100` | 最多可建立任務數 |
| `schedule.inbox-check-every` | `500` | 每成功下載多少件作品，檢查一次過度存取站內信 |
| `schedule.auth-failure-circuit-breaker` | `5` | 連續探索失敗觸發熔斷暫停的次數 |
| `schedule.pending-max-attempts` | `5` | 失敗作品最多自動重試次數 |
| `schedule.overuse-defer-default-minutes` | `60` | 過度存取暫停後的預設冷卻分鐘數（最小 60） |

完整設定說明見[設定參考](/zh-hant/configuration)。
