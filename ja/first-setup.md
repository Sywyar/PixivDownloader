# 初回セットアップ

初回セットアップでは、PixivDownloader 本体の管理者アカウントを作成し、バックエンドが外部サービスに接続するときに使用する HTTP プロキシを設定します。Pixiv のログイン Cookie は、ダウンロードページを開いてから別途保存します。

[インストールと起動](/ja/installation)を終えたら、実行環境に合った方法で初期化してください。

| 実行環境 | 初期化の入口 | 初期化後の操作 |
| --- | --- | --- |
| ローカルデスクトップ | デスクトップの初回ガイド、または同じ端末のブラウザーで `http://localhost:6999/setup.html` を開く | ダウンロードページを開いてログインする |
| デスクトップのないサーバー（`--no-gui`） | 先に `--setup` を実行する | その後 `--no-gui` で起動する |
| Docker | 先に `docker compose run --rm app --setup` を実行する | その後 `docker compose up -d` を実行する |

## デスクトップまたはローカルブラウザーで初期化する

1. プログラムを起動し、バックエンドの準備が完了するまで待ちます。必須プラグインの不足やデータベースの利用不可が表示された場合は、先に[プラグイン管理](/ja/plugin-management)に従って修復してください。アカウントを初期化し直しても、プラグインやデータベースの不具合は解決しません。
2. 管理者のユーザー名とパスワードを設定します。パスワードは 8 文字以上が必要で、12 文字以上を推奨します。8～11 文字の場合は追加の確認が必要です。
3. 実際のネットワークに合わせて HTTP プロキシのホストとポートを入力します。ローカルプロキシなら `127.0.0.1` と `7890` などです。対象サービスに直接接続できる場合は、プロキシを無効にできます。
4. 保存後に `http://localhost:6999/pixiv-batch.html` を開き、作成した管理者アカウントでログインします。

デスクトップとブラウザーの初期化画面は、シングルユーザーモード（`solo`）を使用します。`setup.html` はローカルのループバック接続からのみアクセスできます。リモートサーバーやコンテナーでは、以下の CLI 初期化を使ってください。その後の通常の設定変更はデスクトップの「設定」ページで保存します。プロキシと各プラグインの通信経路の適用範囲は、[ネットワークアクセスと外部サービス](/ja/network-access)を参照してください。

## コマンドラインで初期化する（サーバー / ヘッドレス環境）

配布パッケージ全体を展開したディレクトリに移動し、同じデータディレクトリを使うインスタンスが動作していないことを確認します。以下の `APP.jar` は実際の本体 JAR 名に置き換えてください。

```text
java -Dfile.encoding=UTF-8 -jar APP.jar --setup --mode=solo
```

画面の案内に従って、管理者のユーザー名、パスワード、プロキシ設定を入力します。アカウントの状態は `state/setup_config.json`、プロキシ設定は `config/config.yaml` に保存されます。完了したらヘッドレスサービスを起動します。

```text
java -Dfile.encoding=UTF-8 -jar APP.jar --no-gui
```

自動化スクリプトでは、すべての引数をまとめて指定できます。パスワードとプロキシは実際の値に置き換えてください。コマンドライン引数はシェルの履歴やプロセス一覧に表示されます。

```text
java -Dfile.encoding=UTF-8 -jar APP.jar --setup --username=admin --password=REPLACE_WITH_A_UNIQUE_PASSWORD --mode=solo --proxy-enabled=true --proxy-host=127.0.0.1 --proxy-port=7890
```

プロキシが不要な場合は `--proxy-enabled=false` を使います。CLI は `--mode=solo` と `--mode=multi` の両方に対応しています。ゲストへの読み取り専用の共有には、[詳細リファレンスのゲスト招待](/ja/usage-guide#ゲスト招待)を優先してください。

## Docker で初期化する

[Docker のインストール手順](/ja/installation#方法-3：docker-でデプロイする)に従ってイメージとマウントディレクトリを準備し、`docker-compose.yml` のあるディレクトリで実行します。

```bash
docker compose run --rm app --setup --mode=solo
docker compose up -d
docker compose logs -f app
```

コンテナー内の `127.0.0.1` はコンテナー自身を指します。ホストのプロキシを使う場合は、プロキシホストに `host.docker.internal` を指定し、ホスト側のプロキシがその接続を許可していることを確認してください。`--setup` を完了する前にヘッドレスサービスを起動すると、終了コード `78` で終了します。

## 結果の確認とパスワード変更

管理者アカウントでダウンロードページにログインし、ワークベンチが正常に読み込まれることを確認してから、[初回ダウンロード](/ja/first-download)に従ってダウンロードを試してください。保存や起動に失敗した場合は、エラーを記録し、`log/latest.log`、ディレクトリの書き込み権限、ポートの使用状況、データベースの状態を確認します。初期化ファイルを繰り返し削除して問題を解決しようとしないでください。

実行中のインスタンスを停止してから、配布ディレクトリで管理者パスワードを変更またはリセットできます。

```text
java -Dfile.encoding=UTF-8 -jar APP.jar --change-password
java -Dfile.encoding=UTF-8 -jar APP.jar --reset-password
```

`--change-password` は元のパスワードを確認します。`--reset-password` は、パスワードを忘れたときにローカルから強制リセットするための操作です。成功すると既存のログインセッションはすべて無効になりますが、作品ファイルとデータベースには影響しません。初期化状態の再作成が本当に必要な場合に限り、プログラムを停止してバックアップを取った後、`state/setup_config.json` を退避して `--setup` を再実行してください。
