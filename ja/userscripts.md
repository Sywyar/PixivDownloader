# ユーザースクリプト

Tampermonkey スクリプトを使うと、Pixiv のページで作品を選択・取得したり、ローカルのバックエンドにタスクを送ったりできます。ユーザースクリプトは任意であり、インストールしなくても `pixiv-batch.html` で一括ダウンロードできます。

スクリプトの一覧とインストール API はアプリケーションのホストが提供し、`download-workbench` には依存しません。ホストは現在有効なプラグインが宣言したスクリプトだけを表示します。ダウンロードワークベンチを無効にすると、そのダウンロード補助スクリプトは一覧から外れますが、外部インポートなど他のプラグインのスクリプトは引き続きインストールできます。シングルユーザーモードでバックエンドに接続するには、本プログラムへのログインが必要です。`@updateURL` がバックエンドを指す場合、Tampermonkey のバックグラウンド更新リクエストにログインセッションが付く保証はありません。

## 前提条件とスクリプト一覧

ブラウザーに [Tampermonkey](https://www.tampermonkey.net/) をインストールしてください。Java バックエンド版やツールボックスを使用するには、バックエンドを起動し、シングルユーザーモードではログインしておく必要があります。ブラウザーだけで動く `Local Download` はバックエンド不要ですが、メタデータの保存やギャラリーへの登録は行いません。

| スクリプト名 | 動作する場所と用途 |
| --- | --- |
| All-in-One 統合パッケージ | 標準のダウンロード補助スクリプトとツールボックスを統合（外部インポートなど他のプラグインのスクリプトは含まない） |
| ページ一括ダウンローダー (Page Scrape) | 検索、フォロー新着、ランキングなどの一覧ページでサムネイルを選択して一括でキューに追加 |
| ユーザー一括ダウンローダー (User Batch) | 作者のホーム（`/users/<id>` とその子ページ）でイラスト・小説ごとに全作品をワンクリックでキューに追加 |
| URL 一括インポート (URL Batch) | Pixiv の任意のページでフローティングパネルを開き、URL を貼り付けて一括ダウンロード |
| 単一作品ダウンローダー (Java バックエンド版) | 単一作品ページ（`/artworks/<id>`）からバックエンド経由でダウンロードし、メタデータの保持と自動ブックマークに対応 |
| 単一作品ダウンローダー (Local Download) | 単一作品ページでブラウザーから直接保存。Java バックエンドは不要で、ギャラリーのデータベースには登録しない |
| 機能拡張ツールボックス (Toolbox) | Pixiv ページの右側に、ダウンロード済み作品の色付き枠や Cookie のワンクリックインポートなどを提供 |

[外部ダウンロードのインポート](/ja/pixiv-batch-downloader-import)用スクリプトは `pixiv-batch-downloader-import` プラグインが別途提供し、All-in-One には含まれません。プラグインをインストールして再起動した後、個別にスクリプトをインストールしてください。

## インストール手順

### 方法 1：バックエンドのダウンロードページからインストール（推奨）

1. PixivDownloader を起動し、現在のインスタンスのダウンロードページを開きます。例は `http://localhost:6999/pixiv-batch.html` です。ポートは実際のアドレスに合わせてください。
2. 「ユーザースクリプト」を展開し、対象の「インストール」をクリックして Tampermonkey で確認します。
3. ダウンロードページと開いている Pixiv ページを再読み込みし、スクリプトの状態とフローティングパネルを確認します。

バックエンドからインストールすると、更新リンクと検出範囲がポートを含む現在のアドレスに紐づきます。バックエンド用ダウンロードスクリプトの初回接続にもこのアドレスを使い、保存済みのアドレスがあればそちらを優先します。リモート接続に対応するスクリプトは `@connect YOUR_SERVER_HOST` を置き換えますが、外部インポート用スクリプトは引き続きローカル接続専用です。**All-in-One 統合パッケージ**をインストールした場合は、含まれている個別スクリプトを無効にして二重パネルを防いでください。両者のローカルストレージは独立しています。

### 方法 2：ソースリポジトリから個別スクリプトをインストール

[ソースリポジトリ](https://github.com/Sywyar/PixivDownloader)にコミットされている `.user.js` の Raw を開き、Tampermonkey でインストールした後、スクリプト設定のバックエンドアドレスと `@connect` の許可を確認してください。All-in-One 統合パッケージはビルド時に生成され、公開処理でも個別の userscript を Release の添付ファイルとしてアップロードしません。実行中のバックエンドからインストールしてください。

## 履歴によるスキップと別マシンでの運用

バックエンドを使う各ダウンロードスクリプトの設定パネルでは「過去のダウンロードをスキップ」を有効にし、さらに次を選べます。

- **実際のディレクトリを確認**：ディスク上にファイルが存在するかも確認し、欠けている場合は再ダウンロードします。
- **削除済みの作品の再ダウンロードを許可**：ギャラリーから削除した作品には[削除マーク](/ja/gallery#作品を削除する)が残り、デフォルトではダウンロード済みとしてスキップします。選択すると再ダウンロードし、成功時に削除マークを解除します。

バックエンドを別のマシンやデフォルト以外のポートで運用する場合（デフォルトは `http://localhost:6999`）：

1. 接続先のバックエンドからインストールすると、初回接続にはそのプロトコル、ホスト、ポートが使われます。別のアドレスを保存済みの場合は、スクリプト設定で変更してください。
2. そのバックエンドの Web ページからスクリプトを再インストールし、`@connect` のホスト許可を更新します。手動インストールの場合はスクリプト先頭の `@connect` を確認してください。`@connect` の変更だけではリクエストの送信先は変わりません。
3. Pixiv ページを再読み込みして作品を 1 件送信し、対象バックエンドのキューに届いたことを確認します。

## インストール元アドレスと実行検出

たとえば `http://localhost:7000` からインストールした場合、更新リンクとダウンロードページでの検出はポート 7000 を使います。他のポートはスキャンしません。Pixiv ページで使う接続設定とダウンロードページの検出範囲は別であり、接続設定を変えても検出範囲は広がりません。

| 場所 | 用途 |
| --- | --- |
| `@updateURL`、`@downloadURL` | プロトコル、ホスト、ポート、アプリケーションのコンテキストパスを含むインストール URL |
| `@include` と挿入された `origin` / `pages` | 検出に応答できるバックエンドページ。`@include` は正規表現で、ソース内のスラッシュはエスケープされる |
| `@connect` | リクエストを許可するホスト。ポートは記載せず、送信先の選択にも使わない |

検出は同じページ内の `window.postMessage` で実行中のバージョンを取得し、バックエンドへ検出リクエストを送りません。カード右上には検出バージョンとインストール可能なバージョンをまとめて表示し、同じバージョンは一度だけ表示します。更新がある場合は先頭行にオレンジ色で表示します。検出済みは緑、All-in-One による対応は青、古いバージョンと未検出は中立色で示し、状態を表すテキストも表示します。

比較するのは同じスクリプトのバージョンで、ドットで区切った 1〜3 個の数値と `alpha.N`、`beta.N`、`rc.N` のプレリリース形式に対応します。独自形式や複数の検出バージョンで大小関係が混在する場合は、インストール可能なバージョンとして表示します。All-in-One と単独スクリプトのバージョンは比較しません。

### 開発者向け：検出ページの宣言と既定アドレス

スクリプトはプラグインの `UserscriptContribution` で宣言します。userscript メタデータの終了マーカーより前に次を追加してください。

```javascript
// @pixiv-presence-page /pixiv-batch.html
// @pixiv-presence-page /pixiv-batch-alt.html
```

最外層の IIFE の `'use strict'` の後、業務処理の初期化より前に `// @pixiv-presence-bootstrap` を置きます。両方が必要で、マーカーだけではホストは `@include` を生成しません。バックエンドページでは検出応答だけを行い、Pixiv の処理を開始しないでください。

ホストの `ScriptController.buildInstallUrl` が現在の HTTP リクエストからプロトコル、ホスト、ポート、context path を取得し、更新リンクを書き換えます。`UserscriptPresenceInstaller` は同じ URL から検出範囲を生成します。ルートのバックエンド用スクリプトでは `scripts/shared/installed-server.js` が `GM_info`（`GM.info` にも対応）の `script.downloadURL`、`script.updateURL`、`scriptUpdateURL` から既定の接続先を取得します。有効なバックエンドのインストール URL がない場合だけ、ソースの既定値 `http://localhost:6999` を使います。`GM_getValue` で保存済み設定を読み、初期化時に上書きしないでください。

共有コードは `scripts/sync-shared-snippets.ps1` で同期し、All-in-One はビルド時に生成します。外部インポート用スクリプトは専用の `installedServer()` を持ち、引き続きサブパスのないローカルアドレスだけに接続します。Local Download には既定のバックエンドアドレスは不要です。

## トラブルシューティング

- **Pixiv ページにスクリプトのパネルが出ない**：Tampermonkey 拡張機能と対象スクリプトが有効か、現在の URL がスクリプトの `@match` に一致するか（User Batch は `/users/` ページのみなど）を確認し、再読み込みしてください。Chrome 138+ では拡張機能の詳細で「ユーザースクリプトを許可」も有効にする必要があります。
- **ダウンロードページに「未検出」と表示される**：ページ内の応答を受け取っていないという意味で、未インストールとは限りません。有効化状態、サイトの権限、インストール元のポートを確認し、必要なら現在のバックエンドから更新して再読み込みしてください。インストールレスポンスに `@include` がない場合は、スクリプトを提供するプラグインの更新が必要です。同じ内容を再インストールしても宣言は追加されません。
- **「バックエンドが起動していない」「接続失敗」と表示される**：バックエンドのプロセス、シングルユーザーモードのログイン状態、スクリプトのバックエンドアドレスを確認してください。Cookie のワンクリックインポートに失敗する場合は、[初回ダウンロード](/ja/first-download#方法-c：ユーザースクリプトの「cookie-をワンクリックでインポート」)に従い、Tampermonkey の HttpOnly Cookie 権限を確認してください。
