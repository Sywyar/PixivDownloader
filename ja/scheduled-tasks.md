# スケジュールタスク

スケジュールタスクは、バックエンドの起動中に固定間隔または Cron の時刻で新しい作品を自動的に**検出してダウンロード**します。作成時に取得元、絞り込み条件、ダウンロード設定のスナップショットを保存し、その後にダウンロードページの設定を変更しても既存タスクには反映されません。ブラウザーを閉じても動作しますが、バックエンドを停止すると実行されません。

スケジューラーと管理 API はアプリケーションのホストが提供します。`download-workbench` を無効にすると、ダウンロードページ、Pixiv の取得元、イラスト実行機能が取り除かれ、これらに依存するタスクはデータと進捗を保持したまま中断します。他のプラグインだけで必要な機能が揃うタスクは引き続き動作します。必要な機能が復帰すると、スケジューラーは機能不足による中断を自動的に再確認して解除します。手動の一時停止、認証情報の失効、ポリシーによる中断には、引き続き明示的な対処が必要です。

## 前提条件

1. 管理者アカウントでログインしていること。招待ゲストは利用できません。
2. バックエンドが起動しており、全体スイッチ `schedule.enabled` が有効であること。
3. アカウント専用の取得元（ブックマーク、自分の作品、フォロー新着、コレクション）や R-18 などの制限付きコンテンツでは、有効な `PHPSESSID` を含む Cookie をタスクに関連付けること。有効な Cookie がない場合、アカウント専用の取得元は中断され、匿名で空の処理を実行しません。

## 最初のスケジュールタスクを作成する

ダウンロードページの現在の設定をスナップショットとして保存することで作成します。新旧どちらのダウンロードページでも共通です。以下は「作者の新作を定期的に追跡」する例です。

1. ダウンロードページを開いて「User モード」に切り替え、作者のホームのリンクまたは数値 ID を入力します。例の `https://www.pixiv.net/users/123456` は実際の作者 ID に置き換えてください。
2. 「ダウンロード設定」を展開し、必要に応じて設定します。
   - **ファイル名テンプレート**：デフォルトは `{artwork_id}_p{page}`。
   - **コレクション**、**最大同時実行数**、**作品間の間隔**（ミリ秒、例：`1000`。間隔を設けても取得先の制限を回避できる保証はありません）。
   - **削除済みの作品の再ダウンロードを許可**：ギャラリーから削除した作品には[削除マーク](/ja/gallery#作品を削除する)が残り、デフォルトではスキップします。選択すると各回で自動的に再ダウンロードします。この設定はスナップショットに保存され、旧バージョンのタスクを更新した場合は未選択で補われます。
3. 「追加の絞り込み」を展開し、年齢区分、AI の除外、タグ条件を必要に応じて設定します。
4. ページ下部の「スケジュールタスクとして保存」カードに移動します。
   - **タスク名**を入力します。
   - **実行方式**として、固定間隔（例：`60` 分ごと）または 6 フィールドの Cron 式（毎日 03:00 なら `0 0 3 * * *`）を選びます。
   - 必要に応じて[初回取得上限](#初回取得上限)と[個別のプロキシ・cookie](#個別のプロキシ・cookie)を設定します。
   - 「タスクを作成」をクリックします。
5. 「スケジュールタスク」一覧でスナップショットを確認し、まず「今すぐ実行」を 1 回試します。キューの成功、スキップ、失敗の理由を確認し、次回の実行時刻を確かめます。タスクの作成後にプロキシや Cookie の保存だけが失敗した場合は、そのタスクで設定を続け、重複作成しないでください。

## Cron 式の形式

Spring の 6 フィールド形式を使い、最初の項目は「秒」です。

```text
秒  分  時  日  月  曜日
0   0   3   *   *   *   毎日 03:00:00
0   30  8   *   *   1   毎週月曜 08:30:00
0   0   */6 *   *   *   6 時間ごと
0   0   9   1   *   *   毎月 1 日 09:00:00
```

| 項目 | 範囲 | よく使う記号 |
| --- | --- | --- |
| 秒 / 分 | `0–59` | `*` 毎秒・毎分、`/n` n 秒・分ごと |
| 時 | `0–23` | `*` 毎時、`/n` n 時間ごと |
| 日 | `1–31` | `*` 毎日 |
| 月 | `1–12` | `*` 毎月 |
| 曜日 | `0–7` | `0` または `7` は日曜、`*` は毎日 |

## 取得元ごとの動作

| 取得元 | 実行方式 |
| --- | --- |
| 作者の新作（User モード） / 自分の作品 | 初回は条件に合う未ダウンロード作品を取得。以降は**ウォーターマークによる差分取得**を行い、前回処理した最新作品に到達するまで走査 |
| 作者のリクエスト作品（User の「リクエスト」/ クイック取得の「自分のリクエスト」） | 毎回、完成済みで公開されたリクエスト作品を列挙し、通常のイラスト経路でダウンロード。ダウンロード済みはスキップ。順序の単調性が保証されないためウォーターマークは使用しない |
| キーワード検索（Search モード） | 選択したページ範囲を取得。「最新」順で終了ページが `-1` の場合はウォーターマークによる差分取得を使用 |
| 漫画・小説シリーズ（シリーズモード） | 毎回シリーズの章一覧を確認し、ダウンロード済みをスキップして新しい章を補完 |
| 自分のブックマーク / フォロー新着 / コレクション | [クイック取得](/ja/quick-access)で対象の取得元を展開して作成。コレクションではイラストと小説を両方ダウンロード。編集時の取得元は読み取り専用で、変更には削除して再作成が必要 |

## 初回取得上限

過去の作品が多い取得元では「初回取得上限」を設定できます。`0` は件数制限なしです。

- **初回だけの上限**（作者の新作、フォロー中ユーザーの新作、「最新順 + 終了ページ `-1`」の検索）：初回に最新 N 件まで取得してウォーターマークを進めます。以降はその後に公開された新作だけを追跡し、それより古い作品は追加取得しません。
- **毎回の上限**（自分のブックマーク、コレクション、リクエスト作品、最新順以外の「終了ページ `-1`」検索）：単調な新着順ではないため、毎回最大 N 件の新しい作品を受け付け、複数回に分けて過去の作品を処理します。
- **固定ページ範囲の検索**：上限は毎回適用されます。`0` は件数制限をなくすだけで、選択したページ範囲は広がりません。1 ページ目だけを選んだ場合、次のページには自動で進みません。

!> ダウンロード済み作品のスキップは受付件数を消費しませんが、追加の絞り込みによるスキップは消費します。ページ数無制限や複数ページの取得元で `0` を指定すると、大量の過去作品を取得する可能性があるため、保存前に確認が表示されます。

## 既存タスクを管理する

「スケジュールタスク」一覧のカード右上のランプは、現在の状態を表します。

| ランプ | 意味 |
| --- | --- |
| 灰色 | 次回の実行待ち、無効、または手動で一時停止中 |
| 緑色 | 実行中、または前回成功 |
| 黄色 | 複数のタスクの期限が同時に来たため実行順を待機中 |
| 赤色 | 実行失敗、Cookie 失効、中断、または過剰アクセスによる一時停止。カードをクリックして理由を確認 |

カードでは、**今すぐ実行**、**個別のプロキシ・cookie**、定期実行の**有効 / 無効**、**手動で一時停止 / 再開**、**スナップショットを表示**、**編集**、**再試行待ち**（失敗して再試行を待つ作品の確認）、**削除**（ダウンロード済みファイルには影響しない）を操作できます。

## 個別のプロキシ・cookie

シングルユーザーモードでタスクを作成する際、有効な Cookie が保存済みで個別設定を選んでいなければ、現在の Cookie が自動的にタスクへ関連付けられます。作成時、またはタスクカードの「個別のプロキシ・cookie」ダイアログで独立した設定もできます。

- **個別のプロキシを設定**：`127.0.0.1:7890` などの `host:port` を入力すると、そのタスクのすべての Pixiv リクエスト（検出、メタデータ、画像・小説のダウンロード、過剰アクセスのメッセージ確認）がその HTTP プロキシを経由します。未選択なら全体のプロキシを使います。
- **個別の cookie を設定**：`PHPSESSID` を含む Cookie を貼り付けるか、「現在保存されている cookie を使用」で入力します。関連付け済みの Cookie は再表示されません。空欄のまま保存すると維持され、新しい値を入力すると置き換わります。

有効なチェックを外して保存すると、対応する設定が解除されます。プロキシは全体設定に戻り、Cookie を解除すると匿名の「制限モード」になり、R-18 を取得できず、アカウント専用の取得元も実行できません。Cookie の失効を検出するとタスクは自動的に一時停止して「ログイン状態が失効」と表示されます。新しい Cookie を取得して関連付け直すと再開します。同じ失効済み Cookie の再送信は拒否されます。

## 過剰アクセスによる一時停止と通知

Pixiv からの「過剰アクセス」のサイト内メッセージを検出すると、**同じアカウントのすべてのスケジュールタスク**を自動停止します。一覧上部のバナーには「リスクを無視して今すぐ再開」と「N 分後に再開」が表示されます。最小値・デフォルトとも 60 分で、待機後の再開を推奨します。

デスクトップの「設定 → メール / SMTP」または「設定 → プッシュ通知」（Bark、DingTalk、Telegram、Feishu、WeCom、PushPlus、Server 酱、Webhook に対応）を設定すると、次のイベントで通知を並行送信します。本文に Cookie やパスワードは含めません。

- **過剰アクセスによる一時停止**：影響を受けるタスク名、ID、件数、警告時刻を記載。
- **ログイン状態の失効 / 連続失敗による遮断**：タスク名、ID、種類、実行ルール、次回実行時刻を記載。
- **失敗作品の再試行上限到達**：該当作品の Pixiv リンクも記載。

## トラブルシューティングと関連設定

タスクが動かない場合は、バックエンドのプロセス、全体スイッチ、タスクの有効状態、カードに表示される中断理由の順に確認してください。有効な Cookie への変更で解除されるのは認証情報による中断だけで、他の理由による中断は自動解除されません。ダウンロードページの全体 Cookie を消去しても、既存タスクの独立した認証情報は自動解除されません。タスクの取得元や絞り込み条件を編集すると差分取得のウォーターマークがリセットされ、次回は再走査してローカルのダウンロード記録で重複判定します。

| 設定項目（`config/config.yaml`） | デフォルト | 説明 |
| --- | --- | --- |
| `schedule.enabled` | `true` | スケジュールタスク全体のスイッチ |
| `schedule.tick-interval-ms` | `60000` | 実行時刻が来たタスクの確認間隔。ミリ秒単位、変更後は再起動が必要 |
| `schedule.max-tasks` | `100` | 作成できるタスクの上限 |
| `schedule.inbox-check-every` | `500` | ダウンロード成功件数がこの数に達するごとに過剰アクセスのメッセージを確認 |
| `schedule.auth-failure-circuit-breaker` | `5` | 連続した検出失敗により遮断・中断するまでの回数 |
| `schedule.pending-max-attempts` | `5` | 失敗した作品の自動再試行回数の上限 |
| `schedule.overuse-defer-default-minutes` | `60` | 過剰アクセス停止後のデフォルト待機時間。分単位、最小 60 |

設定全体は[設定リファレンス](/ja/configuration)を参照してください。
