# スケジュールタスク

スケジュールタスクは、指定間隔で新作を自動検出・ダウンロードします。作者の新作、検索結果、マンガ / 小説シリーズ、ブックマーク、コレクションを継続的に同期できます。

?> スケジュールタスクは管理者専用です。ゲストは管理者に依頼してください。

## 前提

1. 管理者としてログインしている
2. `PHPSESSID` を含む Cookie が設定されている

Cookie のないタスクは制限モードとなり、全年齢の公開作品だけを取得します。R-18、非公開ブックマーク、フォロー一覧には Cookie が必要です。

## 初めて作成する

タスクは専用の空フォームからではなく、現在のダウンロード設定を保存して作成します。

### 例：作者をフォローする

1. `pixiv-batch.html` の「**👤 ユーザーモード**」を開く
2. `https://www.pixiv.net/users/123456` または作者 ID を入力
3. 必要ならファイル名、コレクション、最大同時実行数、作品間隔、追加フィルターを設定
4. ページ下部の「**⏰ スケジュールタスクとして保存**」を開く
5. タスク名を入力する
6. 固定間隔（例：60 分ごと）または Cron を選ぶ
7. 必要なら初回取得上限、専用プロキシ、専用 Cookie を設定
8. 「**タスクを作成**」をクリックする

作成後は「⏰ スケジュール」タブで確認できます。削除済み作品を再取得したい場合は「削除済み作品の再ダウンロードを許可」を有効にします。

## Cron 形式

Spring の 6 フィールド形式（秒を含む）です。

```text
秒  分  時  日  月  曜日
0   0   3   *   *   *   → 毎日 03:00:00
0   30  8   *   *   1   → 毎週月曜 08:30:00
0   0   */6 *   *   *   → 6 時間ごと
0   0   9   1   *   *   → 毎月 1 日 09:00
```

秒 0〜59、分 0〜59、時 0〜23、日 1〜31、月 1〜12、曜日 0〜7（0 / 7 は日曜）です。`*` はすべて、`/n` は n 間隔を意味します。

## ソース種別

### 作者の新作

初回は条件に一致する未取得作品を探し、後続回は前回の位置を示すウォーターマークから新作だけを検出します。初回だけ大量取得される場合があります。

### 作者のリクエスト作品

完了済み・公開のリクエスト納品物を毎回全件確認し、未取得分を追加します。順序が安定しないためウォーターマークは使わず、初回取得上限は各回の上限として動作します。

### 検索キーワード

設定したページ数の検索結果を取得します。「新着順」かつ終了ページ `-1` ならウォーターマークで新作だけを追跡します。

### マンガ / 小説シリーズ

シリーズの章を毎回確認し、取得済みをスキップして新しい章を追加します。

### クイック取得から作成したタスク

ブックマーク、自分の作品、フォロー中ユーザーの新着、フォロー中作者、コレクションを展開してから保存できます。ブックマークとコレクションではイラストと小説の両方を取得します。これらは非公開データのため、Cookie がなければ「ログイン期限切れ」となって停止します。編集時のソースは読み取り専用で、変更するには削除して作り直します。

## 初回取得上限

大量の履歴を一度に取得したくない場合は上限を指定します。`0` は上限なしです。作者の新作、フォロー新着、「新着順 + -1」の検索では初回だけ上限が適用され、以降はウォーターマークで新作を追跡します。ブックマーク、コレクション、リクエスト作品、その他の検索では各回の上限として使われます。シリーズと固定ページ検索では通常この項目は不要です。

## 既存タスクの管理

「**⏰ スケジュール**」タブで一覧を開きます。

| 表示 | 状態 |
|------|------|
| 🔘 灰 | 待機 / 無効 / 一時停止 |
| 🟢 緑 | 実行中 / 最終成功 |
| 🟡 黄 | キュー待ち |
| 🔴 赤 | 失敗 / Cookie 期限切れ / 中断 / 過負荷停止 |

各カードから、今すぐ実行、専用プロキシ / Cookie の変更、有効化 / 無効化、一時停止 / 再開、保存時のスナップショット確認、編集、保留中の再試行確認、削除を実行できます。タスクを削除しても取得済みファイルは削除されません。

## 専用プロキシ / Cookie

作成時に保存済み Cookie があり、「専用 Cookie」を選ばなかったソロモードのタスクは、現在の Cookie に自動バインドされます。

- **専用プロキシ**：`host:port` を指定すると、そのタスクの検出、メタデータ、画像 / 小説取得をすべて指定プロキシ経由にする
- **専用 Cookie**：`PHPSESSID` を含む Cookie を貼り付けるか、「現在の Cookie を使用」をクリックする

設定を解除するとプロキシはグローバル設定へ戻り、Cookie を解除したタスクは制限モードになります。Cookie が期限切れになるとタスクは停止して通知されるため、再ログイン後にダイアログから新しい Cookie を再登録してください。

## 過負荷による一時停止

Pixiv の受信箱に過剰アクセス警告が届くと、同じアカウントのスケジュールタスクをすべて一時停止します。「リスクを無視して再開」または「N 分後に再開」を選べます。後者（最低 60 分）を推奨します。

## 通知

Cookie 期限切れ、過負荷警告、サーキットブレーカー停止、失敗作品の再試行上限到達時に、設定済みのメール / プッシュ（Bark、DingTalk、Telegram、Feishu、WeCom、PushPlus、ServerChan、Webhook）へ通知します。通知に Cookie、パスワード、認証情報は含まれません。メールは GUI の「設定 → Mail / SMTP」、プッシュは「設定 → Push」で設定します。

## 関連設定

GUI の「設定 → スケジュールタスク」、または `config.yaml` の `schedule.*` で設定します。

| 設定 | 既定値 | 説明 |
|---------|---------|---------|
| `schedule.enabled` | `true` | マスター切り替え |
| `schedule.tick-interval-ms` | `60000` | 期限確認間隔。変更には再起動が必要 |
| `schedule.max-tasks` | `100` | 作成できる最大数 |
| `schedule.inbox-check-every` | `500` | 過負荷受信箱を確認する成功作品数 |
| `schedule.auth-failure-circuit-breaker` | `5` | 連続失敗で停止する回数 |
| `schedule.pending-max-attempts` | `5` | 失敗作品の自動再試行回数 |
| `schedule.overuse-defer-default-minutes` | `60` | 過負荷後の再開待ち時間 |

詳しくは [設定リファレンス](/ja/configuration) を参照してください。
