# スケジュールタスク

バックエンドの起動中、一定間隔または Cron で作品を発見・ダウンロードします。作成時に取得元、フィルター、保存設定をコピーして保持するため、ダウンロード画面の設定を後から変えても既存タスクは変わりません。ブラウザーを閉じても実行しますが、バックエンドを停止すると実行しません。

スケジューラーと管理 API はアプリのホストが提供します。ダウンロードワークベンチを無効にすると、その画面、Pixiv の取得元、イラスト実行機能が利用できなくなります。これらに依存するタスクはデータと進捗を保持して中断し、他のプラグインだけで実行できるタスクは継続します。取得元や実行機能の不在・停止による中断は、必要な機能がすべて戻るとスケジューラーが再確認して再開します。手動、認証情報、ポリシーによる中断には明示的な操作が必要です。

管理者ログイン、起動中のバックエンド、スケジュールの全体スイッチが必要です。アカウント専用の取得元や制限付きコンテンツには、`PHPSESSID` を含む有効な Cookie をタスクに関連付けてください。公開の取得元は条件に応じて匿名で動作しますが、アカウント専用の取得元は Cookie がなければ停止します。

## 最初のタスクを作る

作者の新作を定期取得する例です。両方のダウンロード画面のレイアウトで同じタスク設定を使えます。

1. 「User モード」で作者の URL または ID を入力します。例：`https://www.pixiv.net/users/123456`。ID は実際の作者に置き換えます。
2. ダウンロード設定でファイル名、コレクション、同時実行数、作品間隔を設定します。既定のファイル名は `{artwork_id}_p{page}`、同時実行数は全体設定に従います。間隔 `1000` は 1 秒ですが、上流のアクセス制限を防ぐ保証はありません。
3. 必要なら年齢区分、AI 除外、タグなどのフィルターを設定します。削除済み作品は既定でスキップします。再取得を許可する場合は、その設定もタスクに保存されます。古い設定にこの項目がない場合は、起動時に無効として補います。
4. 画面下部のスケジュール保存欄で名前を入力し、固定間隔（例：60 分）または Cron（毎日 3 時なら `0 0 3 * * *`）を選びます。
5. 必要に応じて初回取得上限、個別の HTTP プロキシと Cookie を設定し、作成します。
6. スケジュール一覧で保存した設定を確認し、まず手動実行します。キューの完了・スキップ・失敗を確認してから、次回実行時刻を確認してください。

作成は成功したもののプロキシや Cookie の保存に失敗した場合、同じタスクを作り直さず、そのタスクの設定を完了してください。

## Cron の形式

Spring の 6 フィールド形式で、先頭に秒があります。

```text
秒 分 時 日 月 曜日
0 0 3 * * *       毎日 03:00
0 30 8 * * 1      月曜日 08:30
0 0 */6 * * *     6 時間ごと
0 0 9 1 * *       毎月 1 日 09:00
```

秒・分は `0`～`59`、時は `0`～`23`、日は `1`～`31`、月は `1`～`12`、曜日は `0`～`7`（日曜は `0` / `7`）です。`*` はすべて、`/n` はその間隔を指定します。

## 取得元ごとの動作

| 取得元 | 動作 |
|---|---|
| 作者の新作 / 自分の作品 | 初回は未取得の対象を発見し、以後は前回の最新位置まで走査して新作を取得 |
| 公開済みのリクエスト作品 | 毎回一覧を取得し、取得済みを除外。順序が単調とは限らないため増分位置を使わない |
| 検索 | 設定したページを取得。「新しい順」かつ終了ページ `-1` の場合は増分位置を使う |
| 漫画・小説シリーズ | 毎回メンバーを確認し、未取得の章を取得 |
| 自分のブックマーク | 公開・非公開、イラスト・小説の選択した範囲から未取得作品を取得 |
| フォロー中の新着 | フォロー中の作者の新しいイラスト・漫画・うごイラを取得 |
| Pixiv のコレクション | イラストと小説の両方を確認し、未取得作品を取得 |

ブックマーク、自分の作品、フォロー中の新着、コレクションは[クイック取得](/ja/quick-access)で対象を展開して保存します。これらのアカウント専用取得元には Cookie が必要です。ない場合は認証失効として停止し、匿名の空実行はしません。編集時の取得元は読み取り専用で、変える場合は削除して作り直します。

リクエスト作品は通常のイラストとしてダウンロード・命名・重複判定を行います。

## 初回取得上限と毎回の上限

`0` は件数の上限なしです。取得元によって作用が異なります。

- 作者の新作、フォロー中の新着、「新しい順 + 終了ページ -1」の検索：初回だけ最新 N 件に制限し、増分位置を最新へ進めます。その後は新作だけを取得し、初回に除外した古い作品は補完しません。
- ブックマーク、コレクション、リクエスト作品、最新順以外の終了ページ `-1` の検索：毎回最大 N 件の新しい対象を受け入れ、複数回に分けて未取得分を処理します。
- 固定ページ数の検索：件数制限は毎回適用します。`0` でも選択したページ範囲を広げません。最初の 1 ページだけなら、後のページは自動取得しません。シリーズもそのメンバー範囲に従います。

取得済みのスキップは受け入れ件数を消費しませんが、フィルターによるスキップは消費します。ページ数無制限や複数ページの取得元で上限 `0` を指定すると、大量の過去作品を取得する可能性があるため保存前に確認します。最初の 1 ページだけの検索には同じ全件確認はありません。

## 状態と管理操作

スケジュール一覧の状態表示を確認します。

| 色 | 状態 |
|---|---|
| 灰 | 待機、無効、手動停止 |
| 緑 | 実行中、前回成功 |
| 黄 | 実行順の待機 |
| 赤 | 失敗、Cookie 失効、中断、過剰アクセスによる停止 |

手動実行、個別プロキシ・Cookie、定期実行の有効・無効、協調的な一時停止・再開、保存した設定の確認、編集、再試行待ちの確認、削除を行えます。タスクを削除してもダウンロード済みファイルは残ります。

## タスク専用のプロキシと Cookie

作成・編集欄、または各タスクの個別設定から指定します。solo モードで作成時に有効な Cookie があり、個別指定を選ばない場合は現在の Cookie を自動で関連付けます。

個別プロキシは `host:port` 形式です。そのタスクの発見、メタデータ、画像・小説、過剰アクセスの受信箱確認を同じ HTTP プロキシに通します。無効にすると全体設定を使います。経路を変えても Pixiv のアクセス制限がなくなるわけではありません。

個別 Cookie は `PHPSESSID` を含む値を貼り付けるか、現在保存している Cookie を入力欄へ読み込みます。関連付け済みの値は表示しません。既存の関連付けがある状態で空欄のまま保存すると維持し、入力すると置き換えます。

有効なチェックを外して保存すると、確認後にその設定を解除します。プロキシは全体設定へ戻り、Cookie は匿名の制限モードになります。R-18 などは取得できず、アカウント専用の取得元は実行できません。制限モードを解除する場合は有効な Cookie を関連付けてください。

Cookie の失効を確認するとタスクは停止し、設定済みの通知を送ります。新しい有効な Cookie を関連付けると認証理由の停止を解除します。同じ失効済み Cookie の再送は拒否します。他の理由による停止は自動解除しません。

## 過剰アクセスによる停止

Pixiv からの過剰アクセス警告を検出すると、同じアカウントの全スケジュールを停止します。この保護もアカウント制限を防ぐ保証はありません。

一覧上部のバナーから、警告を承認して即時再開するか、時間を置いて再開するかを選べます。待機は最低 60 分、既定も 60 分です。再開はリクエストを再送するため、警告を確認してから判断してください。

## 通知

Cookie 失効、過剰アクセス、連続失敗による停止、作品の再試行上限到達を通知します。設定済みのメールとプッシュ（Bark、DingTalk、Telegram、Feishu、WeCom、PushPlus、ServerChan、Webhook）へ並行して送ります。

過剰アクセスには対象タスク名・ID・件数・警告時刻、認証失効や連続失敗にはタスク名・ID・種類・実行条件・次回予定、再試行上限にはさらに作品の Pixiv リンクを含めます。Cookie やパスワードは本文に含めません。

GUI のメール / SMTP とプッシュ設定で、それぞれの接続先を設定してください。未設定の経路は通知をスキップします。各設定画面のテストボタンで表示を確認できます。

## 動かない場合

バックエンド、全体スイッチ、タスクの有効状態を確認し、停止理由に対応してください。認証は Cookie の再関連付け、過剰アクセスはバナー、機能不足は対応プラグインの復旧、作品操作待ちは各作品の処理方針を確認します。

取得元やフィルターの定義を編集すると増分位置を解除し、次回は発見し直してローカルの取得記録で重複判定します。タスクの Cookie は独立した関連付けです。ダウンロード画面の Cookie を消しても全タスクの認証は解除されないため、タスク側で明示的に解除してください。

## 関連設定

GUI のスケジュール設定、または `config/config.yaml` の `schedule.*` で指定します。

| キー | 用途 | 既定 |
|---|---|---|
| `schedule.enabled` | 全体スイッチ | `true` |
| `schedule.tick-interval-ms` | 期限確認の間隔（ミリ秒）。変更後は再起動 | `60000` |
| `schedule.max-tasks` | 作成できる最大タスク数 | `100` |
| `schedule.inbox-check-every` | 警告確認までのダウンロード作品数 | `500` |
| `schedule.auth-failure-circuit-breaker` | 連続失敗による停止のしきい値 | `5` |
| `schedule.pending-max-attempts` | 失敗作品の最大自動再試行数 | `5` |
| `schedule.overuse-defer-default-minutes` | 過剰アクセス後の既定待機分数（最低 60） | `60` |

詳細は[設定リファレンス](/ja/configuration)を参照してください。
