# 小説と読み上げ

`novel` プラグインを有効にすると、単一小説や小説シリーズ全体を TXT、HTML、EPUB で保存し、ローカルの小説ギャラリーで読書、全文検索、翻訳、読み上げを利用できます。翻訳には `translation` プラグイン、AI による複数キャラクターの読み上げには `ai` と `tts` の設定が必要です。以下の ID は形式の例です。アクセス権のある実際の作品・シリーズに置き換えてください。

## 小説とシリーズをダウンロードする

### 単一小説

1. `http://localhost:6999/pixiv-batch.html` を開き、「単一作品の一括インポート」を選びます。
2. 小説のリンクを貼り付けます。

   ```text
   https://www.pixiv.net/novel/show.php?id=12345678
   ```

   数字の ID だけを入力する場合は、その上に独立した行で `novel:` のセクション見出しを書きます。

   ```text
   novel:
   12345678
   ```

3. ダウンロード設定で保存形式（TXT / HTML / EPUB）を選び、キューに追加してダウンロードを開始します。自分の小説やブックマークは[クイック取得](/ja/quick-access)から直接追加できます。

### 小説シリーズと EPUB 合本

1. ダウンロードページで「シリーズモード」を選び、シリーズのリンクを貼り付けて「解析とプレビュー」をクリックします。

   ```text
   https://www.pixiv.net/novel/series/123456
   ```

2. 「すべてキューに追加」、または一部の章を選択して追加し、ダウンロードを開始します。

| 形式 | 特徴 |
| --- | --- |
| TXT | 書式を持たないプレーンテキスト |
| HTML | ルビや見出しなど元の書式を保持し、ブラウザーで直接開ける |
| EPUB | EPUB3 に準拠。階層付きの章目次、埋め込み表紙、書籍メタデータ（紹介文、タグ、出典リンク）を含む |

- **ダウンロード時に合本を生成**：ダウンロード設定で「シリーズ合本を生成」を選び、形式を指定します（EPUB を推奨）。ファイルは `novel-series-{seriesId}/{シリーズタイトル}.epub`、翻訳合本は `{シリーズタイトル}_{言語コード}@{エンジン}.epub` に保存されます。
- **シリーズ目次ページでいつでも生成**：`pixiv-series.html?type=novel&seriesId=...` を開き、「合本をダウンロード」で読む言語（原文または保存済みの訳文）と翻訳エンジンを個別に選ぶと、現在のデータベースの状態から即座に EPUB を生成してダウンロードできます。翻訳言語を選んだ場合、未翻訳の章は原文になります。全体の言語を揃えるには、先に「シリーズ全体を翻訳」を完了してください。

## ローカルでの読書と全文検索

小説ギャラリーにアクセスします。

```text
http://localhost:6999/pixiv-novel-gallery.html
```

タイトル、作者、シリーズ、タグによる絞り込みと、ローカル索引を使った**本文の全文検索**に対応します。カードをクリックすると `pixiv-novel.html?id=<id>` で本文を読み、シリーズ目次を確認して前後の章に移動できます。

閲覧ページのツールバーには、戻る、読み上げ、翻訳、お気に入りの操作を表示します。「その他の操作」から表示言語や外観を変更したり、Pixiv の原作を開いたりできます。管理者はこのメニューから小説をエクスポートまたは削除することもできます。削除前には確認が必要です。

管理者は閲覧ページの「その他の操作」でエクスポートを選び、読む言語と翻訳エンジンを個別に指定して、単篇の EPUB を直接ダウンロードできます。アーカイブタスクや一時アーカイブは作成せず、ダウンロード済みの元ファイルも変更しません。

一括エクスポートでは、小説ギャラリーで作品を選択します。言語とエンジンを個別に選べるほか、グループ分けと ZIP の設定も利用できます。訳文は既存のローカル文書と同じ形式で生成し、ローカル文書がない場合は EPUB を生成します。選択したすべての小説に保存済みの訳文がある組み合わせだけを表示し、未翻訳の項目は原文を使います。

## 読み上げ（単一音声 TTS）

小説の閲覧ページで「読み上げ」をクリックすると、本文を段落順に読み上げ、現在の段落の強調表示、ページのスクロール、読書位置の保存を自動で行います。

| 音声エンジン | 説明 |
| --- | --- |
| ブラウザーエンジン（デフォルト） | ブラウザー・システムの音声サービスを使用。利用できる声と通信の有無はブラウザーと OS に依存 |
| オンラインエンジン（Edge ニューラル音声） | バックエンドのプロキシ経由で Microsoft のオンライン TTS を使用。ネット接続が必要 |

## AI による複数キャラクターの読み上げ（管理者）

デスクトップ設定の「AI モデル」で「テキストモデル」（OpenAI 互換 LLM）と「TTS モデル」（ローカルの VoxCPM / CosyVoice、またはクラウド TTS）を両方設定して有効にすると、閲覧ページで「複数キャラクターの読み上げ」を使えます。片方でも無効なら「読み上げ」のエンジン一覧に表示されません。まずモデルと TTS に接続できることを確認してください。分析失敗時はテキストモデルの応答、合成失敗時は TTS エンジンと参照音声の設定を確認します。

- **文ごとの話者判定と再生**：LLM が章全体の各文をナレーターと登場人物に割り当て、固定したキャラクターの声で合成します。順番に再生しながら次の文を先読みし、再生バーには現在の話者と台詞を表示します。
- **ナレーターとキャラクターの声の固定**：初回分析前にナレーターの基本的な声を試聴して固定できます（デフォルトは温かみのある女性の声）。キャラクターパネルでは性別、年齢、英語の声の特徴を確認・変更でき、保存すると固定されます。以降の章で AI に上書きされず、変更は次の音声合成から即座に反映されます。
- **キャラクターの参照音声によるクローン**：ナレーターを含む任意のキャラクター用に標準の参照音声を生成するか、WAV / MP3 をアップロードできます。文字起こしも添付でき、文や章をまたいで声を統一しつつ感情の変化を保ちます。参照音声を変更すると、キャッシュした音声は新しい声で自動的に再生成されます。設定でクローンを無効にしたり、生成上限を調整したりできます。
- **声の矛盾への対処**：本文中の新しい情報が固定済みの声と明らかに矛盾する場合、パネルに矛盾が表示され、「提案を採用 / 現在の設定を維持 / 書き換え」を選べます。
- **分割文字数とキャッシュ**：`0`（デフォルト）は章全体を 1 回のリクエストで分析します。長すぎる本文は拒否され、範囲を小さくするよう案内されます。正の整数を指定すると、段落を約その文字数までまとめて分割分析します。分析結果はローカルにキャッシュされ、再生のたびに再分析する必要はありません。必要な場合は「再分析」を実行できます。

## 翻訳エンジン（管理者）

`translation` プラグインをインストールして有効にします。依存関係の `novel-translation-contract` もインストールされます。デスクトップ設定の「翻訳」でエンジンを選び、保存後の案内に従ってバックエンドを再起動してください。閲覧ページでの手動翻訳、シリーズ翻訳、ダウンロード後の自動翻訳は同じ選択エンジンを使います。

| エンジン | 設定と制限 |
| --- | --- |
| AI モデル | `ai` プラグインに保存したモデル、ベースアドレス、認証情報を使用。ローカルの OpenAI 互換サービスにも対応 |
| 有道 | 有道智雲のテキスト翻訳 API のアプリケーション ID とアプリケーション秘密キーを指定。有道辞書クライアントのアカウントは使用不可 |
| LibreTranslate | 自前のサービスのベースアドレス（`/translate` を含めない）と任意の API Key を指定。サービスと言語モデルは自分で用意する必要がある |

有道と LibreTranslate は各エンジンのリクエスト設定で長文を分割し、短い段落をまとめて送信します。改行と画像・改ページ・ジャンプの Pixiv 記法は保持します。文末や空白での分割を優先し、上限を超える長い単語はサロゲートペアを壊さず Unicode コードポイント単位で分割します。タイトルと本文は別々に送信し、AI の用語対応表は使用・学習しません。

デスクトップ設定の「翻訳」には、選択中のエンジンのリクエスト設定だけが表示されます。以下はクライアントの既定値です。キーには `translation.youdao.` または `translation.libretranslate.` を付けます。保存後にバックエンドを再起動してください。

| パラメーター | 有道の既定値 | LibreTranslate の既定値 | 設定範囲 |
| --- | --- | --- | --- |
| `request-chars` | 5000 | 5000 | Youdao: 1–5000; LibreTranslate: 1–1,000,000 |
| `batch-size` | 50 | 10 | 1–100 |
| `request-interval-ms` | 1000 ms | 0 ms | 0–60,000 ms |
| `request-concurrency` | 1 | 1 | 1–32 |
| `max-retries` | 3 | 3 | 0–10 |
| `read-timeout-seconds` | 120 s | 120 s | 1–3600 s |
| `use-proxy` | false | false | true / false |


文字数は各テキストとバッチ合計の両方を制限します。有道の公式上限は 1 クエリ 5000 文字です。LibreTranslate の文字数・バッチ数・呼び出し枠はサーバー設定や API キーに依存し、5000 は本クライアントの設定値です。50/10 件のバッチ数と有道の 1000 ミリ秒間隔もアカウントの割り当てを示すものではありません。LibreTranslate はバッチ内のテキスト数だけ呼び出し枠を消費するため、その数を掛けた間隔で送信します。外部サービスではバッチ数も実際の枠に合わせてください。

手動・シリーズ・ダウンロード後の自動翻訳は、エンジンごとに同時数と送信間隔を共有します。有道の `411` / `412` または HTTP `429` の場合のみ、待機時間を延ばして現在のバッチを再試行し、`Retry-After` に従います。60 秒を超える待機は頻度制限エラーを返し、冷却中の新しいタスクも早期送信しません。認証失敗・タイムアウト・その他のエラーは自動再送しません。選択した章の内容がすべて成功してから保存し、失敗時は既存の翻訳を保持します。同じタスクを再開すると、保存済みの成功応答を再利用します。ログにはバッチ・リクエスト・再試行・翻訳済み文字数を記録し、原文・訳文・認証情報は記録しません。
- AI の認証情報は `ai`、有道と LibreTranslate の認証情報は `translation`、音声の認証情報は `tts` プラグインが管理します。

翻訳ダイアログは現在のエンジンを表示します。有道の翻訳先言語は公式の語種表から選択でき、LibreTranslate は設定先サービスの対応言語を取得します。取得に失敗した場合は再読み込みできます。AI では自由入力と用語対応表を使えます。失敗時は原因に応じた対処方法を表示します。バックエンドの英語ログには実行 ID、作品 ID、エンジン、処理段階、安全なエラーコードを記録し、本文や秘密キーは記録しません。

同じ小説・翻訳先言語でも、エンジンごとの訳文を同時に保存できます。上書きとスキップは現在のエンジンの訳文にだけ適用されます。閲覧・シリーズページでは、同じグループ内の「読む言語」と「翻訳エンジン」を個別に選択します。保存済みの訳文がある組み合わせだけを選べ、原文を選ぶとエンジンは「対象外」になります。合本のダウンロードと小説のエクスポートでも言語とエンジンを個別に選択し、読み上げも選択中の訳文を使います。エンジン情報のない既存の訳文は「提供元不明」として残り、合本のファイル名も従来の言語のみの接尾辞を維持します。AI モデルはすべて `ai` というエンジン識別子を共有するため、モデルを切り替えても別の訳文版は作成されません。

翻訳の進捗はバックエンドに保存されます。ページを閉じたり非表示にしたりしても実行は続きます。「翻訳」を再度開くと既存タスクを確認でき、一時停止・再開・キャンセルを選べます。キャンセルは実行中のリクエストが終了するまで待ち、成功したチェックポイントと完了済みの章を保持します。タスクの破棄には再確認が必要で、タスクとチェックポイントだけを削除し、公開済みの訳文は残します。

バックエンドの再起動後、未完了タスクは一時停止し、自動で翻訳サービスを呼び出しません。再開時には原文、既存の訳文、エンジンのアドレス、モデル、分割設定を確認します。変更されている場合は設定を戻すか、タスクを破棄して翻訳し直してください。AI の用語コンテキストも保存します。途中で打ち切られたモデル応答を完成した訳文として公開することはありません。タスクを破棄して分割を小さくした新規タスクを作成できます。モデルサービスが対応していれば、サービス側の出力制限を調整してから再開することもできます。

AI 応答で必須項目が欠けている、翻訳先と異なる言語が指定されている、または言語コードが無効な場合、タスクは一時停止します。再開すると無効な部分を再要求し、ほかの保存済みの成功応答を再利用します。

タスクは最大 256 件、チェックポイントは合計 256 Mi UTF-16 コード単位まで保持します。新規タスク作成時に、完了から 7 日を超えた記録を削除し、容量が満杯なら最も古い完了記録を削除します。一時停止・キャンセルしたタスクは手動で破棄します。外部サービスで処理済みでも応答がローカルに保存されていなければ、再開時に同じリクエストを再送し、再度課金される可能性があります。

## AI 翻訳と用語対応表（管理者）

テキストモデルを設定して有効にした後、小説の閲覧ページまたはシリーズ目次ページで「翻訳」をクリックします。

- **対象言語**：デフォルトでは現在の画面言語が入力され、任意の自然言語名に変更できます。
- **分割文字数**：`0` は設定の `translation.ai-segment-size` を使用します（既定値 `0` は章全体）。正の値はその長さを目安に段落をまとめます。UTF-16 コード単位の段落分割目標であり、厳密なリクエスト上限ではないため、長い単一段落は超えることがあります。コンテキストと出力トークンの上限は AI モデル設定で管理します。文字数からトークン数への固定換算はできません。通常の翻訳では `0` はサービスの文字数設定を使用し、正の値は区切りをさらに小さくする場合に使います。
- **既存の翻訳の扱い**：「上書きして再翻訳」または「スキップ」を選べます。
- **用語対応表**：「原語 ↔ 各言語の訳語」を保存し、固有名詞の訳を揃えます。シリーズ作品はデフォルトで同名の表を共有し、単独作品はそれぞれの表を使います。表を使わない、既存の表に切り替える、新規作成・編集することもできます。AI が翻訳中に見つけた新しい固有名詞は、選択中の表に自動追加され、以降の章で再利用されます。モデルが対応表どおりに訳さない場合もあるため、翻訳結果を確認してください。
- **内容の言語切り替え**：閲覧・シリーズページの「読む言語」と「翻訳エンジン」で、画面言語とは独立して原文と既存の翻訳を切り替えられます。本文、章タイトル、シリーズ名、翻訳 EPUB のタイトルが連動し、未翻訳の項目は原文になります。読み上げも選択中の言語を使います。章タイトルと本文は同じ AI リクエストで翻訳し、シリーズ名の翻訳には同じ言語の翻訳済み章タイトルの対と用語対応表を添えます。
- **シリーズ全体を翻訳**：シリーズページで章の順に一括翻訳できます。バックグラウンドに隠すことやキャンセルに対応し、キャンセルしても翻訳済みの章は残ります。完了後に `{シリーズタイトル}_{言語コード}@{エンジン}.epub` を生成します。「翻訳済みをスキップ」を選ぶと、最初に軽量なリクエストを 1 回送り、対象言語名を正規の言語コードに解決したうえで、既存の翻訳がある章をそのままスキップします。今回の翻訳では、選択した言語とエンジンの合本だけを更新します。
- **ダウンロード後の自動翻訳**：ダウンロードページまたはスケジュールタスクの「小説設定」で「新規ダウンロード小説を自動翻訳」を選び、対象言語と分割文字数を指定します。自動翻訳は作品・シリーズのデフォルトの用語対応表を使い、シリーズの章順でバックグラウンド実行され、ダウンロードを妨げません。ダウンロード成功時点で完了と記録し、翻訳に失敗した場合は「完了（翻訳失敗）」と表示するだけで、保存済みの原文には影響しません。

## 削除、一括管理、結果の確認

管理者は閲覧ページで単一小説を削除できます。小説ギャラリーの「一括管理」では、絞り込み結果の全選択、ZIP の一括エクスポート、コレクションへの追加、一括削除ができます。エクスポート後の元ファイル削除も選べ、進捗はサイドバーの「タスク一覧」で確認できます。プログラム管理下のファイルを削除すると画面からは元に戻せませんが、[削除マーク](/ja/gallery#作品を削除する)を保持し、デフォルトでの再ダウンロードを防ぎます。[外部ダウンロードのインポート](/ja/pixiv-batch-downloader-import)で登録した読み取り専用の元ファイルは残ります。一括管理の詳しいルールは[作品ギャラリー](/ja/gallery)と同じです。

ダウンロード後は、ローカルの TXT / HTML / EPUB と小説ギャラリーの記録をそれぞれ確認してください。ディスクにファイルがあってもギャラリーに記録がない場合は、まず現在のデータベースとダウンロードディレクトリが同じインスタンスのものか確認し、再構築を試すためにデータベースを削除しないでください。
