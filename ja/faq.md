# よくある質問（FAQ）

症状に合う項目を確認してください。データベース、アカウント、ディレクトリを操作する前に、実際の作業ディレクトリを確認してバックアップを保管します。以下の `APP.jar` は実際の JAR 名に置き換え、配布物を展開したディレクトリで実行してください。

## インストールと起動

### 「Java が認識されない」と表示される

Java 17 以上を [Adoptium](https://adoptium.net/) からインストールし、ターミナルを開き直してください。必要なら `JAVA_HOME` と `PATH` を設定します。

### 起動後に文字化けする

起動時に `-Dfile.encoding=UTF-8` を付けます。

```bash
java -Dfile.encoding=UTF-8 -jar APP.jar
```

### ポート 6999 が使用中

すでに PixivDownloader が起動していないか確認し、同じデータディレクトリで重複起動しないでください。別のプログラムなら用途を確認してから停止するか、`config/config.yaml` の `server.port` を変更して再起動します。

### Windows インストーラーが失敗する

`PixivDownload.exe` を終了し、以前のインストーラーが残っていないか確認して、必要なら管理者として実行してください。

### アンインストール方法

インストーラー版はインストーラーまたは Windows の「設定 → アプリ」からアンインストールします。JAR 版は[ストレージ](/ja/storage)に従って作品、設定、状態、データベースを保管してからプログラムを削除します。作業ディレクトリ全体を不要なプログラムとして消さないでください。

### 管理者アカウントを初期化し直したい

パスワードだけなら `--reset-password` を使います。初期化し直す必要がある場合は、停止・バックアップ後に `state/setup_config.json` を退避して `--setup` または GUI の案内を実行します。初期化状態を作り直す操作で、全設定の消去やデータベースの移行・再構築は行いません。[初回セットアップ](/ja/first-setup)を参照してください。

### サーバー / Docker が「先にセットアップしてください」と言って終了する

未初期化の headless / `--no-gui` 起動は終了コード `78` で停止します。先に初期化してから起動します。

```bash
java -Dfile.encoding=UTF-8 -jar APP.jar --setup
java -Dfile.encoding=UTF-8 -jar APP.jar --no-gui
```

### 管理者パスワードを忘れた

サービスを停止し、以前のパスワードなしで次を実行します。

```bash
java -Dfile.encoding=UTF-8 -jar APP.jar --reset-password
```

8 文字以上の新しいパスワードを確認入力します。12 文字以上を推奨します。既存セッションは無効になります。現在のパスワードが分かる場合は、それを確認する `--change-password` を使えます。

### 起動引数が認識されない

引数は厳密に検証されます。`--no-guii` のような typo、`--username admin` のように `=` がない値、単独の位置引数は拒否されます。`--help` で一覧を確認してください。`--key=value` は Spring プロパティの上書きとしてそのまま渡されます。

## プロキシとネットワーク

### プロキシを設定してもダウンロードできない

設定の保存、実際の Pixiv 作品リンクへのアクセス、バックエンドのログの失敗先とエラー、ファイアウォールを確認してください。CDN のルートへの応答だけではダウンロードできるか判断できません。GUI または CLI で保存した設定はホットリロードされます。`config/config.yaml` を直接編集した場合は再起動するか GUI で保存します。全体プロキシ、タスク専用プロキシ、プラグインの設定、ブラウザーの通信は別の経路です。[ネットワークアクセス](/ja/network-access)を確認してください。

### リバースプロキシの後ろで全ユーザーが同じ制限を受ける

`server.trusted-proxy-cidrs` に実際のプロキシ出口アドレスまたはコンテナサブネットを設定し、完全な `Forwarded`、または `X-Forwarded-For` / `X-Forwarded-Proto` / `X-Forwarded-Host` を毎回送信します。公開ネットワークやクライアントネットワークを信頼しないでください。詳しくは [設定リファレンス](/ja/configuration) を参照してください。

### LAN の別端末からアクセスできない

ファイアウォールでポート 6999 を許可し、バインド設定を確認し、`http://<サーバー IP>:6999/` を開きます。

## Cookie

### 検索結果がない

検索モードには Pixiv Cookie が必要です。内容に合う Netscape / Header 形式を選んで保存したか、期限切れでないか、プロキシが動作しているかを確認してください。

### Cookie 形式エラー

書き出した形式とページの Netscape / Header の選択を合わせます。完全な `PHPSESSID` が必要で、通常のページスクリプトでは読めない場合があります。[初回ダウンロード](/ja/first-download)に従って取得し直し、Cookie をログや Issue に含めないでください。

### 保存した Cookie を消したい

ダウンロード画面で明示的に Cookie を消去します。スケジュールは独立した認証情報を保持するため、各タスクでも関連付けを解除してください。ログアウトは保存済み認証情報の消去確認の代わりになりません。

## ダウンロード

### うごイラが再生できない

変換には FFmpeg と選択形式のエンコーダーが必要です。`ffmpeg -version` で確認し、`PATH` に追加するか GUI のステータスページからインストールしてください。

### 小説 EPUB の表紙が表示されない

プロキシと、表紙 URL のホストが `.pximg.net` で終わるかを確認し、小説を再取得してください。

### 読み上げのオンラインエンジンが失敗する

オンライン音声はバックエンドのプロキシ経由で Microsoft に接続します。ネットワーク、プロキシ、システム時計を確認してください。ハンドシェイクが 403 の場合は、古い Edge バージョンの更新と時計のずれ補正を自動で試します。続く場合は実際の時計を確認してください。ブラウザーエンジンも選べますが、通信の有無はブラウザー・OS の音声サービスによります。招待ゲストは両モードで `guest-invite.tts-request-limit-minute` の対象となり、超過時は 429 を返します。待つか管理者に設定を相談してください。管理者自身にはこの制限を適用しません。

### 一括ダウンロードの一部が失敗する

Cookie の期限、Pixiv のレート制限、プロキシの安定性、作品の削除・非公開化を確認してください。同時実行数を下げ、リクエストの間隔を広げてください。

### ファイル名テンプレートが効かない

変数を `{artwork_id}` のように波かっこで書き、対応している変数だけを使います。使用できない文字は自動除去され、新しい設定は新規ダウンロードにだけ適用されます。

### うごイラがクォータを多く消費する

マルチモードでは `multi-mode.quota.limit-image` を設定します。指定数を超える画像を含む作品は複数のクォータ単位として計算されます。

## GUI

### 「起動中」のまま進まない

10 秒を超えると待機秒数を表示します。データベース更新中の場合もあるため、長く続く場合は `log/latest.log` で移行、ポート待機、プラグイン読み込みの状態を確認してください。データとエラーを保管し、起動が遅いという理由でデータベースを削除しないでください。Java 17 以上かも確認します。

### GUI のオンライン更新に失敗する

ネットワークとプロキシを確認し、改善しなければ [Releases](https://github.com/Sywyar/PixivDownloader/releases) から手動で取得して上書きインストールします。

### エラーダイアログが文字化けする

詳細はログに記録されます。ダイアログの「ログファイルを開く」から確認してください。

## データベース

### データベースはどこにあるか

既定の SQLite は `data/pixiv_download.db` で、`-wal` / `-shm` を伴う場合があります。PostgreSQL では指定したサーバーに保存します。操作前に設定画面で現在の provider と実際の場所を確認してください。

### データベースが壊れた

アプリを停止して元データと付随ファイルを保管し、バックアップのコピーを診断します。SQLite の `PRAGMA integrity_check;` は整合性の検査だけを行い、修復しません。SQLite CLI から、元ファイルではなくバックアップのコピーを対象に実行してください。破損を確認したら検証済みバックアップからの復元を優先します。作品ディレクトリからギャラリーを戻せると考えて元データベースを削除しないでください。PostgreSQL は同製品のバックアップ・復元手順を使い、SQLite のコマンドは使えません。

### データベースを失ったら再ダウンロードされるか

再ダウンロードを防げるとは限りません。作品の識別、ページ数、パス、タグ、コレクションの関連はデータベースが基準で、既存画像だけから完全な作品と判定しません。元ファイルを保持し、対応するデータベースを復元してください。保存先変更にはパスの移行、エンジン切り替えには検査・移行を使います。データ補完ツールは既存記録の不足を補うもので、任意の作品ディレクトリの完全復元ツールではありません。

### バックアップ方法

アプリを停止し、`config/`、`state/`、`data/`、プラグイン、コレクションを含む実際の作品ディレクトリを保管します。アイコンは `data/collection_icons/` です。PostgreSQL のサーバーデータベースと外部インポート元も別途保存します。詳細は [ストレージの仕組み](/ja/storage) を参照してください。

## ユーザースクリプト

Tampermonkey が有効か、スクリプトが対象ページで有効か、`@match` と `@connect` が正しいかを確認してページを再読み込みします。オールインワンと単体版を同時に有効にするとパネルが重複するため、どちらか一方だけを使います。バックエンドに接続できない場合はサービス、solo モードのログイン、接続先アドレスと `@connect` の両方を確認してください。詳しくは[ユーザースクリプト](/ja/userscripts)を参照してください。

## セキュリティ

Pixiv へのアクセスにはユーザーの Cookie を使うため、アカウントのリスクはユーザー自身が負担します。適切な間隔と同時実行数を設定し、Pixiv の利用規約を守ってください。multi で未ログインかつ招待コードのない利用者は匿名利用者で、ダウンロード状態をその識別子ごとに分離します。管理者は管理用ビューを持ちます。招待セッションのゲストは solo / multi 共通で、許可されたページと作品だけにアクセスできます。履歴、コレクション、統計にも入口ごとの権限があり、この 2 種類の利用者は別です。

HTTPS は `config.yaml` で設定します。

```yaml
server.ssl.enabled: true
server.ssl.certificate: /path/to/cert.pem
server.ssl.certificate-private-key: /path/to/key.pem
```

証明書と秘密鍵のパスは実際のものに置き換えます。PEM と JKS の両方を設定した場合は PEM が優先です。再起動後に HTTPS を確認し、リバースプロキシの条件は[設定](/ja/configuration)を参照してください。

## 移行・アップグレードと問い合わせ

新しい PC への移行は[ストレージ](/ja/storage)の停止・バックアップ・復元手順に従います。絶対パスが変わる場合はデータベースの参照も移行します。ログイン、ギャラリー、小説本文、コレクション、新しいダウンロードを確認してから旧コピーを処理してください。

更新は GUI の状態画面、Java 配布物全体の展開とプログラム・プラグインの置き換え、または Windows の新しいインストーラーから行います。設定、状態、データを保持し、主 JAR だけを置き換えないでください。起動時の schema 更新と SQLite / PostgreSQL 間の移行は別の操作です。接続設定の変更だけで旧データは移りません。更新前にバックアップし、更新後にログインと既存作品を確認します。

不具合や要望は [GitHub Issues](https://github.com/Sywyar/PixivDownloader/issues) に、OS、バージョン、再現手順、`log/latest.log`、必要ならスクリーンショットを添えて報告してください。Cookie、トークン、パスワード、個人のアドレスを除去してから送ります。
