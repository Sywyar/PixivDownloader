# よくある質問 (FAQ)

症状に応じて診断と対処の手順を確認してください。データベース、アカウント、ディレクトリを操作する前に、実際の作業ディレクトリを確認し、バックアップを保持してください。以下のコマンドの `APP.jar` は配布パッケージ内の実際のメインプログラム JAR 名に置き換え、完全に展開したディレクトリで実行します。

## インストールと起動

### 「Java は内部コマンドまたは外部コマンドとして認識されていません」と表示される

Java 17+ がインストールされていないか、環境変数に登録されていません。[Adoptium](https://adoptium.net/) から Java 17+ をインストールしてターミナルを開き直すか、`JAVA_HOME` と `PATH` を確認してください。

### 起動後、コンソールの中国語が文字化けする

手動起動では `-Dfile.encoding=UTF-8` を追加してください。配布パッケージの `run.bat` / `run.sh` には含まれています。

```bash
java -Dfile.encoding=UTF-8 -jar APP.jar
```

### ポート 6999 が使用中と表示される

まず、同じデータディレクトリを使う PixivDownloader が既に起動していないか確認してください。同じデータディレクトリで複数のインスタンスを起動しないでください。他のプログラムが使用している場合は、それを停止するか、`config/config.yaml` の `server.port` を変更して再起動します。

### Windows インストーラーでインストールに失敗する

実行中の `PixivDownload.exe` を閉じてから、管理者としてインストーラーを再実行してください。

### アンインストールや管理者アカウントの再初期化をしたい

- **アンインストール**：Windows インストール版はインストーラーまたはシステムの「設定 → アプリ」から行います。Java 展開版は[ストレージとバックアップ](/ja/storage)に従い、作品ディレクトリ、`config/`、`state/`、`data/` をバックアップしてからプログラムファイルを削除してください。作品やデータベースを含む作業ディレクトリ全体をそのまま削除しないでください。
- **パスワードを忘れた場合・再初期化**：パスワードを忘れただけなら、サービスを停止して `--reset-password` を実行します。初期化状態を作り直す必要がある場合は、サービスを停止してバックアップ後、`state/setup_config.json` を別の場所に移し、`--setup` またはデスクトップのガイドを実行します。業務設定の消去やデータベースの再構築は行いません。[初回セットアップ](/ja/first-setup)を参照してください。

### サーバー / Docker が起動直後に終了コード 78 で終了する

ヘッドレスモード（`--no-gui`）は初期化が未完了だと終了コード `78` で中断します。対話式の初期化を先に実行し、その後でサービスを起動してください。

```text
java -Dfile.encoding=UTF-8 -jar APP.jar --setup
java -Dfile.encoding=UTF-8 -jar APP.jar --no-gui
```

### 管理者パスワードを忘れた

実行中のインスタンスを停止し、このマシンでリセットコマンドを実行します。元のパスワードは不要で、新しいパスワードは最低 8 文字、12 文字以上を推奨します。リセットすると旧セッションはすべて失効します。元のパスワードが分かる場合は `--change-password` を使えます。

```text
java -Dfile.encoding=UTF-8 -jar APP.jar --reset-password
```

### 「認識できない起動引数」と表示される

起動引数は厳密に検証されます。誤字のあるスイッチ（`--no-guii` など）、`=` のない引数（`--username admin` など）、単独の位置引数は拒否されます。`--help` で対応オプションを確認してください。

## プロキシとネットワーク

### プロキシを設定してもダウンロードできない

1. プロキシ設定が保存されたことを確認します。デスクトップ GUI の保存や CLI `--setup` はホットリロードに対応します。`config/config.yaml` を手動編集した場合は、再起動するか GUI で保存してリロードしてください。
2. ブラウザーで実際の Pixiv 作品ページにアクセスできるか確認し、`log/latest.log` の失敗したホストとエラーコードを調べます。
3. ファイアウォールがプロキシのポートを許可しているか確認します。コンテナーでは `127.0.0.1` ではなく `host.docker.internal` を使用してください。
4. 全体のプロキシ、スケジュールタスク専用のプロキシ、プラグイン独自のプロキシ、ブラウザーの直接接続を区別してください。[ネットワークアクセスと外部サービス](/ja/network-access)を参照してください。

### リバースプロキシの背後でマルチユーザーモードの全利用者が同じレート制限を共有する

信頼するプロキシが未設定の場合、バックエンドは TCP の送信元 IP で制限します。`config/config.yaml` の `server.trusted-proxy-cidrs` に、実際のリバースプロキシの出口またはコンテナーネットワーク（`172.18.0.0/16` など）を指定し、完全な `Forwarded`、または `X-Forwarded-For` + `X-Forwarded-Proto` + `X-Forwarded-Host` を渡すよう設定してください。[設定リファレンスの HTTPS とリバースプロキシ](/ja/configuration#https-とリバースプロキシ)を参照してください。

### LAN 内の他の端末からアクセスできない

ファイアウォールが `server.port`（デフォルト `6999`）を許可し、サービスが `127.0.0.1` だけにバインドされていないか確認してください。Docker はデフォルトでホストのループバックだけにバインドするため、リバースプロキシかポートマッピングの変更で公開する必要があります。LAN 内の端末では `http://<サーバーIP>:6999/` にアクセスします。

## Cookie とダウンロード

### 検索結果がない、または Cookie の形式エラーが出る

- 検索ダウンロード、クイック取得、R-18 作品には、有効な `PHPSESSID` を含む Cookie が必要です。
- 貼り付け時の形式（**Netscape** または **Header String**）をエクスポート内容に合わせてください。通常のフロントエンドスクリプトが取得する `document.cookie` には HttpOnly の `PHPSESSID` が含まれません。[初回ダウンロード](/ja/first-download#_2-pixiv-cookie-を保存する（必要な場合）)に従って取得し直してください。
- Cookie の消去はダウンロードページで明示的に実行してください。スケジュールタスクは独立した Cookie の関連付けを持つため、対象タスクでも解除が必要です。

### うごイラ（Ugoira）を変換できない、または小説 EPUB に表紙がない

- **うごイラ**：`ffmpeg -version` が実行できるか確認するか、デスクトップ GUI の「状態」で「FFmpeg をダウンロード」を実行してください。MP4 には H.264 エンコーダーも必要です。
- **小説の表紙**：表紙は `.pximg.net` から取得します。バックエンドのプロキシから画像ドメインにアクセスできるか確認し、修正後に小説を再ダウンロードしてください。

### 読み上げの「オンラインエンジン」で音が出ない、または合成に失敗する

1. オンラインエンジン（Edge ニューラル音声）はバックエンドのプロキシ経由で Microsoft のサービスに接続するため、まず `proxy.*` が使えることを確認します。
2. ハンドシェイクが 403 を返すと、バックエンドは Edge のバージョンを自動更新し、時計のずれを補正して再試行します。継続して失敗する場合は、このマシンのシステム時刻を合わせてください。
3. 再生バーで「ブラウザーエンジン」に切り替えることもできます。
4. 招待ゲストには `guest-invite.tts-request-limit-minute`（デフォルト毎分 30 回）の制限があり、超過すると 429 を返します。管理者にはこの制限は適用されません。

### 一括ダウンロードの一部が失敗する、ファイル名テンプレートが反映されない、クォータの消費が速い

- **一部の失敗**：作者が作品を削除・非公開にしていないか、Cookie が失効していないか確認してください。取得先のレート制限に遭遇した場合は、同時実行数を減らし、作品間の間隔を広げます。
- **ファイル名テンプレート**：変数は `{artwork_id}` のように波括弧で囲み、変更後の新規ダウンロードにだけ反映されます。対応する変数は[ファイル名テンプレートの変数](/ja/usage-guide#ファイル名テンプレートの変数)を参照してください。
- **マルチユーザーモードの複数画像のクォータ**：`multi-mode.quota.limit-image` が `0` より大きい場合、そのページ数を超える複数画像作品は、比率に応じて複数のクォータとして換算されます。

## デスクトップ GUI とデータベース

### GUI が「起動中」のまま、更新に失敗する、またはエラーが表示される

- **起動が遅い**：10 秒を超えると待機秒数が表示されます。データベースの移行やプラグインの読み込み中の可能性があります。`log/latest.log` を確認し、データとログを保持してください。**起動の遅さを調べるためにデータベースを削除しないでください。**
- **オンライン更新の失敗**：バックエンドのプロキシ接続を確認するか、[Releases](https://github.com/Sywyar/PixivDownloader/releases) から新しいインストーラーを取得して上書きインストールします。
- **エラーの詳細**：ダイアログの「ログファイルを開く」から、`log/latest.log` にある完全な英語の診断ログを確認します。

### データベースの場所、破損への対処、バックアップと復元

- **場所**：デフォルトの SQLite は `data/pixiv_download.db`（`-wal` / `-shm` を伴う場合あり）、PostgreSQL は設定したデータベースサーバーにあります。
- **データベースの破損**：先にプログラムを停止して元データベースと付随ファイルをすべてバックアップし、**バックアップのコピーだけ**に `PRAGMA integrity_check;` を実行してください。このコマンドは検査だけで修復は行いません。破損を確認したら、検証済みのバックアップからの復元を優先します。作品の識別、ページ数、パス、関連付けはデータベースを基準にするため、**データベースを失った場合、作品フォルダーだけではギャラリーの復元や再ダウンロードのスキップを保証できません。**
- **バックアップ、マシン移転、更新**：完全なバックアップ範囲とディレクトリ移転は[ストレージとバックアップ](/ja/storage)を参照してください。Java 配布パッケージの更新では、全体を展開してメインプログラムと `plugins/` を一緒に置き換え、`config/`、`state/`、`data/` を保持します。メイン JAR だけを置き換えないでください。

## ユーザースクリプトとセキュリティ

### スクリプトが表示されない、パネルが二重になる、バックエンドに接続できない

- Tampermonkey とスクリプトが有効で、現在のページが `@match` に一致するか（User Batch は `/users/` のみなど）確認し、ページを再読み込みしてください。
- **二重パネル**：All-in-One と個別ダウンロードスクリプトを同時に有効にせず、どちらか一方だけを使ってください。
- **バックエンドに接続できない**：バックエンドが起動し、シングルユーザーモードでログイン済みか確認してください。`localhost:6999` 以外で運用する場合は、スクリプト内のバックエンドアドレスと `@connect` の許可を両方更新する必要があります。[ユーザースクリプト](/ja/userscripts)を参照してください。

### アカウントの安全性、利用者の区別、HTTPS

- 本ツールは利用者が指定した Cookie で Pixiv にリクエストします。同時実行数と間隔を適切に設定し、プラットフォームのルールを守ってください。
- **利用者の区別**：`multi` モードで未ログインかつ招待コードがない利用者は**匿名ユーザー**（UUID と `multi-mode.*` で分離）、招待コードを持つ利用者は**招待ゲスト**（`solo` / `multi` とも許可リスト内のコンテンツを読み取り専用で利用し、`guest-invite.*` の制限対象）です。
- **HTTPS の有効化**：`config/config.yaml` で `server.ssl.enabled: true`、`server.ssl.certificate`、`server.ssl.certificate-private-key` を設定します。[設定リファレンス](/ja/configuration#https-とリバースプロキシ)を参照してください。

## 問題を報告する

[GitHub Issues](https://github.com/Sywyar/PixivDownloader/issues) に報告する際は、OS、プログラムのバージョン、再現手順、関連するスクリーンショットと、Cookie、パスワード、トークン、私的なアドレスを除いた `log/latest.log` を添付してください。
