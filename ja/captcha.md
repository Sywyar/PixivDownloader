# 操作 CAPTCHA

公式の `captcha` プラグインは、ログインなどの保護対象フォーム向けに、Turnstile、reCAPTCHA v2、ALTCHA SHA-256、ALTCHA PBKDF2、文字 CAPTCHA（オフライン）、スライドパズル（オフライン）の 6 種類の検証コンポーネントを提供します。通常の配布パッケージにはプリインストールされていません。必要に応じてプラグインマーケットからインストールするか、オフライン完全パッケージを使用してください。対応するフォームにコンポーネントを配置してページを公開すると、フロントエンドとバックエンドの両方がチャレンジの証明を必須で検証します。

CAPTCHA は自動送信のコストを高めるためのもので、ネットワーク層の DDoS 対策、リバースプロキシのレート制限、アクセス制御の代わりにはなりません。外部リクエストについては[ネットワークアクセスと外部サービス](/ja/network-access)を参照してください。

## 検証方式の比較

| コンポーネント | 利用者の操作 | 検証場所 | 事前準備 |
| --- | --- | --- | --- |
| ALTCHA SHA-256（オフライン） | クリック後、ブラウザーの SHA-256 作業証明の完了を待つ | このマシンでチャレンジを発行して署名を検証。外部サービスは不要 | 初回有効化時にローカル署名キーを自動生成 |
| ALTCHA PBKDF2（オフライン） | クリック後、ブラウザーの PBKDF2/SHA-256 鍵導出証明の完了を待つ | このマシンでチャレンジを発行して署名を検証。外部サービスは不要 | SHA-256 とローカル署名キーを共有 |
| 文字 CAPTCHA（オフライン） | 画像の 5 桁の英数字を入力して確定（大文字・小文字は区別しない） | Hutool がこのマシンで画像を生成し、サーバーのメモリ内で照合 | 追加設定なし |
| スライドパズル（オフライン） | スライダーをドラッグ、または方向キー + Enter でピースを穴に合わせて確定 | Tianai がこのマシンでパズルを生成し、サーバーのメモリ内で照合 | 追加設定なし |
| Turnstile オンライン検証 | Managed モードで「検証開始」をクリックし、Cloudflare のウィジェットを読み込む | ブラウザーが Cloudflare を読み込み、サーバーが Siteverify を呼び出す | Cloudflare アカウント、Sitekey、Secret key、許可するホスト名 |
| reCAPTCHA v2 オンライン検証 | チェックボックスを選択。Google の判定により画像問題が出る場合がある | ブラウザーが Google のウィジェットを読み込み、サーバーが Siteverify を呼び出す | Google reCAPTCHA v2 Checkbox の公開キー、秘密キー、ホスト名 |

!> 通常はフォームごとに 1 種類を選べば十分です。**同じフォームに複数の CAPTCHA コンポーネントを置いた場合、すべてを完了するまで送信できません。** オンラインサービスが利用できなくても、オフラインのコンポーネントへ自動的に切り替わりません。

## インストールしてフォームに関連付ける

1. [プラグイン管理](/ja/plugin-management)で「操作 CAPTCHA」と「ページエディター」をインストールして有効にします。
2. Turnstile または reCAPTCHA v2 を使う場合は、先にデスクトップの「設定 → 操作 CAPTCHA」で以下のキーとホスト名を設定して保存します。オフラインのコンポーネントには事前設定は不要です。
3. [ページエディター](/ja/page-editor)でログインページなどの対象ページを選び、左側の「コンポーネントを追加 → CAPTCHA」から必要なものをドラッグし、右側の「保護する操作」が対象フォームに関連付けられていることを確認します。
4. 「公開」をクリックし、必要な外部リソースの権限を確認します。下書きの保存だけでは正式ページの CAPTCHA 保護は有効になりません。
5. 未ログインのウィンドウで正式なログインページを開き、ユーザー名とパスワードを入力して CAPTCHA を完了し、「ログイン」をクリックします。

ユーザー名、パスワード、「ログイン状態を保持」を変更すると、その回の証明は消去されます。パスワードの誤り、検証失敗、チャレンジの期限切れ後は再検証が必要です。

## オフラインコンポーネントの設定と注意点

- **ALTCHA（SHA-256 / PBKDF2）**：初回有効化時に 32 バイトのランダムな署名キーを自動生成し、ホストが暗号化して `config/credentials/captcha.properties` に保存します。有効期限はなく、通常は変更不要です。手動で置き換える場合は 32 文字以上が必要で、認証情報を消去した場合はプラグインを再び有効にすると新しいキーが生成されます。Worker スクリプトはプラグインに同梱され、外部 CDN は不要です。ブラウザーでの計算は [Web Crypto `SubtleCrypto`](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto) に依存するため、`localhost`、`127.0.0.1`、または HTTPS でアクセスしてください。通常の LAN 内の平文 HTTP では、ブラウザーが Web Crypto を無効にする場合があります。
- **文字入力とスライドパズル**：画像はこのマシンで生成され、チャレンジの有効期間は 120 秒、使用は 1 回限りです。「別の画像」をクリックすると、現在のフォームの検証状態がすべてリセットされます。どちらも基本的な自動化対策に留まり、スライドパズルには操作軌跡のモデルはありません。リクエストのレート制限と併用してください。アクセシビリティを重視する場合は、画像の判別が不要な ALTCHA を優先してください。

## Cloudflare Turnstile の設定

1. [Cloudflare ダッシュボード](https://dash.cloudflare.com/)にログインして **Turnstile → Add widget** を開き、実際にアクセスするホスト名を追加します。`localhost` や `download.example.com` のように、プロトコル、ポート、パスは含めません。モードは **Managed** を選び、作成後に Sitekey と Secret key を取得します。
2. デスクトップの「設定 → 操作 CAPTCHA」で Cloudflare Turnstile を選び、**サイト公開キー**（Sitekey）、**署名検証キー**（Secret key）、**想定ホスト名**を入力します。想定ホスト名はブラウザーで実際にアクセスするホスト名と完全に一致させ、`localhost` と `127.0.0.1` を切り替える場合も更新します。「公式テスト設定を許可」を無効にして保存します。
3. ページエディターで Turnstile を関連付けたページを公開します。公開キー、想定ホスト名、テスト設定を変更した場合は再公開が必要です。秘密キーのローテーションだけなら再公開は不要です。

**公式テストキー（送信フローの結合確認専用で、自動化対策にはなりません）**：公開キーは `1x00000000000000000000AA`、秘密キーは `1x0000000000000000000000000000000AA`、想定ホスト名は `example.com` とし、「公式テスト設定を許可」を有効にして再公開します。本番運用前に必ず実際のキーに戻し、テスト設定を無効にして再公開してください。

## Google reCAPTCHA v2 の設定

1. [Google reCAPTCHA 管理コンソール](https://www.google.com/recaptcha/admin/create)で **v2 →「私はロボットではありません」チェックボックス**のサイトを作成します。v3 や Invisible は選ばないでください。実際にアクセスするホスト名を追加し、ローカルテストでは `localhost` を指定します。
2. デスクトップの「設定 → 操作 CAPTCHA」で Google reCAPTCHA v2 を選び、**サイト公開キー**、**署名検証キー**、**想定ホスト名**を入力して、「reCAPTCHA 公式テスト設定を許可」を無効にし、保存します。
3. ページエディターで「reCAPTCHA v2 オンライン検証」を配置し、ページを公開します。

**公式テストキー（結合確認専用で、実際の保護にはなりません）**：公開キーは `6LeIxAcTAAAAAJcZVRqyHh71UMIEGNQ_MXjiZKhI`、秘密キーは `6LeIxAcTAAAAAGG-vFI1TnRWxMZNFuojJ4WifJWe` とします。想定ホスト名は空欄にでき、`testkey.google.com` を検証します。「reCAPTCHA 公式テスト設定を許可」を有効にして再公開してください。

## トラブルシューティング

| 症状またはログのエラーコード | 確認と対処 |
| --- | --- |
| エディターにはあるが正式ログインページに表示されない | 下書きの保存だけでなく「公開」を実行したか確認し、正式ページを再読み込み |
| `CAPTCHA_CREDENTIAL_MISSING` / `CAPTCHA_CREDENTIAL_INVALID` | ログが示すキー名をもとに、秘密キーが空または短すぎないか確認。秘密キーをログや Issue に貼らないこと |
| `CAPTCHA_CONFIG_INVALID` | 公開キー、想定ホスト名、テストモードの組み合わせを確認。テストキーにはテスト設定が必要 |
| `PUBLISHED_POLICY_CHANGED` | CAPTCHA 設定の変更後、ページエディターで該当ページを再公開 |
| `CAPTCHA_REMOTE_UNAVAILABLE` またはウィジェットが読み込まれない | ブラウザーとバックエンドから Cloudflare / Google へのネットワークとプロキシ設定を確認 |
| `HOSTNAME_MISMATCH` | ブラウザーのアドレスバーのホスト名、提供元の管理画面の許可ドメイン、プラグインの「想定ホスト名」がすべて一致しているか確認 |
| ALTCHA を追加してもポリシーが利用不可と表示される | 同じフォームに未設定の Turnstile や reCAPTCHA が残っていないか確認し、不要なコンポーネントを除去して再公開 |

`captcha` プラグインを無効化・アンインストールしても、公開済みページの検証要件は回避できず、保護対象の操作は拒否され続けます。CAPTCHA を解除するには、ページエディターでコンポーネントを除去して再公開してください。
