# 操作認証プラグイン

公式の `captcha` プラグインは、Turnstile、ALTCHA SHA-256、ALTCHA PBKDF2 のフォーム認証コンポーネントを提供します。必要に応じてインストールするプラグインで、通常の配布物には含まれず、完全オフラインパッケージには含まれます。対応フォームに配置して公開すると、サーバーが認証結果を必須として検証します。

CAPTCHA は自動送信のコストを増やす機能です。ネットワーク層の DDoS 対策、リバースプロキシのレート制限、アクセス制御を置き換えるものではありません。外部接続は[ネットワークアクセスとサードパーティサービス](/ja/network-access)を参照してください。

## 認証方式を選ぶ

| 方式 | 操作 | 処理する場所 | 必要なもの |
| --- | --- | --- | --- |
| Turnstile オンライン認証 | Managed モードでは「認証を開始」後、Cloudflare のウィジェットが追加操作の要否を判断 | ブラウザーが Cloudflare を読み込み、サーバーが Cloudflare にトークンを検証させる | Cloudflare アカウント、Sitekey、Secret key、許可ホスト名 |
| ALTCHA SHA-256 | 表示名は「ALTCHA オフライン認証」。クリック後に計算し、「認証済み」と表示 | ブラウザーが SHA-256 の作業証明を計算し、ローカルサービスがチャレンジの発行と検証を行う | 初回有効化時に生成する署名キー。外部アカウントは不要 |
| ALTCHA PBKDF2 | 表示名は「ALTCHA PBKDF2 オフライン認証」。操作は SHA-256 と同じ | ブラウザーが PBKDF2/SHA-256 の作業証明を計算し、ローカルサービスが検証 | SHA-256 と共通の署名キー。外部アカウントは不要 |

どちらの ALTCHA も画像の識別や文字入力を求めません。オフラインとは外部認証サービスに依存しないという意味で、ブラウザーは PixivDownloader への接続が必要です。計算時間は方式、パラメーター、端末によって異なり、PBKDF2 という名前だけで速度や保護効果を比較できません。[ALTCHA の作業証明](https://altcha.org/docs/integration/proof-of-work-captcha/)も参照してください。

通常はフォームごとに一つの方式を選びます。**複数配置すると、すべての認証が必須です。** 選択肢として扱われず、Turnstile が使えなくても自動的に ALTCHA へ切り替わりません。

## インストールとフォームへの配置

1. [プラグイン管理とマーケット](/ja/plugin-management)で「操作認証」と「ページエディター」をインストールし、有効にします。
2. オフライン方式では自動生成したキーをそのまま使用できます。Turnstile は後述の設定を先に行います。
3. [ページエディター](/ja/page-editor)でログインページなどの対応ページを選び、CAPTCHA 分類からフォームへコンポーネントをドラッグします。保護対象の操作との紐付けを確認し、フォーム外への配置や曖昧な紐付けは公開前に修正します。
4. 要求されるリソース権限を確認して公開します。下書きの保存だけでは公開ページの認証要件は変わりません。
5. 未ログインのウィンドウで公開ページを開きます。ログインではユーザー名とパスワードを入力して「認証を開始」を押し、すべての認証後にログインします。

編集とプレビューでは実際の認証を行いません。公開ページは証明が揃うまでログイン要求を送信せず、サーバーもパスワード照合とセッション作成の前に証明を検証します。ユーザー名、パスワード、ログイン保持の変更で証明は消去されます。パスワードの誤り、認証失敗、有効期限切れの後は再認証が必要です。

通常のインストールと有効化はホットロードに対応しており、ページの再読み込みで反映できます。開発環境で読み込み済みの Java クラスやホストコードを更新した場合は、開発インスタンスを再起動してからページを再読み込みします。

## オフライン認証の設定

両方式は「ALTCHA 署名キー」を共有します。初回有効化時に 32 バイトの乱数を生成し、ホストが暗号化してインスタンスの `config/credentials/captcha.properties` に保存します。設定ルートを変更した場合はその配下になります。再有効化や再起動でもキーを再利用し、自動有効期限はありません。通常は変更不要です。

手動置換には 32 文字以上が必要です。パスワード欄を空のまま保存すると既存値を保持します。保存済み資格情報を削除すると実行中のオフライン認証は拒否され、次のプラグイン再有効化時に新しいキーを生成します。既存値の不正、保存領域の破損、書き込み失敗を一時キーで回避することはありません。

Worker はプラグインに同梱され、外部 CDN は不要です。計算には Web Crypto を使うため、HTTPS またはブラウザーが安全と認めるローカルオリジンでアクセスしてください。LAN の IP アドレスへの通常の HTTP では API を利用できない場合があります。[Web Crypto の要件](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto)

## Turnstile キーの取得と設定

### Sitekey と Secret key を取得する

1. [Cloudflare ダッシュボード](https://dash.cloudflare.com/)にログインし、**Turnstile → Add widget** を開きます。
2. `PixivDownloader` などの名前を入力します。
3. Hostname management に実際のアクセス先（例：`download.example.com`）を登録します。
4. **Managed** を選ぶと、追加操作の要否を Cloudflare が判断します。
5. Create を押し、同じウィジェットの Sitekey と Secret key をコピーします。Sitekey は公開識別子ですが、サーバー用の Secret key は公開しないでください。[公式作成手順](https://developers.cloudflare.com/turnstile/get-started/widget-management/dashboard/)

サイトを Cloudflare のプロキシ経由にする必要はありません。ただしウィジェットとサーバーの検証処理には Cloudflare への接続が必要です。[公式導入ガイド](https://developers.cloudflare.com/turnstile/get-started/)

### ソフトウェアに入力する

「設定 → 操作認証」を開きます。

| 項目 | 入力内容 |
| --- | --- |
| Turnstile サイトキー | ウィジェットの Sitekey |
| Turnstile シークレットキー | 同じウィジェットの Secret key |
| Turnstile の期待するホスト名 | 実際のアクセス先（例：`download.example.com`） |
| 公式テスト設定を許可 | 自分で取得したキーではオフ |

ホスト名にプロトコル、ポート、パスは含めません。`https://download.example.com:6999/login.html` は入力しないでください。Cloudflare の許可ホスト名とソフトウェア側の期待値の両方が必要で、プラグインは検証応答のホスト名との完全一致を要求します。[ホスト名の要件](https://developers.cloudflare.com/turnstile/additional-configuration/hostname-management/)

保存後、フォームに Turnstile を配置して公開します。サイトキー、期待ホスト名、テストモードを変更した場合は既存ページも再公開します。シークレットキーだけの更新では既存チャレンジが無効になり、再認証が必要です。通常の設定は `config/plugins/captcha.properties`、秘密情報は暗号化した資格情報ファイルに保存し、ページ文書には保存しません。

### 自分のキーをローカルで使う

開発用ウィジェットを別に作成し、ブラウザーのアドレスに合わせます。

| ブラウザーのアドレス | Cloudflare 許可ホスト名 | プラグイン期待ホスト名 |
| --- | --- | --- |
| `http://localhost:6999` | `localhost` | `localhost` |
| `http://127.0.0.1:6999` | `127.0.0.1` | `127.0.0.1` |
| `https://download.example.com` | `download.example.com` | `download.example.com` |

ポートを変えてもホスト名は変わりません。`localhost` と `127.0.0.1` を切り替える場合は設定変更と再公開が必要です。**ローカル実行のために「公式テスト設定を許可」をオンにする必要はありません。** Cloudflare は開発用のローカルホスト名を許可していますが、本番用では許可しないことを推奨しています。[ローカルテストの説明](https://developers.cloudflare.com/turnstile/troubleshooting/testing/)

### 公式テストキーで接続を確認する

コンポーネントと送信処理だけを確認する場合は、Cloudflare の公開された常時成功するテスト値を使えます。

| 項目 | テスト値 |
| --- | --- |
| Turnstile サイトキー | `1x00000000000000000000AA` |
| Turnstile シークレットキー | `1x0000000000000000000000000000000AA` |
| Turnstile の期待するホスト名 | `example.com`（本プラグインの公式テスト規約） |
| 公式テスト設定を許可 | オン |

保存して再公開します。この `example.com` はテスト応答の照合用で、所有やアクセスは不要です。ページは `localhost` のまま利用できます。テストサイトキーにはテストシークレットが必要です。値の出典は [Cloudflare テスト文書](https://developers.cloudflare.com/turnstile/troubleshooting/testing/)で、**実際のボット対策にはなりません**。本番では自分のキーと実際のホスト名へ変更し、テスト設定をオフにして再公開してください。

## 認証できない場合

| 現象やログ | 対処 |
| --- | --- |
| エディターにあるのに公開ページに表示されない | 下書き保存だけでなく公開が成功したか確認し、再読み込み |
| `CAPTCHA_CREDENTIAL_MISSING` / `CAPTCHA_CREDENTIAL_INVALID` | ログが示す設定キーを確認。秘密情報をログや報告に貼り付けない |
| `CAPTCHA_CONFIG_INVALID` | サイトキー、ホスト名、テストモードの該当項目とキーの組み合わせを確認 |
| `PUBLISHED_POLICY_CHANGED` | 設定を確認して対象ページを再公開 |
| `CAPTCHA_REMOTE_UNAVAILABLE` または読み込み失敗 | ブラウザーとサーバーの Cloudflare 接続、プロキシ、遮断規則を確認 |
| `HOSTNAME_MISMATCH` | ブラウザーのアドレス、Cloudflare 許可ホスト名、期待ホスト名を比較 |
| ALTCHA 追加後もポリシーが利用できない | 未設定の Turnstile も必須になっていないか確認。オフラインのみなら削除して再公開 |
| 完了後に再認証を求められる | 入力変更、誤ったパスワードの送信、期限切れ、設定変更を確認 |

必要なログイン認証ポリシーが利用できないというメッセージは結果の要約です。直前のイベントで原因と設定キーを確認してください。プラグインを無効化・削除しても公開済み要件は残り、保護対象の操作を拒否します。要件を解除するにはページを編集して再公開します。
