# ローカル作品インポートとプリセット

ローカル作品インポートは、ファイルパスに含まれる作品 ID を手がかりに、ディスク上の既存イラスト・漫画・うごイラを**読み取り専用の参照**として作品ライブラリへ一括登録します（元のフォルダとファイルは維持され、ギャラリーから削除しても元ファイルは削除されません。パスから取得できないタイトル・作者・タグなどのメタデータは、登録後に[メタデータ補完](#metadata-backfill)で補えます）。PixivBatchDownloader からエクスポートした履歴 JSON の取り込みは[外部ダウンロードのインポート](/ja/pixiv-batch-downloader-import)を使用してください。

?> ローカル作品インポートはバックエンド稼働中に動作するオンラインツールです（停止を伴う保守モードには入りません）。Compose（「ツール → クイックツール」のダイアログとして開き、閉じても開始済みタスクはバックグラウンドで継続）と Swing の両方ともデスクトップのツールページから開きます。HTTP API で指定するパスも、バックエンドが動作しているサーバー上のローカルパスを指します。

## パステンプレートと利用可能な変数

**パステンプレート**は、パス内の変化する部分を波括弧 `{変数}` で表し、そこから作品情報を逆方向に読み取る仕組みです：

- 各テンプレートには `{artwork_id}`（ディレクトリ名またはファイル名内）が必須で、絶対パスで記述します（Windows では `/` と `\` の両方に対応）。テンプレートは照合と解析にのみ使われ、ディレクトリの作成やファイル名の変更は行いません。
- **フォルダーテンプレートと単一ファイルテンプレート**：末尾が `/` のテンプレートは**フォルダーテンプレート**（そのディレクトリとサブディレクトリ内の対応ファイルを再帰的に収集）、末尾が `/` でないテンプレートは**単一ファイルテンプレート**（ファイル名と `.{extension}` まで記述）として扱われます。
- 変数名は小文字の `snake_case` で完全一致が必要です。**隣接する変数の間には固定の区切り文字が必要**であり（`{artwork_id}_{name}` は可、`{artwork_id}{name}` は不可）、`*` はワイルドカードとして使えません。

| 既存ファイルの実際のパス | 入力するパステンプレート | 解析結果 |
| --- | --- | --- |
| `D:/xxx/12345/pic.png` | `D:/xxx/{artwork_id}/` | 作品 ID `12345`。このディレクトリとサブディレクトリ内の対応ファイルを収集 |
| `D:/xxx/12345_xxx.png` | `D:/xxx/{artwork_id}_xxx.{extension}` | 作品 ID `12345`、拡張子 `png`（`_xxx` は固定文字） |
| `D:/678/12345/pic.png` | `D:/{author_id}/{artwork_id}/` | 作者 ID `678`、作品 ID `12345` |
| `D:/xxx/12345_p0.jpg` | `D:/xxx/{artwork_id}_p{page}.{extension}` | 作品 ID `12345`、`0` ページ目 |

| 変数 | 意味 |
| --- | --- |
| `{artwork_id}` | 必須。正の整数の作品 ID |
| `{author_id}` | 正の整数の作者 ID |
| `{artwork_title}` | パスに含まれる作品タイトル |
| `{author_name}` | パスに含まれる作者名 |
| `{page}` | ページ番号（`0` から開始） |
| `{extension}` | ファイル拡張子（先頭の `.` を除く） |
| `{name}` | 1 つのパス区間内のその他の名前（作品タイトルとしては保存しない） |

## 操作手順

ダイアログ内の「今回のインポート設定」（一時パステンプレート、作品 ID、対象ファイル）は既定で折りたたまれています。プリセット保存済みなら 3 つの入力欄をすべて空にしたまま「スキャンしてプレビュー」を実行できます。プリセット未保存で一時テンプレートも空のままスキャンを押すと、設定欄が展開されてテンプレート入力欄が赤く強調表示されます。

### 方法 1：一時テンプレートを入力して単発インポートする

1. デスクトップの「ツール → ローカル作品インポート」を開き、「今回のインポート設定」を展開します。
2. 「一時パステンプレート」に絶対パステンプレートを 1 行に 1 件ずつ入力します（例：`D:/xxx/{artwork_id}/`。一時テンプレートを入力した場合はその内容だけが使われ、設定ファイルには保存されません）。
3. **作品 ID（任意）**：1 件なら `12345`、複数件なら改行・空白・カンマ区切りで入力します。空欄にすると一致する全作品をスキャンします。
4. **対象ファイル（任意）**：1 ファイルだけを登録したい場合にそのパスを入力します（そのファイルを解析できるテンプレートも必要です）。
5. 「スキャンしてプレビュー」をクリックし、作品 ID・パス・状態を確認してから「インポート開始」をクリックします。

### 方法 2：ローカルインポートのプリセットを保存する（定常的なインポート向け）

**ローカルインポートのプリセット**（設定キー `local-import.presets`）はパステンプレートの一覧を保存し、スキャン時に保存済みパスをすべて自動適用します：

1. 「ツール → ローカル作品インポート」を開き、ダイアログ内の「ローカルインポートのプリセット」をクリックします。
2. 「パスを追加」をクリックし、`D:/{author_id}/{artwork_id}/` などの絶対パステンプレートを 1 行に 1 件ずつ入力します（ダブルクリックで編集や行の削除が可能。スキャン範囲を絞るため、作品が置かれている具体的なディレクトリを指定してください）。
3. 「プリセットを保存」をクリックします（再起動なしで次回スキャンから有効。キャンセル時は保存済みパスを変更しません）。
4. インポートダイアログに戻り、3 つの入力欄を空のままスキャンすると保存済みパス全体が走査されます。「作品 ID」に `12345` を指定すると、作者 ID を入力しなくても `D:/` 配下の各作者ディレクトリから該当作品を検索します。

## プレビュー状態、キャッシュ、集計方法

- **対応形式**：`JPG`、`JPEG`、`PNG`、`APNG`、`GIF`、`WebP`、`WebM`、`MP4`、`ZIP`（ファイルヘッダー検証を通過する必要があり、ZIP はうごイラのフレームパッケージとしてのみ扱われ、任意のアーカイブとして展開されることはありません）。
- **スキャン索引キャッシュ**：直近のディレクトリスキャン索引はメモリ上に 5 分間保持され、ディスク変更を自動監視しません。ファイルの追加・移動・削除後は「ディレクトリを再スキャンしてインデックスを更新」にチェックを入れてからプレビューしてください。
- **キャンセルとバックアップ**：キャンセル時は現在登録中の作品の処理完了を待って停止し、登録済み作品は保持されます。外部ファイルは読み取り専用参照のため、元ファイルの移動や削除で参照が無効になります。バックアップ時はデータベースと外部ディレクトリの両方を保存してください。

| プレビュー結果 | 意味 | 実行時の集計先（作品単位で集計） |
| --- | --- | --- |
| `NEW` | 新規作品を登録 | 書き込み成功で `imported`、実行時に変更なしで `skipped`、エラーで `failed` |
| `SUPPLEMENT` | 登録済み作品に外部ファイルやページを追加 | 書き込み成功で `imported`、実行時に変更なしで `skipped`、エラーで `failed` |
| `DUPLICATE` | すべてのファイルが登録済み | `skipped` |
| `CONFLICT` | 登録の競合（同じページに 2 つのファイルが一致した場合など。既存記録は上書きしない） | `failed` |
| `MISSING` | 一致するファイルが見つからない | `failed` |

たとえば 4 作品すべてが `CONFLICT` の場合、結果は `imported: 0, skipped: 0, failed: 4` になります。理由はプレビュー項目の `reason` またはタスクの `problems` で確認できます。

## HTTP API

管理者または `core:local-import.*` 権限を持つプログラムキーは `/api/local-import` で同じ手順を実行できます（同時実行はインスタンスあたり 1 タスクのみで、プレビューと索引はプロセス再起動後には引き継がれません）：

1. `GET /api/local-import/presets`：保存済みプリセットを取得します。
2. `POST /api/local-import/previews`：スキャン要求を送信します（`202` とプレビュー ID を返却。`templates` を空配列にすると保存済みプリセットをすべて使用）：

   ```json
   {
     "templates": [],
     "artworkIds": [12345, 12346],
     "refreshIndex": false,
     "selectedFile": ""
   }
   ```

3. `GET /api/local-import/previews/{id}`：`phase` が `READY` になるまでポーリングし、`GET /api/local-import/previews/{id}/items?offset=0&limit=20` で明細を確認します。
4. `POST /api/local-import/tasks`：`{"previewId": "<プレビュー UUID>"}` を送信してインポートを開始します。
5. `GET /api/local-import/tasks/{id}`：結果を確認します（スキャンやインポートのキャンセルは `POST /api/local-import/previews/{id}/cancel` または `POST /api/local-import/tasks/{id}/cancel`）。

登録したイラストの元ファイルは `GET /api/downloaded/rawfile/{artworkId}/{page}` でページ単位（先頭は `0`）に取得できます（登録レコードの `folder` はテンプレートの共通プレフィックスのみで、各ページが別々のサブディレクトリにある場合もあります）。

## インポート後のメタデータ補完 :id=metadata-backfill

`{artwork_id}` のみでインポートした場合、作品は直ちにギャラリー件数へ加算されますが、タイトル・作者・タグ・シリーズは空のままです。タイトルやタグ、シリーズで検索するには、デスクトップの「ツール → データ補完」を実行するか（起動時補完を有効にしておけば次回起動時にも自動確認）、HTTP API でインポートした作品 ID を指定して補完を実行します（`12345` を実際の作品 ID に置換。`artworkIds` を省略すると全イラスト・小説から `limit` 件まで候補を選択）：

1. **候補数の確認**（`core:backfill.read` が必要）：`POST /api/tools/backfill/candidates` に `{"artworkIds": [12345]}` を送信。
2. **ドライラン**（`core:backfill.execute` が必要）：`POST /api/tools/backfill/tasks` に `{"artworkIds": [12345], "dryRun": true}` を送信し、`202` 応答の `Location` を完了までポーリング。
3. **本実行**（`core:backfill.execute` が必要）：`POST /api/tools/backfill/tasks` に `{"artworkIds": [12345], "dryRun": false}` を送信し、同様に `Location` を完了までポーリング。

データ補完は登録済みのローカルメタデータを優先し、不足項目がある場合のみ Pixiv に照会します（詳細は[ネットワークアクセスと外部サービス](/ja/network-access)を参照）。同時実行は 1 タスクのみで、完了状態は元の `Location` で 1 時間（最大 64 件）照会できます。期限切れ・押し出し・サービス再起動後の ID 照会は `404` を返します。
