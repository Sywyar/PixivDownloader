# プラグイン管理

管理者は `/plugin-market.html` でプラグインを探してインストールし、`/plugin-manage.html` でインストール済みバージョン、現在のプロセスの読み込み状態、再起動の要否を確認したり、ローカルパッケージをアップロードしたりできます。ディスクへのインストール成功は、現在のプロセスで読み込まれたことを意味しません。プラグインによってはバックエンドの再起動、またはソフトウェアを完全に終了してからの再起動が必要です。

## プラグインの HTTP Hook を承認する

プラグイン詳細の HTTP Hook 宣言で、コールバック、対象エンドポイント、実行段階、必要なフィールドを確認します。「承認内容を確認」を選び、権限と影響するページを確認してから「確認して公開」を実行します。キャンセルしても公開設定は変わりません。新しい宣言は既定では実行されません。

承認済みで変更のない宣言は、プラグインの再有効化後に復帰します。対象や契約が変わった場合は再承認が必要です。対象がない場合や一意に決まらない場合は承認できません。無効化しても事前検査の要件は残り、保護対象のリクエストを拒否します。解除する場合は「解除内容を確認」から公開を確定します。各操作は選択した宣言だけを更新します。SDK の使用方法は[プラグイン開発](/ja/plugin-development)を参照してください。


## インストールとカスタムリポジトリ

1. プラグインマーケットで信頼できるリポジトリのプラグインを選ぶか、管理ページでローカルの `.jar` / `.zip` をアップロードします。必要に応じて `.sig` も添付できます。
2. 用途、必要な SDK バージョン、入手元、依存関係、実行モードを確認します。
3. インストール計画（対象パッケージ、依存先の入手元とバージョン、逆依存の利用側、競合、再起動への影響）を確認します。実行の信頼確認が表示された場合は、公開者の公開キーフィンガープリントまたはパッケージの SHA-256 を確認してください。
4. 結果の案内に従って必要な再起動を行い、管理ページで読み込まれたバージョンと機能の入口を確認します。失敗した場合は元の操作記録を先に確認し、理由を確認せず再インストールを繰り返さないでください。

カスタムリポジトリはデスクトップ GUI の「設定 → プラグインマーケット設定」で追加・編集します。「リポジトリ記述子を使用」では、公開者、通信先ホスト、公開キーの完全なフィンガープリントを確認してから設定の下書きに追加します。「手動入力」では HTTPS マニフェスト URL、プロキシ方針、Ed25519 公開キーを指定します。設定をまとめて保存し、再起動すると反映されます。

依存パッケージは順番に独立したインストールトランザクションで処理されます。親パッケージが失敗しても、インストール済みの依存先は保持され、結果にバージョンと `transactionId` が表示されます。マーケットの操作記録は現在のプロセスのメモリ内に保持されます。最大 64 件、非アクティブな記録は 24 時間です。ページを閉じても開始済みのバックエンドインストールはキャンセルされません。プロセス再起動後や記録の期限切れ後は、まず管理ページで実際のインストール状態を確認してください。

## 更新通知と過去のバージョン

ダウンロードページのナビゲーションの数字バッジは、インストール済みプラグインに互換性のある更新があることを示します。感嘆符は、より新しい SDK を必要とする新版があることを示し、管理ページのバナーでは両者を分けて表示します。安定版プラグインにはデフォルトで安定版の更新だけを推奨します。プレリリース版を手動でインストールした場合のみ、対応するプレリリースチャネルを追跡します。より新しい安定版への更新も可能です。同じバージョンの手動修復パッケージ（`-f`）では通常の更新バッジは出ないため、修復案内に従って再インストールしてください。

公式の主マニフェストは、最新版、最新安定版、固定された旧 SDK 群（`1.0.0`、`1.1.0`）ごとの最新互換安定版を保持します。それ以外の過去バージョンは、ダイジェストを名前にした `history/` のマニフェストに保存されます。1 ファイルの上限は 900 バージョンまたは 1 MiB で、履歴表示や互換性のある旧版の自動検索時に必要に応じて読み込みます。

最新版が現在の SDK と非互換の場合、マーケットは同じリポジトリから、互換性がありインストール可能な最も新しい旧版を自動検索し、カードと詳細でデフォルトの選択を示します。詳細では、静的に隔離された README、今回の更新説明、CHANGELOG を展開して読んだり、過去バージョンを手動選択したりできます。プラグインのライセンスとコミュニティへの登録ルールは[サードパーティープラグイン SDK](/ja/plugin-development#プラグインのライセンスと公開先)を参照してください。

## セキュリティモデルとパッケージの受け入れ上限

Ed25519 署名が証明するのは公開者とバイト列の完全性であり、コードの安全性審査や OS サンドボックスによる隔離ではありません。信頼できる公開者とリポジトリだけを利用してください。ホストは読み込み前にプラグインを上限付きで専用作業領域に固定し、同じ固定済みバイト列を対象にパッケージ構造、`plugin.properties`、SHA-256、署名、provenance、SDK 互換性、依存関係を検証します。

### 実行モード

各外部プラグインは `plugin.properties` で `pixiv.execution-mode` を明示する必要があります。指定がない、または不明な値の場合はコード実行前に拒否されます。

| 値 | 実行場所 | 隔離と権限の境界 |
| --- | --- | --- |
| `host-process-full-trust` | ホスト JVM | ホストプロセスのファイル、ネットワーク、OS 権限を引き継ぐ。ホストを昇格権限で実行している場合、管理ページに警告を継続表示 |
| `declarative-process` | 独立した worker JVM | ホストと OS アカウントを共有し、上限付きプロトコルで宣言型ルートと機能だけを公開。完全な OS サンドボックスではない。本番ではディレクトリ形式を拒否し、開発モードでは一時的に full-trust に変更してその事実を表示 |

`declarative-process` から `host-process-full-trust` への変更、SDK メジャーバージョンの変更、信頼の撤回後には、管理者による信頼の再確認が必要です。worker のデフォルト上限は heap 128 MiB、metaspace 128 MiB、direct memory 64 MiB です。OOM 時は終了し、最大 3 回、`500–10000` ms のバックオフで自動再起動します。初期化・コマンド・終了のタイムアウトはそれぞれ `10000` / `5000` / `2000` ms で、同時に許可するリクエストは処理中 1 件と待機中 1 件です。`pixivdownload.plugin-worker.*` の JVM プロパティで調整できます。

### プラグインパッケージのデフォルトリソース上限

| JVM プロパティ（接頭辞 `pixivdownload.plugin.package.`） | デフォルト上限 |
| --- | --- |
| `max-archive-bytes` | 192 MiB |
| `max-entries` | 48,000 エントリー |
| `max-total-uncompressed-bytes` | 672 MiB |
| `max-entry-uncompressed-bytes` | 64 MiB |
| `max-descriptor-bytes` | 1 MiB |
| `max-compression-ratio` | 200（64 KiB 以上のエントリーだけを検査） |
| `max-entry-name-length` / `max-entry-depth` | 1,024 文字 / 64 階層 |

これらのプロパティは正の整数だけを受け付け、不正な値はプラグインランタイムの初期化を停止させます。

## インストール元とマーケットの状態

- **配布パッケージに同梱**：Windows インストーラーと Java 標準パッケージは、`plugins/` にデフォルトの公式プラグイン（`download-workbench`、`database-sqlite`、`gui-compose`、`gui-swing`、`gallery`、`novel` など）を含みます。オフライン完全パッケージには `database-postgresql`、[PixivBatchDownloader インポート対応](/ja/pixiv-batch-downloader-import)などの公式オプションプラグインも含まれます。`douyin` は独立したサードパーティープラグインで、カスタムリポジトリまたはローカルパッケージからのみインストールします。
- **ローカルアップロード**：独自の信頼ルートは作成しません。署名付きなら既存の信頼ルートで検証し、公開者のフィンガープリントに対して承認します。署名なしは `LOCAL_UPLOAD / UNSIGNED_ALLOWED` と表示し、その正確な SHA-256 だけを承認します。リモートリポジトリのパッケージはマニフェスト署名を必須とし、ローカルの署名なし扱いには切り替わりません。開発モードで同名のソースモジュールと競合する場合、パッケージは保存するだけで有効にしません。競合パッケージを移動するかソースモジュールを除外してから再起動してください。
- **マーケットの状態コード**：`NOT_INSTALLED`（互換性のあるインストール可能版あり）、`INSTALLED`（インストール済みで、より新しい互換版なし）、`UPDATE_AVAILABLE`（より新しい互換版あり）、`INCOMPATIBLE`（現在の SDK に互換性のある版なし）、`UNAVAILABLE`（インストール可能な成果物なし、または互換性の照会が未完了）。

## トランザクションによる置換とライフサイクル方針

プラグインのインストールと更新は原子的なトランザクションで行います。候補のバイト列を固定 → 記述子・署名・依存関係を検証 → 旧世代への新規受付を停止して処理完了を待機（drain） → artifact と provenance を原子的に置換 → 方針に従って有効化、の順です。失敗時は旧世代へ完全にロールバックします。

| `pixiv.lifecycle-policy` | インストール / 更新 | 有効化 / 無効化 | 対象プラグイン |
| --- | --- | --- | --- |
| `hot-reload`（デフォルト） | 現在のプロセスで即座に置換・有効化 | 直接 start / stop | 提供機能をすべて撤回し、バックグラウンドタスクとクライアントを解放できるもの |
| `backend-restart` | 現在のプロセスで即座に置換・有効化 | 状態を保存してバックエンドの再起動を案内 | Spring バックエンドコンテキストの再構築が必要なもの |
| `process-restart` | ディスクに保存し、ソフトウェアを完全に終了して再起動後に有効化 | 状態を保存してソフトウェア全体の再起動を案内 | `gui-compose`、`gui-swing`、データベース provider、契約を保持するプラグイン、テーマなどプロセス単位のもの |

管理可能な `hot-reload` プラグインは、`load`、`start`、`quiesce`（新規受付を停止し処理完了を待つ）、`stop`、`unload`、`remove`（パッケージと provenance を削除し、`config/`、`state/`、`data/` の業務データは保持）、`restart`（同一世代で再起動）、`reload`（generation と classloader を新規作成）の 8 操作に対応します。`purge` 操作はありません。

## 復旧モード、撤回情報、トラブルシューティング

- **有効状態と復旧モード**：有効・無効は `config/config.yaml` の `plugins.{pluginId}.enabled` に保存されます。必須プラグインや選択中の主データベース provider が不在、破損、非互換、起動失敗の場合、アプリケーションは復旧モードに入り、ログイン、プラグイン管理、「パッケージ交換による修復」の入口を保持します。通常のオプションプラグインの障害は、その機能だけを隔離します。
- **撤回情報（`YANKED` / `REVOKED`）**：`YANKED` は新規インストールと更新を禁止し、`REVOKED` は以降の読み込みと起動も禁止します。有効な撤回スナップショットがない、または 24 時間の猶予を超えた場合、新規インストールを禁止します。撤回情報の更新は、現在のプロセスで実行中の full-trust コードを強制停止しません。アプリケーションを完全に終了し、修復してから再起動してください。
- **よくある問題**：
  - **インストール後にページが出ない**：結果の `effectiveAfterRestart` を確認してください。`process-restart` はソフトウェアを完全に終了して開き直す必要があり、Web ページの更新やバックエンドの再起動だけでは反映されません。
  - **非互換または署名検証失敗と表示される**：`plugin.requires`（アプリケーションのバージョンではなく、必要な SDK バージョン）と依存先のバージョンを確認し、元のリポジトリから完全なパッケージを再取得してください。`plugin.properties` を手動で変更しないでください。
  - **`stop` / `reload` が長く待機する**：`log/latest.log` で、終了していないキュータスク、HTTP/WebSocket クライアント、スケジュールスレッドを確認してください。

プラグインの保存構成は[ストレージとバックアップ](/ja/storage)、サードパーティープラグインの開発は[サードパーティープラグイン SDK](/ja/plugin-development)を参照してください。
