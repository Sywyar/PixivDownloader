# プラグイン管理

管理者は `/plugin-market.html` でプラグインを探してインストールし、`/plugin-manage.html` でインストール済み・読み込み済みのバージョンと再起動条件を確認します。ローカルパッケージも管理画面からアップロードします。ディスクへのインストール成功と、現在のプロセスでの有効化は別の状態です。

## インストールする

1. マーケットで信頼するリポジトリを選ぶか、管理画面でローカルパッケージを選びます。
2. 用途、必要な SDK、出典、依存、実行モードを確認します。
3. インストール計画を確認して実行します。実行の信頼確認が出たら、発行者の鍵フィンガープリントまたはパッケージの正確なダイジェストも確認します。
4. 結果に従って必要な再起動を行い、読み込みバージョンと対象画面を確認します。失敗した場合は元の操作結果を確認し、無条件に再インストールしないでください。

カスタムリポジトリは GUI のプラグインマーケット設定から追加・編集します。記述子を使う方法では、発行者、接続先ホスト、公開鍵の全フィンガープリントをプレビューして設定の下書きに追加します。手入力では URL、ネットワーク方針、信頼鍵を指定します。設定全体を保存して再起動すると反映します。Web のマーケットは閲覧とインストール用です。

## 計画と操作結果を確認する

計画には対象パッケージ、依存の出典・バージョン、共有依存を使う他のプラグイン、競合、再起動への影響を表示します。確定時に再確認し、状態が変わっていれば新しい計画を確認してもらいます。カタログにライフサイクル情報がない場合は再起動の可能性だけを示し、実際の結果を優先します。

依存は順番に独立したトランザクションでインストールします。親が失敗しても成功済みの依存は残り、バージョンと `transactionId` を結果に示します。部分成功を全体のロールバックと解釈しないでください。

操作記録はダウンロード準備からインストール終了まで保持します。ページを閉じても開始済みのバックエンド処理はキャンセルされず、開き直して元の操作を照会できます。同じ操作 ID の再実行は元の状態を返すだけです。記録は現在のプロセス内に最大 64 件、非活動の記録は最大 24 時間残します。再起動、期限切れ、退避で不明になった場合は、実際のインストール状態、診断、トランザクションを確認してから明示的に新しい操作を開始します。照会失敗だけで画面が自動再インストールすることはありません。

## 更新と過去のバージョン

ダウンロード画面の数字バッジは互換更新、感嘆符は新しい SDK を必要とする更新を示します。管理画面も両方を区別し、同じプラグインに両方がある場合もあります。互換候補は SDK とマーケット方針上の判定で、依存や実際の条件はインストール時に再検査します。確認に失敗したことを別に表示し、自動取得・インストールはしません。

安定版のプラグインは既定で安定版の更新を勧めます。プレリリースを手動導入するとそのプラグインが該当チャンネルを追い、より新しい安定版にも更新できます。アプリ自体が Beta でもプラグインのチャンネルは自動で変わりません。詳細画面では別の版も手動選択できます。`-f` による同バージョンの修正版は通常の更新バッジを出さないため、修復案内に従って再インストールします。

公式の主マニフェストは最新版、最新安定版、固定した旧 SDK 集合の最新互換安定版を保持します。現在の旧 SDK 集合は `1.0.0` と `1.1.0` で、配布リポジトリの整理設定が管理し、新 SDK の公開だけでは増えません。

その他の履歴は必要なときに取得し、互換版やチャンネル候補の探索でも読み込む場合があります。候補なしと履歴取得の失敗は別に表示します。旧版も同じ署名・出典検証を通ります。履歴はダイジェスト名で保持し、旧ファイルを自動削除しません。単一履歴が 900 バージョンまたは 1 MiB に達すると、公開を止めてメンテナーの対応を求めます。

## マーケット内の文書

対応する版の詳細画面にはアイコン、画像、作者のリンク、README、今回の更新説明、CHANGELOG があります。文書は選択後に取得し、失敗時は再試行できます。旧カタログも既存のホームページとテキストの更新説明を表示します。

HTML / Markdown は静的文書として表示し、スクリプト、フォーム、イベント処理、独自スタイルは実行しません。画像はダイジェスト検証済みのバージョン添付物から読み、本文指定の任意画像 URL をブラウザーで直接取得しません。外部リンクはクリックしたときに開きます。言語は現在の言語、作者の既定、利用できるフォールバックの順です。

文書は用途の判断を助けますが、出典、互換性、失効状態の検査の代わりにはなりません。表示内容は作者の投稿、コミュニティツール、使用中のホストの対応に依存します。[ライセンスと公開](/ja/plugin-development)は SDK ガイドを参照してください。

## 署名と実行権限

署名は発行者とバイトの完全性を確認するもので、安全性の審査済み証明や追加権限の付与ではありません。信頼できる作者・リポジトリだけを使ってください。

読み込み前にサイズ、圧縮比、パス、JAR / ZIP 構造、記述子の ID・版・API・依存、SHA-256、構造化 Ed25519 署名、provenance、必須プラグイン条件を検証します。検証、記述子解析、読み込みには同じ有界の凍結バイトを使い、外部プロセスが置換できる公開パスを開き直しません。

### 実行モード

外部プラグインは `plugin.properties` の `pixiv.execution-mode` に次のどちらかを明示します。

| 値 | 実行場所と権限 |
|---|---|
| `host-process-full-trust` | ホスト JVM。ホストのファイル、ネットワーク、OS 権限を継承 |
| `declarative-process` | 独立 worker JVM。有界プロトコルを通じて宣言的なルート・能力を提供 |

未指定、空、未知の値はコード実行前に拒否します。worker も同じ OS アカウントを使い、隔離はプロセス・プロトコル・資源の範囲です。完全な OS サンドボックスも、それを必須にする JVM スイッチもありません。本番はディレクトリ形式の `declarative-process` を拒否し、明示的な開発モードでは `host-process-full-trust` として動かして実効モードを状態とログに示します。

信頼を実行境界の変更に自動で拡大しません。発行者が同じでも、full-trust への変更、SDK メジャー変更、信頼の撤回後は管理者の再確認が必要です。ホストが高権限なら full-trust も継承し、警告を表示し続けます。

worker の既定は heap 128 MiB、metaspace 128 MiB、direct memory 64 MiB で、OOM 時に終了します。初期化・コマンド・終了のタイムアウトは `10000` / `5000` / `2000` ms、異常終了後は最大 3 回、`500` から最大 `10000` ms の待機で再起動します。stderr は最大 1 MiB を読み、末尾 16 KiB を保持します。同時の処理中リクエストは 1 件、待機も 1 件です。終了時は先にルートと能力を撤回してから、この上限で復旧を試みます。

起動前の `pixivdownload.plugin-worker.*` には、`initialize-timeout-ms`、`command-timeout-ms`、`shutdown-timeout-ms`、`restart-attempts`、`restart-initial-delay-ms`、`restart-max-delay-ms`、`stderr-max-bytes` を指定できます。

### パッケージの上限

既定の許容上限と対応する JVM プロパティは次のとおりです。各キーには `pixivdownload.plugin.package.` を付けます。

| キー末尾 | 上限 |
|---|---|
| `max-archive-bytes` | 192 MiB |
| `max-entries` | 48000 |
| `max-total-uncompressed-bytes` | 実際の展開量 672 MiB |
| `max-entry-uncompressed-bytes` | 1 エントリー 64 MiB |
| `max-descriptor-bytes` | 1 MiB |
| `max-compression-ratio` | 200。64 KiB 以上のエントリーを検査 |
| `max-entry-name-length` | 1024 文字 |
| `max-entry-depth` | 64 階層 |

正の整数だけを受け付けます。不正値はランタイムの初期化を失敗させ、既定値へ黙って戻しません。

## 状態とインストール元

カードは用途、実行状態、有効設定、操作を示し、広い画面では複数列、狭い画面では 1 列になります。詳細にはディスク上の版、現在のプロセスで読み込んだ版、SDK、依存、出典検証を表示します。摘要と失効時刻は展開して確認できます。インストール版と読み込み版が違う場合は再起動条件を確認してください。

「現在のプロセスに未読み込み」「依存するプラグインなし」「情報を取得できない」は異なる事実です。削除・無効化の確認には対象状態と影響する依存側を表示します。

### 同梱とローカルアップロード

Windows と Java 標準版は、必須の `download-workbench`、既定の `gui-compose`、代替の `gui-swing` を含む公式集合を `plugins/` に持ちます。オフライン完全版は `database-postgresql` と [PixivBatchDownloader インポート](/ja/pixiv-batch-downloader-import)も含みます。Douyin はカスタムリポジトリかローカルから導入する第三者プラグインです。同梱版も独立した artifact で、Boot JAR に組み込みません。

管理画面では `.jar`、対応する `.zip`、任意の detached `.sig` をアップロードします。ローカルアップロードで独自の信頼ルートは作りません。署名があれば精確な artifact と一致し、適用される信頼根で検証する必要があります。未署名は `LOCAL_UPLOAD / UNSIGNED_ALLOWED` になります。

本番でも非公式のローカルパッケージを導入できますが、コード実行前のリスク確認が必要です。署名付きは発行者フィンガープリント、未署名はその SHA-256 だけを承認します。更新、鍵変更、失効、権限拡大で再確認する場合があります。リモートパッケージはマニフェストの署名が常に必要で、未署名ローカルへ格下げしません。独自鍵を継続的に信頼させる場合はカスタムリポジトリを設定します。

開発モードでもインストールディレクトリのプラグインを読み込みます。実行中のソースプラグインと競合するパッケージは、保存のみで有効化しません。ソースを使う場合は競合するパッケージをインストールディレクトリ外へ移動し、パッケージを使う場合は対応するソースモジュールを開発ビルドから除外してから、アプリを再起動してください。

### マーケットの状態

マーケットと公式リポジトリは既定で有効ですが、起動だけでは接続しません。管理者画面の更新確認、マーケットを開く・更新する操作、インストール時に通信します。`plugin-catalog.enabled` で停止できます。公式の URL と信頼根は組み込みで、カスタムの HTTPS manifest と Ed25519 公開鍵は[設定](/ja/configuration)で指定します。

最新版が SDK と非互換なら、同じリポジトリの最高の互換・インストール可能版を探し、既定の選択として説明します。互換のみのフィルターでも表示し、履歴から別の版も選べます。互換候補なしと照会未完了は区別し、後者は更新して再試行できます。高い版をインストール済みでも、自動でダウングレードしません。

| 状態 | 意味 |
|---|---|
| `NOT_INSTALLED` | インストール可能な互換版がある |
| `INSTALLED` | インストール済みで、より高い互換版がない |
| `UPDATE_AVAILABLE` | より高い互換版がある |
| `INCOMPATIBLE` | 現在の SDK に合う版がない |
| `UNAVAILABLE` | インストール可能な成果物がない、または互換版の照会が未完了。画面の理由を確認 |

詳細画面は用途、状態、インストール操作を先に示し、説明・バージョン条件、出典・能力・検証・更新履歴を下に置きます。インストール済みや再起動待ちは管理画面へ移動できます。計画検査、確認待ち、実行中を区別し、確認待ちは開始済みではありません。計画の確認をキャンセルすると実行しませんが、後続の信頼確認をキャンセルした場合、すでに成功した依存は残ります。

## 更新トランザクションとライフサイクル

アップロードとマーケットは同じ処理を使います。

1. 上限内で候補を読み、凍結します。
2. 構造、記述子、API、依存、ダイジェスト、署名、出典を検査します。
3. 旧 generation の新規受け入れを止め、処理の排出を待ちます。
4. artifact と provenance を原子的に置換します。
5. ライフサイクル方針に従って有効化します。
6. 失敗時は旧 artifact、provenance、利用可能な generation を復元します。

旧インスタンスへのパッチではなく、トランザクションによる置換です。操作後は状態を再取得してください。

`pixiv.lifecycle-policy` は大文字・小文字を区別し、未指定は `hot-reload` です。

| 方針 | インストール・更新 | 有効・無効の切り替え |
|---|---|---|
| `hot-reload` | 現プロセスで置換・有効化 | start / stop |
| `backend-restart` | 現プロセスで置換・有効化 | 設定を保存し、バックエンド再起動を案内 |
| `process-restart` | ディスクへ保存し、完全再起動後に有効化 | 設定を保存し、完全再起動を案内 |

hot-reload は起動時専用資源を持たず、寄与・タスク・クライアントを完全に撤回できる場合に使います。backend-restart は Spring の再構築、process-restart はデスクトップ、テーマ、トレイなどプロセス側が保持する能力向けです。バックエンド再起動では process-restart を適用できません。デスクトップのライフサイクル管理がない場合、Web 管理画面は OS の再起動操作を代行できません。

Compose と Swing は独自の画面・操作を持ち、アプリの業務意味を共有します。どちらも `process-restart` で、インストール、更新、切り替え、有効・無効、削除後は完全に終了して再起動します。

### 8 つの操作

管理可能な hot-reload プラグインの API は次の操作を提供します。

| 操作 | 意味 |
|---|---|
| `load` | artifact から classloader を作って読み込む。能力はまだ公開しない |
| `start` | 子コンテキストを作り、寄与を公開する |
| `quiesce` | 新規処理を止め、現在の publication のタスク・呼び出しの排出を待つ |
| `stop` | 寄与を撤回して停止。パッケージは残す |
| `unload` | 停止後に PF4J と classloader を解放。パッケージは残す |
| `remove` | 安全な終了後に artifact と provenance を削除 |
| `restart` | 同じ generation / classloader のまま stop / start |
| `reload` | quiesce、stop、unload、load、start で generation / classloader を作り直す |

`purge` はありません。`remove` が設定やデータを暗黙に消去することもありません。任意の process-restart プラグインも削除できますが、現在のインスタンスは完全再起動まで動き、設定、認証、データベース、状態、取得ファイルは残します。必須プラグインや活動中の依存先がある場合は拒否します。削除・更新後はディスクと実行中の版を別表示し、新しいパッケージは自身のバイトと出典で検証します。再インストール後は保持したデータを使えます。

コードやリソースを変えた場合は `reload`、同じクラスでサービスを作り直す場合は `restart` です。非同期処理の `quiesce` は、正の generation に対応する実際に待機可能な drain を返す必要があります。動作中タスクを「完了」の代用値で隠してはいけません。

## 必須プラグイン・依存・保存領域

有効状態は `config/config.yaml` の `plugins.{pluginId}.enabled` に保存します。必須プラグインを無効化・削除して条件を満たさなくする操作は拒否します。必須パッケージの欠落、破損、非互換、オフライン検証失敗、起動失敗は復旧モードになります。任意の故障は通常その機能を隔離しますが、選択中の主データベース provider が使えない場合も業務開始を止めます。マーケットには不足した必須機能と診断、修復に使う既定プラグインを表示します。

`plugin.dependencies` は PF4J の依存式です。存在、版の範囲、依存グラフを検査します。共有依存を更新する前に全利用側の条件を確認してください。`plugin.requires` はコア API の条件で、アプリの商品バージョンではありません。

インストールの正本は `plugins/` 直下の artifact と `plugins/provenance/` です。`plugins/runtime/` は generation ごとの凍結領域で、インストール元・署名元・共有キャッシュではありません。実行中に JAR を上書きせず、リモート由来の provenance を省略してコピーしないでください。秘密鍵も保存しません。

portable では `plugins/` ルート自体にリンクや junction を使えます。実際のルートを固定しますが、その配下のリンク artifact は拒否します。対応ファイルシステムでは runtime と provenance の POSIX 権限・Windows ACL を制限します。FAT32、exFAT、SMB などで使えない場合は診断し、通常ファイル、`NOFOLLOW`、凍結コピー、ハッシュ検査を継続します。[保存領域](/ja/storage)も参照してください。

## 問題を調べる

| 症状 | 確認・対処 |
|---|---|
| 成功したのに画面がない | `effectiveAfterRestart` と方針を確認。process-restart は完全終了・再起動。その他は `STARTED` と登録診断を確認 |
| 非互換 | `plugin.requires`、`requiredCoreApi`、依存版を確認。記述子を書き換えず、対応版か新しいホストを使う |
| 署名・provenance 失敗 | 元のリポジトリから取得。署名欠落、未知・失効鍵、不一致は拒否し、未署名へ格下げしない |
| stop / reload が待ち続ける | 活動中の呼び出し、キュー、HTTP / WebSocket、スケジューラーをログで確認。作者は受け入れ停止、キャンセル・drain、子コンテキスト終了時の資源解放を実装する |
| 削除後も設定がある | データ保持の動作。不要と確認してバックアップした後、停止中に owner を限定して整理する |

起動に失敗した外部プラグインは、カードのパッケージ修復から同じ ID の互換パッケージをアップロードできます。検証とリスク確認は省略しません。必須版は交換できますが削除はできません。任意版は依存とライフサイクルを満たせば削除できます。交換・削除は設定、データ、未完了タスクを保持し、データ移行はプラグインが担当します。

## 失効情報と実行中インスタンス

管理画面は最後の更新成功、文書の有効期限、猶予期限、制限理由を表示します。管理者は有効な設定済み出典を明示更新できます。マーケットとインストールも所定の更新を行います。通常の状態照会は通信せず、定期的なバックグラウンド更新もありません。オフライン・更新失敗では最後の検証済み有効コピーを保持し、制限がないとは判断しません。

`YANKED` は新規導入・更新を止め、`REVOKED` は後続の読み込み・開始も止めます。有効なコピーがない、または 24 時間の猶予を過ぎた場合、新規導入を拒否します。失効更新だけでは実行中の full-trust コードを強制終了しません。止めるには完全に終了し、修復を確認してから起動してください。

プラグインを作る場合は[SDK ガイド](/ja/plugin-development)のテンプレートを使い、アプリシェルの実装をコピーしないでください。
